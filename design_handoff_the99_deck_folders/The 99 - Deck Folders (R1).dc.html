DECK FOLDERS R1 a shelf to put decks on
§5 answered first · for the chassis build, today

A folder is a nav level, not a filter dimension — and the chassis needs no redraw, no density pass and no sixth control to make that true. One call site changes one number.

Branch (b). The level is one 34px line above the chassis carrying the shelves and their counts; the chassis keeps its four dimensions and its trailing sort slot exactly as shipped, and filters within the shelf. What the chassis team has to do: pass the shelf’s deck count as total to the result line instead of the library’s (decks-view.tsx, one argument). Nothing else. No slot, no panel, no chip, no new clear scope.

the kill shot for (a)
Under (a) a new folder is born disabled. listFolders returns empty folders with deckCount: 0, and every panel dimension on this route disables a zero-count row (decks-view.tsx’s disabled: count === 0). So the only surface naming the folder you just made refuses to be clicked, and there is no route to file the first deck into it. A shelf you cannot reach is not a shelf.
and the row cannot hold it
A sixth control fits by zero pixels at rest and overflows the moment a folder is chosen — measured against the shipped literals in §2. A folder is also the only dimension on /decks whose value is player-typed and unbounded; every other one has a fixed vocabulary of two, five or six short words.
one way to narrow, not two
There is no folder chip, no folder panel and no folder in DeckFilters. The shelf lives on ViewState beside the filters, never inside them, which is what makes EMPTY_FILTERS, activeFilterCount and Clear all filters incapable of touching it — by construction, not by care.

Below: four corrections to the brief read from main (§0), the density arithmetic that decides §5 (§2), the nav model with its rejected alternative (§1), the three empty states and the precedence ladder that keeps five kinds of nothing from colliding (§4), move / create / rename / delete (§5b), and the contract (§6).

§0

Four corrections, read at main rather than recalled

The brief was verified at e4b40752 and describes the chassis as landing. It has landed. That changes the shape of the §5 question from what should the chassis do about folders to what can be added to a frame that is already built and audited — which is a better question, and it has a measurable answer.

1 · the chassis is shipped, not building
src/components/ui/filter-chassis.tsx exists and decks-view.tsx mounts it, with ColourPips, two FilterPanel mounts and DeckSortMenu in the trailing slot. So this handoff amends a live component rather than a drawing.
2 · the sidebar is already gone
§4 says “that sidebar is going”. It went: deck-filter-column.tsx is now three exported helpers (toggleIn, SearchField, two label maps) and draws no column. The 262px is already spent. This round must not ask for any of it back, and does not — the level is horizontal.
3 · the breakpoint is 1000, not 900
CHASSIS_WIDE_MIN_PX = 1000, and the component says why: the chassis handoff’s own 887px total was wrong (/collection needs 987). Every frame here switches at 1000, and the shelf line takes that breakpoint rather than a Tailwind stop — the same trap deck-filter-sheet.tsx already fixed with max-[999px]:flex.
4 · the compact row is already three controls
Below 1000 the shipped row is a 44px search icon, then Sort and Filters as a trailing cluster — not five inline controls. There is no room in it for a fourth, which is the compact half of the (a) arithmetic and needs no measurement.

§1

The nav model — a shelf line, its own pattern, a parameter rather than a route

§3.1 · not the breadcrumb
The set pages’ line is a trail between two real pages — a <Link> to /collection/sets above a title. A breadcrumb here would promise a parent page to climb to and would sit above the h1, where the reader is not choosing anything. Folders get their own pattern; the set breadcrumb is untouched.
§3.1 · a place you go, and the URL says so
?folder=<id>, ?folder=none for Unfiled, absent for All decks — written with replaceState through the existing apply(), added to OWNED_PARAMS. Not a route: page.tsx would refetch an identical list and throw the filter state away. Shareable without being a navigation.
the selected shelf spends no accent
Selected is --fg on --elevated under a --border-strong ring — verbatim what the active By type pill already draws, and what card-surfaces’ reconciliation ruled for exactly this case. Accent stays reserved for in use and to buy, and the chassis keeps accent as its own “this filter is on” — which is a second reason the two lines never read as the same kind of control.
1a The shelf line — counted segments above the chassis RULED

One 34px line on --bg, above the chassis’s --surface-sunken ground, so the two are different surfaces as well as different heights. Every shelf and its count is on screen without opening anything — which is what makes a feature nothing currently draws discoverable at all, and it is why this wins over 1b.

what wrapping does
Unlike row 1 this line may wrap to a second line, and at many folders it does. That is legitimate here and forbidden there for one reason: the chassis promises a fixed height so the list never moves under a reader mid-filter; the shelf line moves the list only when the reader changes shelf, which moves the list anyway. Ceiling: past two lines it scrolls horizontally rather than growing a third.

The h1 becomes the shelf and carries the picker, so the level costs no pixels at all — the strongest possible answer to the brief’s chrome objection, and drawn because of it.

§3

Below 1000px the level is a trigger and a sheet — the one shape change, and its reason

Chassis decision 23 says a control keeps its shape across both forms. The shelf line is not a chassis control, and it cannot keep this one: three player-named shelves at a 44px target are already past 358px, and a second horizontal scroller directly above the chassis is the defect scrollCompactControls exists to contain, not to duplicate. So the level becomes what every dimension in this app already becomes at this width: a trigger that opens a sheet. What must not happen is it reading like one — four carriers keep it apart, listed under the frames.

§4

The grid region has exactly one occupant, chosen in this order, and the chassis and the shelf line are never replaced by any of them — whatever caused the emptiness must stay on screen and stay reversible.

§3.6 answered by this row, not by the tile. folderName rides on every deck, but a tile stating its shelf repeats the segment above it on every tile of a scoped grid, and the only row with space for it is the one carrying commander and colour — the row card-surfaces already ruled must not give. The fact lives where it is changeable, and in the accessible name of the control that changes it.
No drag and drop. The whole tile is an absolute-inset <Link> and a drag would fight it for every gesture; on the compact form there is no rail to drop onto at all. A shelf line is a destination for a tap, not for a pointer.
Multi-select: asked for as slice B, not drawn here. It needs a selection mode over a grid of links — the pattern top-off-list.tsx’ selection head already establishes — and filing eleven decks one at a time is the only thing in this round that is merely tolerable. It changes no decision here, which is why it can wait.

§6

The contract

CHASSISNo new slot, no new dimension, no new chip, no density pass. One change, at the call site: resultLine takes the shelf’s count as its denominator. filter-chassis.tsx itself is untouched.
STATEA third field on ViewState — shelf: string | null | "none" — never a fifth field on DeckFilters. That is what makes EMPTY_FILTERS, activeFilterCount, the Filters badge and Clear all filters unable to touch the shelf.
URLfolder joins OWNED_PARAMS; written by apply() with replaceState, read once on mount beside the filters. An unknown id falls back to All decks, the same way readList already makes a hand-edited value harmless.
QUERIESlistFolders added to /decks/page.tsx’s Promise.all — required, because a deck row cannot name a folder holding no decks. One new function, renameFolder. moveDeck, createFolder and deleteFolder are used as merged.
FILTERINGThe shelf narrows the list before filterDecks, in the same client-side pass over the same loaded payload. The panels’ per-option counts are computed within the shelf too, so a status reading 0 means 0 on this shelf — which is what the reader is looking at.
TARGETS34px segments at the wide form (the chassis’s own control rhythm), a real 44px trigger and 48px sheet rows below 1000. The shelf line switches at 1000 with everything else, never at a Tailwind stop.
MOTIONNone on the shelf line, matching the chassis: selection changes instantly and the sheet reuses the existing entry animation. No reduced-motion state, because there is no motion to reduce.
