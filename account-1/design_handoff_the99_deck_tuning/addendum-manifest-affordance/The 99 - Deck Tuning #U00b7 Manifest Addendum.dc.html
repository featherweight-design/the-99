The manifest is a list you read, not a set of boxes you tick.

Hugh pressed the empty 18px box expecting a checkbox. The box goes, and so do the row borders and fills. Each read becomes a line in a ruled list, led by a text-sized mark: a dot while pending, a ✓ once read. Nothing in the list has a border except the dashed empty-games row, which holds the list's one control. Copy, counts and every state are unchanged.

1 · The mark: dot → ✓. Pending is a 5px dot in --fg-locked; read is a 12px ✓ in --accent, weight 600. Both are glyphs at text size in a 14px slot: no box, no border, no radius, so there is no empty container to fill. A dot is what a list uses before an item, and it swaps for a ✓ the way a line item gets marked off. Not colour alone: the shape changes, and the label steps from --fg-body to --fg. The dashed row, which is never read, has an en dash.

2 · The row: no border, no fill. A bordered, filled 38px row is a tile, and a tile invites a press. Each row is now a line between 1px --border rules (one rule above the list, one under each row), 2px inset. The done row loses its --elevated fill: the ✓ and the brighter label carry done. No hover, cursor: default. The <ul> keeps its list semantics; the mark stays aria-hidden and the row gets visually hidden text, read or not read yet, after the label.

3 · Heights: the rows stop being targets. Read rows are 32px on desktop, 36px on the phone (min-height, py 8px, so a long label wraps rather than clips). They were 38 / 44 only to be pressable, and a row that is tall for no reason reads as one that can be pressed. The dashed row keeps its height because it holds a target: Log a game → is its own box, a true 44px tall on the phone and 38px on desktop, 12px side padding, flush to the row's right edge (the row's right padding goes to 0). That fixes the 43px button in manifest-rows.tsx:39-45; desktop's dashed row grows 38 → 40px to hold it inside its border.
