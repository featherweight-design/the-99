HANDOFF App-wide · every loading.tsx · page-to-page navigation

Keep the page up. Show the screen only for a real wait.

Every navigation takes about 310ms because every route has a loading screen, and React holds a shown screen for at least 300ms. With no boundary above it, a fast route lands in about 95ms and the current page stays up until then. So only the deck page and the routes under it keep a screen. Everywhere else the link you pressed shows it’s working. Figures are from docs/superpowers/perf/2026-09-27-after-pr6.md, §The navigation floor.

The threshold is a median navigation of about 700ms. Below it, a held screen costs more than it tells you. /collection sits below it (302–337ms, server-bound either way). Its screen would buy about 30ms of earlier feedback and cost a flash on every revisit. A loading.tsx can’t tell a first visit from a revisit, so the call has to be made per route, and this one goes to the pip.
