Addendum · list windowing · issue #52

How far down the ranks do we show?

A large collection can produce a ~200-general ranked list. This addendum adds one control to the shipped Commanders surface — a Show more reveal at the end of the list, matching the pattern Collection already ships (browser.tsx:23). Nothing else changes: the recommendation card is reused unchanged, the sequence stays one fixed rank order, and there is no filtering, jump-to-page, or page number anywhere. Five states below, phone first, desktop beside it.

Pattern
Show more, in-flow at the end of the list — Collection's control, restyled to nothing new.
Batch size
{{ batch }} cards — one screen-and-a-bit of scroll, and the shipped 24-general case never sees the control.
Remaining count
Two figures that can't be mistaken for the shipped filter count — {{ shown1 }} shown · {{ remaining1 }} more below in the header, {{ remaining1 }} remaining in the control. Neither says “showing N of M”.
No batch seams
No divider, no “batch 2” label — the rank numerals already say where you are, and seams read as pages.
Exhausted
The control is removed, not disabled, and a quiet end-of-ranking rule takes its place.
Announcement
Focus lands on the first revealed card; a polite live region reads the new range and the count.
The control · anatomy, states, accessibility
Reveal control — desktop
Secondary button, full width of the list column, sitting in the card stack's own 12px gap. Same fill and border as a recommendation card so it reads as the list's last row rather than a page footer — brass is reserved for Build this deck.

Mobile form
Full-bleed inside the list's 14px padding, two lines so the count never truncates, 52px min height, and 24px clearance above the bottom tab bar. Never sticky — a floating reveal would compete with the tabs and hide rank continuity.
Keyboard & announcement

Native <button> — last stop after the final card's View breakdown link.

Reveals the next batch, then moves focus to the first new card so the keyboard user's position is inside the new material, not thrown to the top.

Accessible name carries the count too — “Show {{ batch }} more commanders, {{ remaining1 }} remaining”. Rest label {{ contrastLabel }} on surface: AA at 14px/600.

What changes in code
commanders-view.tsx
One state value — shown, initialised to REVEAL_STEP — plus a slice on the already-sorted array and the control below the map. Mirror Collection's naming so the two read as one pattern.
rec-card.tsx
Untouched. It gains a forwarded ref only if focus-on-reveal is implemented there rather than by querying the list container.
Tokens
Theme-aware values come from globals.css — surface, elevated, line, text-faint. Nothing new is added; the control borrows the card's own fill and border.
Filter interaction
Changing the color filter resets shown to one batch and recomputes the remaining count against the filtered length — the reveal window is a property of the current result set, not the session.
Degraded states
Unaffected. The global EDHREC banner and per-commander notes sit inside cards; windowing only decides how many cards render.
Empty states
No-candidates and filtered-to-zero never render the control — zero results means zero remaining.
