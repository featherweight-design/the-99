Built against the repo

The deck exists the moment it can. Everything else is carried into it.

Nineteen states, phone (392px) first and desktop (1060px) beside it. There is no review gate — the collection flow makes you clear a matched/unmatched screen because a collection sync is a bulk fact; a deck is a thing you are about to open and use. Lines that don't match become unresolved rows stored against the deck, and you clear them from inside the builder. The parser and the matcher already exist; this handoff owns the entry point, the seven failures, and the reconciliation surface.

Entry
One surface, three modes on a chip row — Moxfield link · Paste · File. The link leads, because that's the ticket.
Failures
Seven, each with its own copy, in the shipped warning-banner geometry. Retry appears once — only where retrying is the advice.
Unresolved row
A deck row with a 2px warning rule, the raw string in mono, and an unmatched tag in the buy tag's slot. Design call — see Anatomy.
The header
No new pill variant. Unresolved rows never count as built, so the arithmetic already keeps the deck off Complete. A banner says why.
Resolution
A row-scoped copy of quick-add-bar's combobox, seeded with the failed string, in an expander at both widths. Owned-only off. No dialog, no new focus trap.
Silent
Tokens, emblems, sideboard, a commander duplicated into the 99 — all dropped without a word. Quantity > 1 on a non-basic is the one parse note.
R2 · rebased on the add-panel overhaul (#158)
states 13–19 now land on the new builder, not the shipped one
R1 resolved a row through SearchPane — inline on desktop, the Add panel's bottom sheet on phone. Both constructs are deleted by #158. The successor, quick-add-bar.tsx, is a persistent global combobox pinned to the bottom of the deck column at both widths. Three calls follow from that, and this handoff makes all three.
a · which search resolves a row
A row-scoped variant of the combobox, inside an inline expander — never the global bar.
The bar's whole premise is that it is never a mode: it is always mounted, always means add a card to this deck, and ↵ always adds the top match. Seeding it from a row would break both halves of that. The control sits at the bottom of the screen while the thing it acts on is in the middle of the list, and ↵ would have to mean add or resolve depending on invisible state.
So: the same row shape, in an expander that belongs to the row. Identical mechanics — combobox, ↑↓ through aria-activedescendant, Esc to dismiss, quick-add-bar's exact result row including the 30×42 thumb. Three deltas, all scoped: the field is seeded and selected, the action reads Use this card, and ↵ resolves this row rather than adding a hundredth card.
Same construct at both widths, which is #158's parity constraint. The phone no longer opens a sheet — there is no sheet. While an expander is open on phone the global bar hides: two search fields on a 392px screen, one of which does something else, is the mode confusion we just removed. It returns on collapse.
b · the owned-only default
Resolution overrides it to off. It does not inherit.
Owned-only is a build-time filter and it is right to default on there: the question is what can I put in this deck tonight. Resolution asks a different question — what was this line — and it has one correct answer whether you own it or not. Imported decks are exactly where the unowned answer is common; a wishlist deck off Moxfield is mostly cards the player hasn't bought.
Inheriting true here would hide the right card behind a toggle the user can't see the reason for, and the failure mode is silent: an empty result set that reads as no such card when it means not in your collection.
The override is scoped to the expander and stated in the caption, not silent — the toggle renders in the expander in its off position and can be flipped back per-row. The global bar's own setting is untouched on collapse. This is now the second filter this surface turns off, alongside colour identity, and one caption carries both: every card, owned or not — you're naming a line, not shopping.

Consider · 99 is unchanged. suggestDeck() iterates the owned pool and dedupes against the deck's oracle ids; a row with no oracle id can neither be suggested nor excluded. The count is what it always was.
Your deck · 97 counts what's built, same figure as the spine — not the 99 rows on screen. The unresolved group carries its own 2 in its header, where it is a heading rather than a second claim about the deck.
The strip gains no cell and no asterisk. A role comes from a type line and an oracle text; there is neither. An "unknown" cell would be a sixth column that can never be filled, and a footnote on five cells is five footnotes. Instead the banner sits directly above the strip and the tabs and takes one extra clause — the one place the reader is about to use those numbers is the one place the caveat belongs.
On resolve, the row acquires an oracle id and everything moves in the same optimistic frame: built 97 → 98, the tab, its role cell, and the Consider tile for that card flipping to ✓ In deck if it was on a shelf. Drawn in state 18.

1 · The name is set in mono. Every other row is a card name; this one is a string out of a file. Mono is already the app's voice for raw data — quantities, set codes, collector numbers — so the row says this is text, not a card before you read a word of it.
2 · The ownership dot becomes a ?. Owned and not-owned are the two things a dot can say. A card with no identity is neither, so it doesn't get a dot at all — it keeps the slot and the alignment.
3 · A 2px warning rule on the leading edge. The same --warning left-rule the replace flow's banner uses, at row scale. It is the redundant signal, never the only one.
Deliberately not done: red, strike-through, reduced opacity, or a separate "problems" tray. This is a card the deck wants — the app just can't name it. Danger red is for something you did wrong.

The banner carries the fact, the pill carries the state. Exact geometry of the replace flow's warning banner — --elevated-hover, 1px --border-strong, 3px --warning left rule. It sits below the spine, above the role strip, and disappears when the count hits zero.
The count is in the copy, never only in a badge. One number, one place. The unresolved group header repeats it because it is a heading, not a second announcement.
Nothing in the spine changes. No extra figure, no second bar, no "97 + 2". The deck's number is what's built; the exception lives in prose.
Where they sit
Unresolved rows get their own group, pinned last, labelled Couldn't identify. They cannot go in a type group — a card with no identity has no type line, and inventing one would be a lie the rest of the list can't see. Pinned last rather than first because the deck is the point; these are the tail.
The group uses the shipped DecklistGroup header with its count, and the same two-column desktop grid. Under Shopping the group is hidden entirely — the spec keeps unresolved rows out of toBuyCount, so a shopping view that showed them would be showing something you cannot buy.

Every failure message is programmatically associated with the field it belongs to and announced once via role="alert". Colour is never the carrier — each one has an icon, a heading and a sentence.
Resolution is a disclosure, not a dialog. No new focus trap. Esc collapses it and returns focus to the row.
Phone controls clear 44px; the seeded search field is 16px so iOS doesn't zoom.
Focus is the global :focus-visible from globals.css — 2px var(--brass) at +2px, not overridden anywhere in this flow.
