Decklist row · card view · Suggested changes · R1

Never cut

A player can mark a card in a deck as never cut, and no tool will offer to take it out. The tuning harness had Suggested changes cutting Lotus Petal and Ornithopter from a Yuriko ninjutsu deck, which is built around cheap evasive bodies. The model couldn't know that. The player does. The mark is a lock, in neutral ink, after the card's name. You set it from the row on desktop, or in the card's In this deck block on any device. It is only ever the player's choice: nothing infers it, and nothing suggests it. Drawn at 1300 and 390. The fixture is HD Yuriko, with Lotus Petal and Ornithopter marked.

The calls

1 · A lock after the name, in no colour

Every hue already means something: accent is in use or to buy, warning is money, success is complete, danger is over-committed. A kept card is none of those, so the lock is --fg-body, the same way the proxy tag spends no colour. It sits after the name, count and fact marks, not in the tag slot, because a kept card can also be a proxy or a card to buy. Its word, never cut, is in the key, in the title and in the row's description.

2 · The row: a pointer shortcut on desktop, a mark on the phone

On desktop, hovering a row shows an outline lock after the name. Pressing it sets the mark, and pressing the solid lock clears it. It takes no space until then, and it's out of the tab order, like the suggestion card's thumbnails. On the phone a third 44px box would cost 44px of name on all 99 rows, so the row only shows the mark. Tapping the row opens the card, where the switch is (1a).

3 · The card view: a second switch in In this deck

It goes under the proxy switch, behind a hairline, in the same square-tick skin. Like the proxy switch, it's deck-scoped and absent without a deck. It's the full control: keyboard, screen reader and phone. Once on, it says what it does and what it doesn't: tools will leave the card in, and the player can still remove it (1b).

4 · Suggested changes says what it kept

The manifest adds a row that names the kept cards. The read line adds 2 never cut. The model is told, and the validator drops any cut of a kept card anyway. When one is dropped, the lead names it. Marking a card an open suggestion would cut turns that suggestion into a no longer applies row, straight away (1c).

5 · Open: cheaper stand-ins, yes

Offering stand-ins means offering to cut the card, so a kept card gets none. There's no ⇄ on its Shopping row, even when it's over the limit, and the card view replaces See cheaper stand-ins → with a line saying why. It still counts toward 2 over: the limit is a fact about price, not an offer (1d).

5 · Open: the climb, listed but never hidden

What would have to go is arithmetic, not an offer: the sheet already says which cards go is yours. Hiding a kept game changer would make the count lie. So it stays in the list with its lock, sorted last, and the sheet says so. If the marks make a bracket unreachable, the sheet says that plainly (1d).

6 · Open: no cap

A cap would be a number the app puts on how much a player may care about their own deck, which is close to a score. The tools already cope with a short list to cut from: the validator returns fewer swaps and the lead says so. The one real edge is logical: if every card but the commander is marked, the panel says there's nothing to cut, the primary action is disabled, and no credit is used (1c). Hugh's call.

7 · No marks: nothing new drawn

With no marks, the deck has no key entry, no manifest row, no read-line clause and no lead clause. The rows are pixel for pixel what ships today. The only new things are an unticked switch in the card view and the lock that shows on desktop hover (1e). Reject is still a reject, and it never marks a card. A rejected cut can come back next run unless the player marks it.

In the card view: off, then on

One block, two switches

ProxyControl's block is already In this deck, and a kept card is a fact about this deck. So the new switch joins that block rather than starting a second one. The proxy half is unchanged and stays first. A hairline separates them, so the proxy's note clearly belongs to the proxy.

The words

The label names the deck, as the proxy label does: Never suggest cutting it from HD Yuriko. Suggest is the honest verb, because the player can still cut it. With the switch on, one line names the tools and the one thing still open to the player. The note says it takes effect at once and isn't part of a version, so no commit is needed.

Everywhere the card opens in the deck

The decklist, Shopping, the Analysis tab, and a suggestion's cut name: all of these open CardModal with the deck's id, so the block is there in all of them. Suggested changes, and how it says it kept them

Before the run: a fifth manifest row

Cards you marked never cut, with the lock, the names on a second line and 2 of 99. It ticks like the others when the pack is built. From four names on, the line reads Lotus Petal, Ornithopter, Gingerbrute and 3 more. The row is absent at zero.

Told, then checked

The prompt tags kept cards in the decklist as it tags the commander ([never cut]), and the system line that forbids cutting a commander grows to cover them. The validator gets a neverCut drop straight after cutInDeck, so a kept cut never renders, whatever the model says.

After: the read line and the lead

The read line ends · 2 never cut. A neverCut drop gets its own clause in the lead, naming the card: One more would have cut Lotus Petal, which you marked never cut, so we dropped it. It's the one drop worth naming, because it shows the mark was read. Other drops keep did not hold up to checking.

Marking mid-set

The deterministic check that already makes a swap no longer applies (cut gone, or add already in) gains a third reason: the cut is now kept. The row reads You marked Ornithopter never cut. with the lock. Clearing the mark brings the card back open. It's Hugh's harness case, answered in two taps.
