You own four Forests. One of them is the one you like.

An addendum to the shipped card detail modal. When you own more than one printing of a card, the Set field becomes a disclosure and opens a region of every printing you own, inside the modal's scrolling content column. 2,368 of 2,470 cards own exactly one printing — those render the modal byte-identical to today, per locked decision 6. Every state leads with the phone (392px), desktop (1060px) beside it.

R3 — four corrections after reading the repo
Mobile does have an art header. card-modal.tsx renders a md:hidden art header with a 180px card image. The hidden md:flex at :180 is the desktop art column. The spec's §Open item 5 says mobile "shows no card image today" — that is factually wrong about the shipped component, and I propagated it into R2. The Collection handoff was right; I called it stale in error. Art header restored.
The modal height is fixed and must stay fixed. md:h-[620px] md:max-h-[85vh], with a source comment explaining why: paging Prev/Next through cards with different oracle lengths resized the dialog under the cursor. R2 grew it to 980px on expand — that reintroduces the exact bug. The region now lives inside the content column, which already scrolls.
The trigger is the existing Set field. MetaField label="Set" value={printingCaption(card)} already names the printing. R1/R2 invented a second caption under the art, which would have contradicted it. The Set field gains a third line and becomes the button.
One printing = no change at all. Decision 6 is explicit: "one owned printing renders the modal exactly as it does today." R1/R2 added a caption to all 2,470 cards and argued it earned its place. That argument is against a locked decision — withdrawn. State 1 is now the shipped modal, untouched.
Where it lives
Inside the modal's scrolling content column, below the meta row. The art column and Prev/Next never move.
Entry point
The existing Set field — MetaField on desktop, promoted out of the 2×2 MetaCell grid on mobile, and only at 2+.
Chosen vs default
Solid brass ring + filled ✓ + Your pick. The resolver's fallback gets a dashed ring + hollow ◇ + Shown now — decision 10, never dressed as a choice.
Overflow
Past {{ overflowThreshold }} entries: SearchField, finish chips, set headers. 54 Forests — the measured worst case.
Finish
One entry per collector number (decision 3). Finish is a text detail, and plain nonfoil shows nothing (decision 9).
Commit
Immediate (decision 7). No Save, no confirm. Only escape hatch: Use the default again.

"Shown now", not "Default". Decision 10 says the fallback-resolved printing must not read as though the user chose it. Shown now describes what the app is doing; Default starts to sound like a setting you own.
Chosen and focused are different rings — the pick hugs the art at +3px; focus is the global :focus-visible from globals.css (2px var(--brass), offset 2px) — not overridden.

The modal does not resize
md:h-[620px] md:max-h-[85vh], and the source says why: the dialog used to be h-auto and paging Prev/Next through cards with one-line and twelve-line oracle text resized it under the cursor on every step. A picker that grows the modal on expand rebuilds that bug and makes it worse — it would jump 360px under your hand.
So the region goes where the variable-height content already goes: inside .flex-1.overflow-auto, below the meta row. 54 Forests scroll there the same way twelve lines of oracle text already do. The art column is a flex sibling and never scrolls — so the card stays put no matter how far down the grid you are, which is what decision 4 is protecting.
Roles & keyboard
button[aria-expanded][aria-controls] div#printings[role=radiogroup] button[role=radio][aria-checked] span.sr-only "shown now, not chosen"
Radiogroup. Arrow keys move and select; Tab leaves. With no pick stored, no radio is checked (decision 10) — roving tabindex starts on the shown-now entry.
Esc collapses the region and returns focus to the Set field. useDialogA11y handles the second Esc as it does today — the region adds no handler that would swallow it.
The region is inside the existing dialog, so the focus trap already covers it. No new trap, no new live region.

The call, and why
The header collapses to a 72px thumbnail with the title beside it, and only at the overflow threshold. Below that it is untouched.
180px of art plus a 62px Set row plus a search field and three chips leaves roughly one tile row on a 812px phone — you would be choosing between 54 printings through a letterbox. Collapsing recovers a full row and a half.
It's also the cheapest place to take the space: the art you're looking at is already the first tile in the grid, at 110px, three inches below. The header at full height is showing you the same picture twice.
The title and type line move into the header as it collapses rather than being lost — they were below it, and the space they vacate is what the grid gains. Collapsing back on close is the same transition reversed.
The Set row's job changed, and it survives it. Its 40×56 thumbnail is no longer the only card art on the phone — so it stops substituting for the art and starts doing what the desktop Set field does: naming the printing, next to art that is already showing it. That is a better job than the one R2 gave it, and it needs no redraw.

Three up, not five
The content column is 820 − 320 = 500px, less 32px padding each side — 436px of usable width. At a 16px gap that's three ~135px tiles. R2's five-up only existed because the region spanned the whole modal, which it can't do now.
Three is enough. The set name gets two lines at 13px without truncating — Commander Anthology Volume II fits — and at 135px the art is bigger than the 110px phone tile, so recognition is easier here, not harder.
Nothing is checked
Decision 10: a card with no pick shows no selection. So the first tile carries Shown now — dashed ring, hollow ◇ — and aria-checked="false" on every radio in the group. It is a statement of fact about the resolver, not a stored preference wearing a disguise.
The subtitle avoids explaining the resolver's rule. "We show the newest one" (R1/R2) states an implementation detail the spec never promises — resolveImageUri's tiers are exact → representative → catalog, not "newest".

The modal is the same size
Compare it to state 2 — 820×620, identical. Fifty-four printings changed nothing about the frame. The content column scrolls, exactly as it already does for a twelve-line oracle, and the art column doesn't move because it's a flex sibling, not part of the scroll.
That's the whole answer to "you never lose the card". It isn't a rule the region has to enforce; it's the shipped layout doing what it was built to do.
Search matches sets
Every entry has the same card name, so name search is useless here. The SearchField matches set name, set code and collector number — "the Kaldheim one", "blb", "282". Reused unmodified, including its focus-within brass border and 0 0 0 3px rgba(201,162,75,.16) glow.
Chips take chip-row.tsx's geometry — --elevated fill, --border-strong, radius 999px — but single-select with a brass active fill, and no dismiss ✕. They're a view switch, not removable filters.
