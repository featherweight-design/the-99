R3
Set collections · /collection/sets · two routes, one entry point

The gaps are the page.

Two child routes under Collection — an index of the sets you hold cards in, with a search that reaches any collectible set, and a grid of one set's base run with your cells at full strength and everything else dimmed. Drawn on the spec's own worked example: Edge of Eternities, base run 1–276, extras 277–399, 62 / 276 owned and 214 missing.

Every value in every frame is var(--token). There is not one hex literal inside a frame, because the whole feature rests on a dim that must mean the same thing in six palettes — §4 draws the same six cells in all six and measures the step at 3.15–3.44:1 in every one.

R3 — redrawn on the shipped /collection. §1 is no longer a sketch of that toolbar but the toolbar: the real header, search field, COLOR well with round pips, Type / Set / Sort / Availability, the view well and the card tiles. That surfaced a collision worth the redraw — a Set ▾ filter already exists, one word from By set, and §1 now rules on how they stay apart. Also this round: Collection rows gain the cost track the rest of the app has (§1b), the grid is drawn at 390px in full, the cell caption spells rarity out in the shipped TLA · uncommon format, and three pieces of furniture come off the 100% head.

R2 — all three calls ratified, one of them overruled. Ruling 4 now marks the cell rather than the head, and the mark turns out to be the other half of a pin that already ships (§3). The entry point is confirmed with its route boundary written down (§1), and three edges outside the spec's state list are drawn in §3b. Nothing is cut — the money block ships.

Read README.md for the decisions log, STATES-set-grid.md for the state matrix, DIM-missing.md for the dim and its per-theme measurements, DENSITY-four-hundred-cells.md for the scroll structure, copy strings, READINESS.md.

Every grey disc marked set is the set icon — written down, not drawn
The circular placeholder in the index row (26px), the set head (44px), the phone head (30px) and the 100% head (46px, ringed) is sets.icon_svg_uri in every case — the real Wizards set symbol, not a letter, not a disc, and never the set code repeated as a glyph. It is a single-colour SVG: render it at var(--fg-muted) on a var(--elevated) disc at rest, and at var(--success) inside a 1.5px var(--success) ring with no fill at 100% — which requires the glyph to inherit currentColor; if it does not, that is a fetch-and-recolour job and it is the one asset risk in this package. The icon is decoration, always aria-hidden — the set code beside it is the identifier that survives greyscale and a screen reader.

Prominence — the call, and what it costs
One hairline pill, no fill. The refresh allows one filled button per screen and /collection has not spent it; this is not what to spend it on. Set completion is a second job, not the job — the entry has to be findable on the second visit, not loud on the first.
Trailing, beside the view well, never inside it. The leading cluster changes what is in the list; the trailing cluster changes what surface you are on. Sets changes the surface.
Phone gets a full 44px pill paired with Filters, because the phone toolbar has no trailing slot and a 44px target cannot hide in one. That is the floor speaking, not emphasis.
It carries no count. By set · 34 was drawn and dropped: the number of sets you have touched answers nothing and competes with the two real counts 40px to its left.
First run: the pill is absent, not disabled. With nothing uploaded the index would have nothing to list and the locked upload surface already owns that moment.
R2 · what makes it a route and not a toggle
Ratified with a warning: it has to be more than a toggle, because combining Commanders and Discover caused bugs. So the boundary is written down rather than assumed. Nothing crosses it in either direction:
Filters do not carry. /collection's search, type and availability filters are not applied to the set page, and the set page's colour / rarity / missing-only are not applied back. Different populations, different params, no shared key names.
Back is a route change, not a state restore. Leaving returns to /collection with its own filters exactly as they were, because they were never touched.
Separate loading and empty states. The set page has its own loading.tsx and its own four empty states; none of /collection's are reachable from it.
One shared component, mounted twice. The colour filter, the card-detail modal and the buy tag — and each is mounted, never branched on route. If a component needs an isSetPage flag, that is the bug this warning is about, and the answer is two components.
The pill carries no state — a plain link to /collection/sets, no query, no memory of the last set. Same rule the /commanders → /discover link got.
R3 · the collision nobody had named: Set ▾ already exists
The shipped toolbar has a Set ▾ filter six controls to the left of where By set now sits, and the two are one word apart. They are opposites, and that is the saving grace: Set ▾ narrows the cards you own to one set; By set leaves for a page of the cards you do not. Three things keep them apart, and all three are drawn: position (leading cluster = narrows the list, trailing = changes the surface), shape (a chevron menu versus a diamond link — no dropdown affordance on the pill), and the words — a noun that names an axis versus a preposition that names a destination.
The one thing that must not happen is the obvious convenience: carrying Set ▾'s value into the route so that filtering to EOE and tapping By set lands on /collection/sets/eoe. It is exactly the state-sharing that made Commanders and Discover confusing, and it would mean the same pill goes to two different places depending on a control the reader may have set ten minutes ago. The pill always goes to the index. If a shortcut is wanted later, it belongs in the Set ▾ menu as an explicit row — See EOE completion → — which is a different control saying so out loud, and it is not drawn here.

What changes, and what it costs
The identity pips move and become the cost track. They leave the leading slot beside the quantity and join a fixed 90px right-aligned track — a 20px mono mana-value disc, then the pips at 13px — which is deck-versioning's un-shingled track at the size it already ships. Nothing new is invented and no second pip component appears.
The leading 56px comes back to the name. Names on this row truncate today (Abdel Adrian, Gorion's Ward is close); moving the pips right buys the name column ~74px including the gap.
Cost, not converted cost alone. The disc carries the mana value and the pips carry the colours, which together are what the deck rows show. Full symbol-by-symbol cost is the ManaPip job already logged in commanders_discover — when it lands, this track is one of the ~6 sweep sites and the geometry does not move.
Lands keep an empty disc slot, not a zero. A land's mana value is 0 and printing 0 on 37 rows reads as a figure rather than an absence. The slot holds its width so the track never ragged-edges.
Phone: 76px track, on the meta line, per the same source. The quantity and name keep line one.
Scope note: this is a change to collection/rows-view.tsx, not to the set grid, and it is severable — it ships or slips on its own. It is in this package because it was asked for here, and because the set page's cells and this row are now the two places Collection states a card's facts.

What the index decides
Search is one field with two populations behind it. At rest the list is your 34 in released_at desc; typing widens it to the collectible catalogue. No scope control, no two tabs — the result line says how many matched and how many are new to you, which is the only fact a scope toggle would have carried.
Not-yet-indexed is a dashed --fg-locked tag in the ratio's slot, never 0 / 0 and never an empty bar — the spec's migration order exists precisely so a null denominator cannot be read as a real zero. The row still links; it lands on the grid's loading state.

No cost figure on the index. Cost to complete is a per-set computation over missing priced cells; summing it across 34 sets would print a number nobody intends to spend.

The cell, and why it is not a disabled control
The dim is on the art, never on the type. That sentence is the whole separation. A disabled control dims its label to --fg-locked and stops responding; a missing cell keeps its name at --fg-body (9.2–10:1 in all six), carries a live price, and opens the same card-detail modal. It is absent, not inert.
Three carriers, not one. Art opacity, a dashed edge, and the price tag that only a missing cell has. Greyscale alone fails the fast scroller; the edge alone is invisible at 1.5:1; the tag alone is 40px of a 196px cell.
The missing edge is --fg-locked dashed, not --border-dashed. Measured, --border-dashed runs 1.46–1.97:1 against the sunken plate in the six and fails the 3:1 non-text floor everywhere. --fg-locked clears at 3.16–3.44:1. Same dashed style — the app's not-settled vocabulary — on a token that can be seen. See §4.
No quantity anywhere. The spec makes a cell binary and rules playsets out of scope, so the badge this canvas drew at first draft is gone: a ×2 would assert a count the page has decided not to track.
Foil is the only mark an owned cell carries, and only when the holding is foil-only. Ruling 3 makes any finish fill the cell, so the mark is a fact about your copy, not about completion — which is why it sits on the art, not in the caption line where the completion facts live.
Rarity is a mono letter beside the number at --fg-locked — C U R M. Not a coloured gem: rarity colour is a fifth palette on a page already carrying five colour identities and an accent, and the letter is what the rarity filter is labelled with.
Money — one figure, one selector
The cost strip states its own gap in the same breath as the total — $1,284.40 over 193 of the 214 missing, with the 21 unstocked named at --fg-locked immediately after. Never a total that silently treats an unpriced card as zero.
The button is the page's one selector (#330's rule): Send 193 to ManaPool, whose count is the same number the sentence just gave. No per-cell checkbox, at either width — a checkbox on 214 cells is a second selection mechanism and would also put a 16px control inside a 116px art plate.
The button follows the filters. Filter to red rares and it becomes Send 9 to ManaPool with the strip's total recomputed — which is how a reader buys part of a set without a selection UI at all. The filters are the selector.
It is the page's one filled button, and it is filled --fg bone, not accent — accent is already doing to buy on 193 price tags below it.
Last-known prices are not marked per cell. as_of staleness is a property of the feed, not of a card; if the whole table is stale the strip carries one prices as of 8 Sep line. 214 individually-stamped tags would be noise in place of a fact.
R2 · Ruling 4 gets a mark, and the mark is an invitation
Ruled: mark the cell. R1 proposed one line in the head and nothing on the cell; Product overruled it, and the reason reframes the state — these cards are cool, and this is the page where you can finally see which one you have. An unpinned fill is not an error to disclose, it is the one moment the app can ask a question worth asking.
The mark mirrors the pin it is missing. printing_picker already ships Your pick as a filled 7px brand diamond. Unpinned is the same diamond, outlined, with BY NAME — bottom-left of the art, in ◆ FOIL's skin at the opposite corner. Not a new mark: the other half of one that exists.
It never lands on a missing cell, which is what keeps the three carriers of missing intact. Only a filled cell can have been filled by name, so the mark occupies a channel that is otherwise empty — and full-strength art beneath it is itself the disambiguator.
It is a mark, not a control. Tapping does what tapping any cell does: opens card detail — where the shipped Set picker already lives. No control enters a cell at any width, and the page adds no second write path against card_art_preferences.
Pinning from here moves the fill, and the page must show it. The pin key is (user_id, oracle_id), so picking #268 in the modal fills #268 and empties #262 — two cells changing from one act, the ratio unmoved at 62 / 276. The set page is the only surface in the app where that swap is legible, which is the argument for the mark in one sentence.
Cost accepted: on a collection pasted from a list the mark can appear on hundreds of cells. It is --fg-body on a 68% scrim at 9px, quieter than the foil mark and far quieter than a price tag, and it appears only where the art is at full strength — a field of them reads as texture on the cells you own, never as a field of errors.

The finding that changed the design
The first draft edged the missing cell in --border-dashed, reasoning that dashed is already this app's not settled vocabulary — the empty partner plate, the import proposal, the Building status pill. Measured, that token runs 1.46:1 on Oil Haze and 1.97:1 on Canopy against the sunken plate: correct as a whisper beside a filled shape, useless as the second carrier of a state. Call 3 — and the three things that pay for the scroll
One density, and it is the larger one. Compact saves 4,600px and costs the card name, which is the only thing in a dimmed cell a reader can search their memory against — the art is at 28% and the number means nothing to anyone who has not memorised a checklist.
No density toggle. A second view control on a page whose sibling route already has one, saving a scroll nobody performs end to end — readers jump, they do not scroll 276 cells looking for one.
1 · The head sticks. Ratio, cost strip and the three filters pin at the top of the viewport — 108px desktop, 96px phone — so the figure the page exists for is never scrolled away from, and the filters that change it are always reachable.
2 · Two sections, one jump. extras ↓ in the sticky result line is the page's only in-page nav. No A–Z rail, no number scrubber: collector-number order is already the reader's index.
3 · Missing-only is the real density control. It removes 62 cells here and far more on a well-collected set, and unlike a toggle that shrinks everything it removes the cells the reader is done with.
Windowing is an engineering call, not a design one, and the design does not depend on it: 399 cells of image_uri_small want loading="lazy" at minimum. Whatever is chosen must not break the sticky head or the extras ↓ jump.
