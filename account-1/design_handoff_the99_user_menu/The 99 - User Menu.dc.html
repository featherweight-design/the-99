Addendum · branded user menu · issue #35 → eng #13

The account menu stops looking like Clerk.

The trigger is already ours; everything that opens still belongs to Clerk — panel styling, the SECURED BY CLERK footer, the lot. This addendum replaces what opens, unifies the trigger across all three sites, and hands eng a per-element token map for the themed <UserProfile/> modal. One component, two viewports. No new atoms — the brass diamond and rail treatment come from #58's shipped shell.

Locked at the workshop — restated, not re-opened
Clerk attribution dropped. The caption does not ship. Dev-instance badge is untouched.
Manage account → themed <UserProfile/>, not a bespoke /account page.
Desktop trigger is avatar-only. It no longer spans the rail; the pill and the #31 click-forwarding go with it.
Popover is narrower than the rail and anchored to the compact trigger — not stretched left:12/right:12.
One trigger, one size, three sites. The 38/34 split ends.
Mobile stays a bottom sheet. Session actions stay Clerk's, behind our UI.
A11y baseline: focus trap while open, Escape closes, focus returns to the trigger, WCAG AA throughout.
Design's calls — the seven open items, answered
Resting size
38px, radius 12px — the shell's existing value. Two of three sites already ship it, so only the commanders header moves. 34px was the outlier, not the standard.
Touch target
Visual box stays 38px; the hit area is padded to 44×44 on both mobile sites. Compact does not mean small to the thumb.
Popover geometry
216px wide, left edge aligned to the trigger's, bottom: calc(100% + 8px). Sits 8px clear of the rail's right border so it reads as attached to the avatar, not as a rail drawer.
Removed caption replaced by
Nothing. The footer slot closes up. Two menu items and a person's name need no chrome underneath, and a substitute line would just be a different kind of reassurance nobody asked for.
Open-state marker
The ellipsis is gone, so a 4px brass diamond sits between trigger and panel — the shell's own motif doing a caret's job. Only where the panel is adjacent; the mobile sheet has no adjacency and no diamond.
Drag handle
Decorative (aria-hidden). Drag-to-dismiss needs a gesture dependency we're not adding; a handle that only half-works is worse than one that only signals. Backdrop tap, Escape, and hardware back all close.
Focus-visible
No override — the global :focus-visible ring at globals.css:130 already fits. Its 2px offset leaves a band of --bg between ring and brass border, so brass-on-brass still reads.
Motion
Two new named utilities, .anim-menu-in / .anim-sheet-up, added to the reduced-motion list at globals.css:166-173 — the same explicit-fallback pattern, not a blanket rule.

Sheet — what changed
Only one thing: the SECURED BY CLERK caption at appshell.md:1779 is deleted, and its 14px top margin with it. Container, handle, 48px avatar, 16px name, 12px mono email, both menu rows and the danger diamond all hold as specified.
Menu rows land at ~52px tall from 15px 6px padding — comfortably over 44px. The 26px bottom padding should sit on top of env(safe-area-inset-bottom), not replace it.
Handle — decorative, and honest about it
It's a shape that says "this came from the bottom edge", nothing more: aria-hidden="true", no pointer handlers, no cursor:grab. Drag-to-dismiss means a gesture library or a hand-rolled pointer-move implementation, and the constraint is no new dependencies. Three dismissals already work: backdrop tap, Escape, and Android hardware back.
Revisit only if beta feedback shows people dragging at it. Logged in the gap report.
Motion & reduced motion
.anim-menu-in — popover, 120ms ease-out, opacity 0→1 + 4px rise. Short enough that it never delays the first item's hit test.
.anim-sheet-up — sheet, 180ms cubic-bezier(.22,1,.36,1), translateY 100%→0. Backdrop cross-fades over the same duration.
Both names join the existing list in the prefers-reduced-motion block at globals.css:166-173 — scoped, not blanket, so the next animation still forces an explicit decision.
Reduced-motion fallback: both surfaces appear at final position, fully opaque, no fade. Closing is instant in both modes.

5 · Accessibility contract · both surfaces
Focus
Trap is active for the whole open lifetime, both viewports.
First focus = Manage account. There is no close button to land on and no filter to type in, so the first action is the right target.
On close, focus returns to the trigger that opened it — including the sheet's backdrop-tap and hardware-back paths.
Opening <UserProfile/> hands the trap to Clerk's modal; when that closes, focus returns to the trigger, not to the dismissed menu.
Contrast — measured on ground

Item label --fg on --surface-raised11.9 : 1 · AAA
Email --fg-faint on --surface-raised4.6 : 1 · AA
Focus ring --brass vs --surface-rail6.6 : 1 · AA
Sign out is not signalled by colour alone — the danger diamond sits beside the literal word "Sign out", and the label stays --fg.
Semantics
Trigger: <button>, aria-haspopup="menu", aria-expanded, aria-controls.
Accessible name is the person, not the initials: "Account — Ana Ruiz". Initials are aria-hidden.
Panel: role="menu" with two role="menuitem" children. The name/email header is not a menu item and is not focusable.
Sheet: same roles plus aria-modal="true" and a label pointing at the name. Handle and diamonds are all aria-hidden.
