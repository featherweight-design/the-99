The ruling: two rank maps, both global
The numeral recomputes. Build a second rank map from the free ordering, exactly as the first is built from the base ordering. Which map is in play follows ?avail=.
Because the invariant is about filtering, and this is not filtering. A filter hides rows without changing any score — renumbering there would be a lie, since the card’s standing among all 214 has not moved. Score against changes the score itself: under What’s free, Kykar genuinely is the third-best thing this player can build right now. The numeral names position in the ranking on screen, so it must agree with it.
The alternative is unreadable. Frozen numerals would render 3, 4, 1, 2 down the page — a list whose numbers disagree with its own order. That is worse than either behaviour on its own.
Global, never post-filter. Both maps are built over the full candidate set before any colour filter applies, so the shipped rule survives verbatim in both modes: filtering never renumbers. Third column shows it — 2, 3, 4 with a gap where rank 1 was.
And Order: Fit ↓ · fixed stays literally true. The order rule is Fit descending in both modes and there is still no ordering control — what changed is the measurement, not the sort. The label needs no edit. If it ever reads as a promise that numerals are frozen, the fix is the label, not this ruling.

The ruling: yes, it resets
Same class of event as a colour-filter change, so it takes the same behaviour: shown → REVEAL_STEP, remaining recomputed against the current result length. Windowing’s own rule already covers it — the window is a property of the current result set, not of the session — and a re-rank produces a new result set in the only sense that matters: different cards occupy the revealed range.
Keeping shown = 50 would hand the player fifty different commanders with no signal that the set beneath them had changed. Resetting is the honest read, and it is the behaviour they have already met on the filter.
The delta needs no anchor in the list. ↓21 from 82 compares a card to itself — its own two scores — never to another row. So it is window-independent by construction: it reads correctly on rank 3 or rank 200, revealed or not, filtered or not. Nothing to fix.
One real cost, accepted. A commander at rank 3 under Everything I own can land at rank 60 under What’s free — outside the first batch, so it vanishes from view on the flip. That is the toggle telling the truth, and the 25 shown · 189 more below count says there is more. Auto-revealing far enough to keep a previously-seen card visible would be a new windowing pattern; not worth it for R2. Carried as gap §10.
The was 1st annotation is optional and I would ship without it — it is drawn above only to show what the reset costs. It is the one thing in this addendum I would not defend hard.
B · rowAria — the clause joins, it does not supplant
R1 — wrong. A replacement that drops the type line.
rowAria: (name, ownedQty, clause) =>
  clause ? `${name}, ${ownedQty} owned, ${clause}` : …
→ “Cyclonic Rift, 1 owned, 0 free”  — type line gone from every Consider row
R2 — the shipped signature, one optional trailing argument
rowAria: (name, typeLine, owned: boolean, availability?: string | null) =>
  `${name}, ${typeLine}, ${owned ? 'owned' : 'not owned'}`
    + (availability ? `, ${availability}` : '')
→ “Cyclonic Rift, Instant, owned, no free copies; this one is on your Atraxa list”
→ “Swords to Plowshares, Instant, owned”  — free state, no fourth argument, byte-identical to shipped
Three properties this now has. The first three arguments and their order are untouched, so existing call sites compile and behave identically. owned stays a boolean — the marker’s clause carries its own counts, so nothing needs a quantity here. And a free card produces the exact shipped string, which is the accessible-name form of “silence is the default”.
Where the clause comes from
The availability argument is one of the marker.*Aria strings already in the copy file — softAria, hardAria, hardMultiAria, overAria — or null. It is prose, not the visual label: the eye reads 0 free — in Atraxa, the ear hears “no free copies; this one is on your Atraxa list”.
Same reason the diamond is aria-hidden: a decorative glyph should not become a word, and a terse mono label should not become a sentence fragment.
Applies to the decklist row too. Row density on both surfaces takes the clause the same way; only the caller differs.

The ruling: banner where there is one, quiet where there isn’t
On /commanders: reuse DegradedBanner — the shipped amber-left-border form with Retry now, unchanged. Availability folds into the same query, so a failure that would already have shown a banner shows this one instead, with its own message.
Because on this surface, quiet failure lies. A silent fallback would leave What’s free selectable and produce scores identical to Everything I own — the player would read “nothing you own is committed” from a network error. So the free segment is disabled and struck, selection reverts to Everything I own, and ?avail=free is honoured again after a successful retry.
On the builder surfaces: genuinely quiet. Consider tiles, decklist rows and quick add have no banner, no recs query and nothing that changes meaning — the marker is pure annotation there, so its absence degrades to exactly the silent state a player with no commitments sees. Never block, and never a banner over a working list.
The distinction is load-bearing, so state it plainly: a banner is owed wherever the failure changes what a control means. Nowhere else.
Two degraded reads can co-occur — EDHREC down and availability down. One banner, two sentences, one Retry now; never two stacked banners. Flagged for engineering rather than drawn.
