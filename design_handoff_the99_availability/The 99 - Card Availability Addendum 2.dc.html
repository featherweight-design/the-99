Two more surfaces. Same diamond, one thing dropped.

The four-state marker is inherited exactly — hollow, solid, doubled, and silence — with one deliberate reduction: on /collection the claiming deck’s name is dropped and the marker runs count-only. Neither view has a cell that can hold a proper noun without the grid moving, and the grid is fixed.

Deck detail gains a soft-claim roll-up for the pre-99 window, sitting under the over-committed line when both fire. Two lines maximum, ordered by severity, and both absent for a player whose collection covers their decks.

Read README.md and ADDENDUM-README.md first — the seven original calls and the R2 rulings both stand. Nothing in #43 is reopened here. The deck index stays untouched.

Three of seven rows carry nothing. The name truncates before the chip does — the chip is flex:none, the name is the flexible half.
The call: the name cell, inline, count-only
The row-density rule doesn’t transfer, and the reason is instructive. On the decklist the marker appends to ×1 owned — a sentence about ownership with room to grow. Here the quantity is ×1 in a 38px column: a fixed-width numeral, not a string. A count cannot annotate a count, and widening the column would move a shipped grid for a state most rows never show.
So it goes in the 1fr cell, inline after the name — the only cell in either grid with slack. Inline rather than a second line, so row height is constant and the 1,418-row scroll keeps its rhythm. The name yields first: it already truncates, and a truncated name plus a legible marker beats a full name and a clipped one.
The claiming deck’s name is dropped here. 0 free — in Atraxa needs about 120px it cannot have on phone, and gap §2 already flags that deck names have no length budget. Rather than invent a truncation rule on the widest list in the app, collection runs the count-only form and the name appears in card detail — which has the room, and where opening a card is already the “tell me more” gesture.
That is a reduction, not a new state: same glyph, same copy keys, one clause shorter. It also means collection never needs hardMulti, closing the drawn/undrawn gap from R1 §3 on this surface at least.
Over-committed keeps its border tint and nothing else. Still the only state that touches its container, still never a dim or a stripe — on an inventory list every row is equally real, and none of them is unavailable.

The call: top-left chip, and the caption stays
The tile rule transfers; only its caption half doesn’t. On Consider the chip sits top-left because top-right is the ownership dot — here top-right is the brass quantity badge, so the same corner is free for the same reason. Nothing about the chip changes: same glyph, same scrim, same 8.5px label.
The caption line is already spoken for. C21 · uncommon is set and rarity — the two facts a player scans a collection grid for. Consider’s tile could spare a line for in use — Atraxa; this one cannot, and displacing set/rarity to name a deck would trade an inventory fact for a deck fact on the inventory surface.

Four checkboxes, not two exclusive states. Availability is a property with four values, so it filters like Type ▾ filters — pick any combination. “Free only” is one selection among four rather than a mode.

Counts in the dropdown because that is the answer to the inventory question before you even apply it: 1,186 free, 168 spoken for, 61 locked, 3 short. A player who reads only this menu has learned the shape of their own collection.

Nothing defaults on. Arriving at /collection shows all 1,418, as it does today.
Why this doesn’t contradict §5
§5 ruled against a second control because of a collision, and the collision isn’t here. In the builder, Owned only and a hypothetical Free only are two checkboxes about the same noun, four millimetres apart, differing on a word the player has known for minutes. On /collection there is no ownership control at all — everything here is owned by definition. Nothing to collide with.
And the question genuinely changes. The builder asks “what should go in this deck”, where a filter that hides a card is a block wearing a filter’s clothes. Collection asks “what do I have” — a question filters are the native answer to, on a surface that already ships four of them and a chip row for exactly this.
It is a filter, not a mode — which is what keeps it clear of the Score against toggle too. That ranks and never hides; this hides and never ranks. Different surfaces, different verbs, and neither one ever appears next to the other.
It joins the existing filter row as one more dropdown beside Type / Set / Sort — fourth on desktop, where colour is an inline pip row, and fifth on phone, where colour is its own panel. And it reuses decision 2 wholesale. Chips (In use ✕) with the marker glyph as the chip’s leading dot, the live Showing N of 1,418 count, Clear all, and a 1:1 query param — ?avail=inuse,over. No new control pattern enters the app.
Silence survives it. A player with no commitments opens the menu to 1,418 / 0 / 0 / 0. The three non-free rows render disabled — the one place in this pass where the concept is visible to someone it does not apply to, and it costs a menu they had to open.

The call: one region, max two lines, severity order
Stacked, not merged. The two lines describe different problems with different resolutions — one is a shopping decision, the other resolves itself the moment you sleeve something. Merging them into “13 cards are contested” would average a real problem with a non-problem.
Red above muted, always. Fixed order, never sorted by count — a deck with 1 over-committed and 40 soft still leads red. The severity ladder is the same hollow → solid → doubled progression the marker uses, read vertically.
The counts are disjoint, and the copy proves it. A card is either over-committed or softly claimed, never both, so 1 and 12 sum to 13 contested cards. When the soft line follows the red one it reads “12 more” — one word doing the arithmetic so the player doesn’t have to.
Why the soft line is deck-level at all. Twelve hollow glyphs scattered down a 62-row list is a pattern nobody perceives — the same argument that put the over-committed summary at the top in §3. One line makes twelve markers legible as a fact about the deck.
Pre-99 only, and it exits quietly. Once the deck hits 99 and turns Playable, its own claims go hard: the soft line disappears and any genuine conflict has already promoted itself to the red line. The disappearance needs no announcement — the player just finished a deck, which is the good outcome.
Still not on the deck index. Locked decision 2 holds: no roll-up, no badge, and the status pill keeps meaning card count and nothing else.

The ruling: the current deck is excluded, both severities
On a deck’s own list, the marker scores against every deck except this one. One rule, no special case for hard or soft — which is why the soft case already read correctly in the drawing you spotted: 1 in a brew inside Kykar was always another brew. R3 states it rather than implying it.
Because a deck holding a card is not competition for itself. The marker answers “can I still build with this?” — and inside a list, the card is built with. 0 free — in Atraxa, rendered inside Atraxa, is the app telling a player something they can see in the surrounding 98 rows. It would also invert “silence is most of the app” on the surface where a finished deck is the success state.
No, 0 free does not earn its place as a cut warning. A cut releases a card — it is the one action that makes a copy freer. Warning on it would be the only place in this system where the marker discourages a move, and locked rule 1 is that we never block; a marker that argues against an action is a soft block. If cut-time guidance is ever wanted, it belongs on the cut, not on all 99 rows in advance.
A consequence worth knowing: inside a finished deck, the hard state is unreachable. If another finished list also claims your only copy, two hard claims on one card is over-commitment — so it presents as short 1, never as 0 free. A deck’s own list therefore shows exactly three things: silence, a brew wanting a spare, or a genuine shortfall. The loud state survives self-exclusion — which is the proof the rule drops noise and not signal.
One copy tweak. On a deck’s own list the over-committed clause names the other claimant — short 1 — also in Kykar — because “2 decks want it” would count the deck you are standing in. Same key family, new variant overAlsoIn; the deck-index and collection forms are untouched.

Contract · what this addendum adds, and what it doesn’t
Accessibility
Collection rows extend the shipped row label, they don’t replace it — the same rule as rowAria in R2. “Smothering Tithe, Enchantment, 1 copy, Ravnica Remastered, rare, no free copies” — the clause lands last, and a free card produces today’s string exactly.

Count-only in the label too. Collection never speaks the deck name, matching what it shows. Card detail speaks the full clause with the status pill.

The filter is a group of checkboxes in a labelled menu — aria-labelledby the Availability heading, each option carrying its count in its accessible name (“In use, 61 cards”). Chips are buttons: “Remove filter: in use”. Zero-count options are aria-disabled, not removed — a menu that changes length between players is worse than one with dim rows.

The roll-up region is a <section> labelled “Card commitments”, holding one or two static lines. Not a live region, not an alert — it is there on arrival, and nothing about it interrupts.

Contrast against --surface #1E1A15, unchanged from R2: #E8CE93 11.8:1 · #E9917A 7.6:1 · #C6B79A 9.2:1 · brass 7.5:1 — all AAA for normal text. Filter-menu rows are 40px; the 44px minimum applies to the trigger and the chips’ ✕, which are the phone targets.
Scope & cost
No new tokens. Every value is one of the four from #43 or an existing brand token. No new hues, no new dependency, no motion — the marker still never animates.

No grid changes. Both collection grids ship as-is: 38px 40px 1fr auto and 52px 54px 1fr 150px 92px 18px. The marker borrows slack from 1fr; nothing is added, widened or reordered.

One new query param — ?avail=inuse,over on /collection, comma-separated like the existing multi-value filters. Distinct from /commanders’s single-value ?avail=free; same name, because it is the same concept on both, and no page reads the other’s.

The collection query is the expensive part. Availability for 1,418 unique cards is the same cross-deck aggregate as #43, joined once for the whole page rather than per row. If it fails, /collection fails quiet — markers absent, and the Availability trigger disabled with the R2 segmentDisabledAria reason. No banner: this surface has no ranking to mislead, so silence tells no lie here.

Copy is appended to availability.ts as collection and deckRollup blocks — no key renamed, no string edited. Free and in use remain the two nouns.
