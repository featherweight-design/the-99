Printed name · addendum to card surfaces · audit patch: the tile is the tightest surface

Both rows have room. The tile does not.

The brief asks which gives when a printed name is too long for a row, and offers the phone widths as the case. Measured, no row is the answer. One subtraction from one usable width: the 400px desktop row holds 174px of name after the count, about 27 characters; 390 holds 175px; 320 holds 105px. Battle of Olympus measures 108px and fits on all three. The deck tile caption holds 93–94px — sixteen characters — and is the one surface where the spec's own example clips.

R3: the numbers above are re-derived, and R1's were wrong. R1 subtracted the row's fixed spend twice and reported a 96px desktop block, which is why it named desktop the tight surface. The finding survives and moves. The audit also found no two-line clamp in the tree — both grid captions are single-line truncate — so the tile is ruled as a second single-line ladder with the ✕ moved off the caption line, and no clamp is added. One consequence worth stating: the ranking is not width-monotonic — 320 with a count (105px) is tighter than the 400px desktop row (174px), because the phone row spends 44px on a touch-target ✕ out of a smaller budget. Design for the surface with the least name, not the fewest pixels.

So the name is what gives — on every surface, by one rule. A decklist of ninety-nine rows cannot wrap one name without going ragged, and everything beside the name on the All tab is already at its floor after the card-surfaces $ collapse. Truncation is not a phone special case — it is what happens wherever the block is too narrow, which is the desktop row first and the tile caption hardest. The widths anyone was worrying about are not the widths that needed the ruling.

call 1 · the oracle-name line
Between the title and the type line, not after it. Body face 13.5px desktop / 13px phone, weight 400, --fg-body, with a mono 10.5px --fg-faint label reading oracle. Gap to the title 5px, gap to the type line 10px — the pair reads as one unit and the type line stays a separate fact.
call 2 · what gives on the row
The name gives — at both widths, by one rule, and the count never does. The name block is the only shrinking child; the count rides inside it after the name at flex-none. Not a phone special case — desktop is the tighter row, and the tile caption is tighter still.
locked 1 · one resolver
The name follows resolvedPrinting(), the same printing the art already comes from. Drawn, not decided — and it is the reason nothing here needs a new query: the surface already knows which printing it is showing.
locked 2 · the control state
A card you do not own keeps its oracle name, and a card whose printing prints its own name is byte-identical to today. Drawn as its own state on every surface, because nothing changes is the state most likely to regress.
call 3 · the tile caption
No clamp. Single line, and the ✕ moves to the art corner — 94px of caption becomes 132px. Equal-height tiles outrank twelve characters.
calls 4 & 5 · tooltip, two faces
The shipped title is dropped for an aria-label. Two-faced cards show the front face on rows and tiles, both in the modal.
locked 3 · one name per row
Rows and tiles show the printed name alone. No parenthetical, no second line, no marker. The consequence is worth stating: a truncated printed name on a row has no fallback on that surface, which is exactly why call 2 states a floor and why locked 4 matters.
locked 4 · the modal is the survivor
The modal is the only place both names appear. So it is also the recovery path for every truncation this addendum permits — the name is the modal's own trigger, one tap from the row that clipped it.

Call 2 — the name gives, on every surface, by one rule
1 · The name block is the only shrinking child — and on the row it already is. flex-auto on the name block with flex-none on every sibling has been the row's shape since #354, which delivers this outcome already. Keep flex-auto; do not swap it for flex:1. The only requirement worth restating is min-width:0, without which the block refuses to shrink at all.
2 · The count rides inside the name block, after the name, at flex-none. So ×2 is never the thing that vanishes: a row that loses its count stops saying how many copies the deck runs, which is a fact the row exists to carry. The name loses characters; the row never loses a field.
3 · No wrap, ever. A wrapped name makes one row taller than its neighbours, and card-surfaces already ruled that row height may only change at a group boundary. Ninety-nine rows with a ragged edge is a worse read than thirteen characters and an ellipsis.
4 · Nothing beside the name can pay. The marker is the floor's own slot, the buy tag is already a bare $, the cost track is fixed at 40px so adjacent rows align, and the ✕ is at its target floor. The row was already spent before this addendum arrived.
5 · The full printed name goes in the row's aria-label, never a title. Screen readers get all of it; sighted readers get the modal, which is the name's own trigger. No tooltip — a hover tooltip on a phone-first row is a control half the users cannot reach. R2: the deck tile ships one today and it goes.
What call 2 actually costs, after the audit. Less than R1 thought on the row and more elsewhere. The row needs no shrink-order work — #354 already gave it — and #467's truncation turns out to live on the Add panel, not this row, so there is no branch to delete and nothing to overrule. What remains is real: ratify the row's behaviour as a ruling rather than an accident, extend the same single-line ladder to the tile caption (call 3, the tighter surface), and put the full name in aria-label on both. R3: the measurement it rests on has been re-derived — the desktop row holds 174px, not 96px, and the surface that actually needs the ruling is the tile at 93px.

Why above the type line, not below it
The type line describes the card; the oracle name identifies it. Identity belongs beside identity, and the pair is the thing that just changed — a reader resolves which card is this in one movement and only then reads what it does. Putting the oracle name after the type line would interleave two answers to two different questions. Gap 5px to the title, 10px to the type line: the tighter gap is what makes the two names read as one unit rather than two facts.
Why body face at 13.5px, weight 400
The title is the display face at 29px, so nothing at 13.5px in Plex Sans can compete with it — which is the point: the printed name is the card's name here, and the oracle name is a gloss. Ink is --fg-body, one step brighter than the type line's --fg-muted, because a name outranks a type. 8.77:1 on --surface in every theme. No italic — italic is the modal's reminder-text convention and this is not reminder text.
Why a label at all
Two bare names stacked is a puzzle — the reader cannot tell which is authoritative, or why the app is showing them a second one. One mono lowercase word at 10.5px --fg-faint settles it, and mono-lowercase-as-field-label is the shipped register (no number · ×1, SLD · 2208). It costs 38px on a line with room.
The line is absent, not empty
When the printing prints its own name the line does not render — no label, no placeholder, no reserved height. The type line moves back up to its shipped 6px and the header is byte-identical to today. This is the state to regression-test, because it is every card but a handful.

5 · rejected
A parenthetical on the row. Battle of Olympus (World at War) doubles the widest field on the tightest surface to serve a question the modal answers in one tap. Locked 3 forbids it; the measurement agrees.
A marker glyph for “this name is a printing's name”. Card-surfaces spent a whole ruling keeping the row to one small mark, and this would be a second 7–9px shape meaning something unrelated a few pixels away. The name being unfamiliar is not an error state.
A hover tooltip carrying the full name. Pointer-only recovery for a phone-first surface, on a delay, duplicating the aria-label. R2: not hypothetical — it ships on the deck tile today (deck-card-tile.tsx:188) and R2 removes it.
Wrapping the name on the row. One taller row shunts the ninety-eight below it, and row height may only change at a group boundary.
A two-line clamp on the tile caption. R2. Buys ~12 characters and costs the grid its equal-height read — the property that makes grid view worth choosing. Reserving two lines up front pays the same on every tile in the app.
The full // string on a row or tile. R2. Unpredictable length in the tightest block on the surface. Front face on rows and tiles; both faces in the modal.
Dropping the count to buy name width. It is 27px, and losing it costs the row the fact it exists to carry. A row that sometimes omits a field is worse than a name that sometimes ends in an ellipsis.
A reserved empty oracle line. 23px per card on every ordinary card, to make the ordinary case look incomplete. The line is absent, not blank.
The oracle name below the type line. It interleaves which card is this with what does it do. Identity beside identity.
Italic for the oracle name. Italic is the modal's reminder-text convention. Reusing it here would make a name look like rules flavour.
A phone-only truncation rule. 390 is the roomiest surface on the feature. A rule fired there and nowhere else leaves the two tightest — both deck tile captions, at 93 and 94px — unruled.
