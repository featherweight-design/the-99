R1
Card line item parity · six rows, one ruling

A card row owes you its name and whether you can play it.

That is the floor, and it is two elements — the name, and the availability slot. Everything else on a card row is that surface's own business: a shopping row leads with price, a browse row leads with what the card is, and they are right to differ. The floor reaches every row that stands for a card at both widths. It does not reach unresolved-row, and the reason is data rather than density: that row has no oracle id, so there is no card whose availability could be stated.

Two rows change, one atom retires, and three radii become one. update-diff-row gains the availability slot; synergy-row gives up its private dot; rows-view swaps a real border for an inset ring so an over-committed row stops shunting the list. Mana pips do not generalise, and the ownership dot is dashed.

1 · Mana appears in two rows, not one — and they draw different things. rows-view.tsx draws colour identity pips from colorIdentity. card-search-row.tsx already draws mana cost pips — <CostPips cost={result.manaCost}> in a fixed 34px desktop slot. So the add-panel search row is not missing mana; it is showing the more useful of the two. That changes Q2's answer from "should it spread" to "the two are distinct affordances and neither spreads".
2 · The private dot is no longer private to the row. The brief cites synergy-row.tsx:33; it now lives in commanders/availability-dot.tsx as AvailabilityDot + LegendPip, with a docblock arguing it cannot be the shared dot. The finding is unchanged — solid vs dashed, and a third colour — but the fix is a merge of two modules and it takes the legend with it.
Q1 · the floor
Name + one availability slot. Both widths. Every row with an oracle id. The slot holds exactly one of BuyTag or AvailabilityMarker — never neither, and never both except the Shopping second-copy case where both are true. unresolved-row is exempt: no oracle id, no card, nothing to state.
Q2 · mana pips
Neither generalises. Identity pips stay on /collection, where identity is a filter facet over 20,000 cards. Cost pips stay on the search row, where the question is which of eight candidates to add. On a decklist every card is already inside the commander's identity, so an identity pip there carries no information and costs 54px.
Q3 · the dot
Dashed for unowned — the shared dot is right. Three states, one component. Dashed is this app's shipped word for absence (the spent slot, the unnamed plate, --border-dashed). Committed does belong in the shared atom — it is a fact about your copy, not about synergy — but as an opt-in third state, not a default.
Q4 · density
44px phone / 34px desktop, radius 7px at both widths, gap 9/10, pad 8–4 / 9. The decklist row's metrics, because it is the densest row that already clears a 44px phone target. One named exception: 52px phone when the row carries a meta line under the name. Radius 6 and 8 both retire.
The over-committed tint
An inset ring, never a border. inset 0 0 0 1px var(--avail-over-border) on the shell. The decklist row's reason generalises: a real border adds 2px to one row and shunts every row below it. rows-view currently uses a border and changes.
The mobile ledger
Every addition names what it displaced. Nothing new lands on a phone row without a subtraction on the same line — and the count-only marker is ~50px, which is the whole budget. The ledger is drawn under each row that changes.
Q4 · the canonical shell — one set of metrics, two content strategies
The shell — what all six share
min-height44px / 34px — 52px phone w/ meta
border-radius7px — both widths, no responsive pair
padding8px / 4px phone · 9px desktop
gap9px phone · 10px desktop
background--surface-rail in a list · --surface on a page
hover (desktop)--elevated-hover, and --row-bg swaps with it
over-committedinset 0 0 0 1px --avail-over-border
name type12.5px phone / 13.5px desktop, --fg
Two content strategies, not two shells. Five rows are flex: slots left to right, the name taking the slack. rows-view stays a grid, because a browse list is read down its columns and a flex row cannot hold a set code on one vertical line. It adopts the shell — radius, gap, ring — and keeps its template.
What retires — and what it is replaced by
radius 6px (phone)→ 7px. Invisible at 375px, and a responsive radius is a token nobody can hold in their head.
radius 8px→ 7px. 8px on a 34px row reads as a pill; the three rows using it are the three tallest.
commanders/availability-dot.tsx→ merged into ui/ownership-dot.tsx, three states. LegendPip moves with it.
diff row's hand-rolled buy pill→ the shipped BuyTag, in the shared availability slot.
diff row's OwnedDot→ the shared dot. It is a third copy of the same two-state span, and it already agrees (dashed).
rows-view's over border→ inset ring, so an over-committed browse row no longer sits 2px taller than its neighbours.
No new token, no new hex, no new component. The floor is satisfied entirely by atoms that already ship. The one net-new export is a third state on a dot that already has two.

Q3 · the dot — three states, one component, dashed for unowned
The three states at 8px
owned --success, filled
committed --avail-hard-fg, filled
unowned hollow, 1px dashed --fg-locked
Committed is filled, not a third shape. A committed card is owned, so it keeps the filled disc and moves hue. Hollow is reserved for absence — and it costs no width, which is the whole reason the private dot got it right.
Why dashed wins — the app already said it three times
the add panel's spent slot — a card that was there
the diff's we cannot name these plate
--border-dashed exists as a token for exactly this
A solid hollow ring reads as a state of something present — the same vocabulary the availability marker's soft diamond uses. Dashed reads as an absence. Two rows out of six draw the ring solid today, and both are the same module.
The legend, which moves with it
free to sleeve
already in a finished deck
not in your collection
The legend renders the dot rather than naming its colour — that call is already made and ratified in availability-dot.tsx, because --avail-hard-fg is redefined by all six themes and "amber" is true of one. It survives the merge unchanged.
Q2 · two mana affordances, and neither generalises
Colour identity — /collection only
Identity is a filter facet on this surface: the reader has just narrowed 20,000 cards by colour and the pips are the receipt. A 54px track, shingling from four pips so it never widens.
×1 Dovin's Veto identity, not cost
Mana cost — the search row, already shipping
Cost is the choice between candidates: eight near-identical names and the question is what each one costs to cast. Fixed 34px slot, drawn whether or not the card has a cost, so the ownership column stays on one line.
Dovin's Veto ×1 owned
Refused — identity pips on a decklist
Every card on a decklist is already inside the commander's colour identity — that is the format. So a pip track there is 54px spent to restate a constraint the deck cannot violate, on the surface with the least room and the most trailing controls. On a 375px shopping row it would displace the whole availability slot, which is the one element the floor requires. Refused for the same reason on the diff row and the synergy list.
