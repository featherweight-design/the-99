## R2 changes (supersede the R1 calls below where they differ)

1. **No not-owned fact.** The dashed dot and the controls say it. `in your collection` stays, on upload-read tokens only.
2. **Manual ownership: `I have one`.** A quiet text control beside `Add to Shopping`, shown on every token not read as owned, including before the read. Pressed, it holds as `✓ I have one` (`--accent`), the dot fills, and `Add to Shopping` leaves; a joined token leaves Shopping. Press it again to unmark. It writes the token ownership record with `source: manual` (G2a). The T0 band names both ways in.
3. **Makers: hover preview and click.** Every name uses the decklist's `HoverPreviewProvider` on desktop, and opens card details on click or tap with the stacked-sheets return.
4. **Long maker lists scroll.** Past 9 names (5 on a phone): a sunken box, 158px or 240px, with a 28px fade, `overscroll-behavior: contain`, and the label gains `A–Z · scrolls`.
5. **`Made by` becomes `Generated by`.**
6. **`On Shopping` becomes `In Shopping`.**
7. **Copy is a token.** It's an ordinary row that can be owned, marked, joined and bought. Lock 9 is overridden (Hugh to confirm). Omnath counts 14, Thorin 8, Wizards 1.
8. **Shopping follows the shipped page, buy box first.** The toggle row, then the buy box (figure, split line, provenance, link, sends), then the limit and key lines, the intro, and the type groups, with Tokens last. The box is above every group, so no number of tokens can push the link below the fold. With cards and tokens, the figure is what the link buys, and the split line keeps the deck's own figure: `67 cards · $270.48 · 4 tokens · $0.70`.
9. **No Makes block in card details.** One line at the foot of the existing **In this deck** box, under the proxy note: `Makes a Food token · In Shopping` and `Tokens ›`. Only from a deck, and only when the card makes a token.

New gap **G2a · Manual marks and upload.** An upload adds the tokens it reads and never removes a hand mark, because the CSV may simply leave tokens out. Unmarking is the only way to clear a hand mark. If an upload reads a token the player had marked, the mark becomes an upload row and keeps no `manual` flag.

## Design's calls (§What Design owns)

1. **Where: a `Tokens` group at the foot of Your deck, under All,** after the last type group (or role group), headed by the shipped `DecklistGroupHeader` with `not in the 99 · from N cards` as its desktop note (a sub-line on the phone). Card details gain one **Makes** block. No tab, no sheet, nothing on Stats. Under the Card view the group stays rows: a token has no card tile.
2. **The row** is a decklist row (`--surface-rail`, radius 7) with a 26×36 art thumb. The name line carries the name, the color pips (the row's pip style; `C` for colorless), and `Creature · 1/1`. Under it is the makers line, `from Appa, Steadfast Guardian and 2 more`. One column at both widths, because rows open in place and a two-column grid would go ragged.
3. **Two tokens of one name** are told apart on the name line by pips and power/toughness, never by a suffix or a number. When those also match (two red 1/1 Goblins), a mono text line shows (G4). A double-faced token puts both faces in one type line: `Artifact // Artifact Creature · 0/0`.
4. **Makers fold into the row.** The disclosure (▾) opens `Made by N cards`, the makers A to Z as links (13 / 600, `--fg`, the combo partner's underline) in 1, 2 or 3 columns by count on desktop and one 44px line each on a phone. Each opens that card's details, as a combo partner does, with the stacked-sheets return. Then one printing line: `pictured and sent: TLA T9 · $0.15 · cheapest of 1 printing`.
5. **Ownership: the deck row's dot plus one mono fact.** Owned is a `--success` dot and `in your collection` (`--fg-muted`). Not owned is a dashed dot and `not in your collection` (`--fg-faint`). Not known yet has no dot and no fact. No verdict word, no warning color, no icon.
6. **Joining Shopping: one control,** `Add to Shopping`, on every token that isn't owned (shown when not known, too). Joined, it holds as `✓ On Shopping` with the `--accent` border and 14% wash. Pressing it again takes the token off, as does the Shopping row's ✕. The row itself never changes.
7. **In Shopping: a `Tokens` group pinned last,** after Spoken for, with the clause `2 · not in the deck's count`. The rows are the shipped Shopping row with a `token · 2/2 R · set #` sub-line. Never counted in the pill, the status, the to-buy figure or `/decks`' roll-up (lock 7). The price strip keeps its figures and adds one line, `+ 2 tokens · $0.30`.
8. **Copy is a note, not a row** (Q2). That's engineering's exclusion with the reason shown, and it's Hugh's call.

## Open questions, answered

1. **Before the read:** once, at the head, with the upload link. Rows lose the dot and the fact, and keep the control.
2. **Copy:** excluded from rows and counts, kept as one dashed note with its maker. Wizards draws the note alone.
3. **Printing:** one representative, by the deck price rule (lock 6), pictured and sent. No chooser this round.
4. **Per deck:** one row per deck. Card details get Makes. No cross-deck list on the deck page.
5. **Shopping:** its own group, last. Not in the pill. The strip adds a `+ N tokens` line.
6. **Link-out:** token lines carry set and number, and the sends line says so. Card lines are unchanged.
7. **All-decks cart:** one copy for every deck that joined it (lock 8 logic). It's a line in the cart's own Tokens group, not drawn this round.
8. **Many tokens:** rows at any count, never folded. The makers fold inside each row.

## Gap report

- **G1 · Fixture names.** The brief gives Aang's tokens only. Omnath's 13, Thorin's 19 Treasure makers, Wizards' Copy maker and all set codes are illustrative. The read-only script in §Fixtures should export per-deck token names, makers and the price rule's printing, so R2 draws true rows.
- **G2 · The read marker drives T0.** Lock 5's per-account marker decides between T0 and T1. With no marker every row is `unknown`. With a marker and zero token rows, every row is `not`. The band reads the marker, never the ownership table's row count.
- **G3 · Bought, for a token.** I got it writes `collection_items`, which a token can't enter (lock 5). This round the token Shopping row's tag is **not pressable**, and a joined token leaves Shopping when an upload reads it as held. Marking a token bought needs a write into the token ownership record, which is its own decision.
- **G4 · Same name, same color, same stats.** Lock 4's token record has no rules text, but two red 1/1 Goblins can only be told apart by it. Proposed: add the token's oracle text (or keywords) to the record, shown as one mono line only when name, colors and P/T collide within a deck.
- **G5 · Price per token.** Lock 6 needs token printings priced. The row's printing line, the Shopping tag and the strip's `+ N tokens` all read that one figure. A token with no live price draws `buy · sold out` and is left out of the strip's sum, with the shipped `pricedClause`.
- **G6 · Mixed link format.** One `manapoolAddDeckUrl` with name-only card lines and `[SET] number` token lines. Engineering should confirm Mana Pool accepts both in one URL, and the URL limit with the extra characters.
- **G7 · The cart.** One copy for every deck (Q7) needs the roll-up to merge joined tokens by token oracle id across selected decks. That's the cart's next round.
- **G8 · Feature switch.** `DECK_TOKENS_ENABLED`, plus an `AboutSwitch` member for the entry. The catalog and upload PRs ship dark, and the surface rides the last PR with the bump.
- **G9 · Join state.** Per deck and per token (lock 7). It needs the Shopping list's read to carry joined tokens so `buildMarkKeyEntries` and the strip see them. A joined token whose link disappears from the catalog (a maker cut) stays joined until it's taken off, drawn in the group with `from no card in this deck`.
- **G10 · Makers that are commanders.** A commander that makes a token is a maker like any other and opens its own details. The commander isn't a `deck_cards` row, so the link query must union the commanders as `list_claims` does.
