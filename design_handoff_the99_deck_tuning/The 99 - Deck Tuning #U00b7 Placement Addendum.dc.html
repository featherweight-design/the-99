How it relates to the reading

Last, under its own rule. The tab reads top to bottom as what the deck is, then what it is short of, then what you could change. The reading is computed; the panel is a proposal. It never sits beside the bracket box or inside the grid.

It never cites the bracket. No suggestion names a bracket, a finding or a rung, and no chip reads from them. Coming down a bracket is the climb's own sheet. The consequence line is the deck's status (99 / 99 · complete), never a bracket.

An applied swap is an edit. It sets the deck's changes flag like any other edit, so the tab's one banner offers Re-analyze. The panel never re-analyzes, and Re-analyze never re-runs the panel.

Staleness stays in the banner. A stale reading does not dim, tag or hide the panel.

Mounts with the grid. Before a first reading (2a–2c) the tab is one empty state and the panel is absent. Analyze is free, so asking for it first costs nothing.

Phone: the same order in one column, the panel last. Nothing in the panel changes from its approved phone frame; 44px floors hold.

Rules

One string, one module. Both surfaces import allowanceCopy.exhausted(time). It names both things the allowance pays for, so it is true wherever it appears, and a player who used it on the synopsis learns why the panel stopped.

Not a failure. No tag, no --danger, no Try again. The primary disables in its own corner, as state 1 does; the mono note carries the line. The body keeps whatever it held.

Never near the reading. The bracket, findings, climb and lean are never limited, so the line is never in the banner and Analyze / Re-analyze never disable for it. Re-analyze on a used allowance still reads the bracket; only the synopsis stays stale.

The time is a slot: sub-project 6 sets the reset. 00:00 UTC here is a fixture.
