Addendum · per-printing art selection · feat/printings-and-sets

You own four Forests. One of them is the one you like.

An addendum to the shipped card detail modal. Today the modal shows whichever printing the resolver picked and never admits there are others. This adds one thing: when you own more than one printing of a card, you can see them all and pin the one that represents it. 2,368 of your 2,470 cards have exactly one printing — for those, nothing on the screen changes at all. Every state below leads with the phone (392px), desktop (1060px) beside it.

Where it lives
A second view of the same modal, not a panel wedged into the 320px art column. One composition works at both widths.
Entry point
The printing caption becomes the trigger — and only at two or more. At one it stays plain text.
Chosen vs default
Solid brass ring + corner check + Your pick. The default gets a dashed grey ring + Default. Ring style, badge shape and words — never colour alone.
Overflow
Past {{ overflowThreshold }} entries the grid grows a SearchField, finish chips and set groups. 54 Forests, newest set first.
Finish
Foil is shown, not chosen. One entry per printing, quantity reads ×3 · 1 foil.
Mobile art
The entry is a property row with a 40px thumbnail — it reads the same whether or not the mobile modal ever gets an art header.

Chosen and focused are deliberately different rings — the pick hugs the art at +3px, focus floats clear of it behind a 2px dark gap. A card can be both at once and still read as both.
Hover is 1px solid #4A4033 at +3px and never brass; the pointer's position must not look like a commitment.
Badges sit on a rgba(10,8,6,.72) plate so the glyph clears AA over any art. The brass badge is #14110E on #C9A24B ≈ 9.4:1.
Why a second view, not a panel
The desktop art column is a fixed 320px and the mobile modal has no art column at all, so any panel that lives beside the art has to be designed twice and cannot hold 54 thumbnails at either size. Instead the modal turns over: the body is replaced by the chooser, with ‹ Back to Cyclonic Rift where the art used to be. Choosing art is a browsing task; it earns the whole 820px. One component, one grid, two widths — and on phone it is exactly the push-view players already know from the tab bar.
Roles & keyboard
button[aria-expanded][aria-controls] div[role=radiogroup][aria-label="Printings you own"] button[role=radio][aria-checked] span.sr-only "shown by default"
Radiogroup, not listbox — exactly one printing represents the card, and the resolver default means one radio is always effectively on. Arrow keys move between tiles and select as they go (single-select radio semantics); Tab leaves the group.
Esc returns to the card view, not out of the modal — one Esc per layer. The second Esc closes the modal.
Picking writes to the modal's existing live region: "Pinned Return to Ravnica number 71."
Tiles are 110px wide minimum on phone — 110×154, far past the 44px floor.

What changed here
Desktop: a caption appeared under the art — two lines of dim text, no border, no chevron, no count. That is the whole diff on 96% of cards, and it earns its place by naming the printing you're looking at, which the modal never did.
Phone: the Set cell is promoted out of the 2×2 grid into a printing row with a 40×56 thumbnail, and the grid drops to Rarity + Identity. Nothing is duplicated and nothing is lost — quantity moves into the row's mono line.
The shipped card-modal.tsx hides the art panel under md. The row is drawn to work either way: if the art header stays, the thumbnail is a redundancy you can drop; if it never arrives, that thumbnail is the only art on the phone screen. See gap 1.

The default is stated, not implied
Before you've picked anything, one tile is still the one you've been looking at. Leaving it unmarked would make the modal's art look arbitrary; marking it brass would claim you'd chosen it. So it gets the dashed ring, the hollow ◇ and the word Default — present, explained, provisional.
The subtitle says why that one: we show the newest one unless you pick. A player who agrees with the resolver never has to touch this screen again.
Ordering matches the set filter panel: release date, newest first, ties A→Z. Same surface, same rule, so the sets in this grid appear in the order the filter panel taught.

54 Forests is the real ceiling
Basics are the only cards where this gets big, and it gets big honestly: a player who has drafted for a decade owns a Forest from nearly every set. The grid stays a grid — you are recognising art, not reading a table — but at {{ overflowThreshold }}+ it gains three things: the SearchField primitive, a finish chip row in the shipped chip idiom, and set group headers so scrolling has landmarks.
No virtualisation: 54 tiles is nothing, and the real worst case across Magic's basics is under 200. If a card ever exceeds that the grouping already caps how much renders above the fold.
Search matches sets, not cards
Every entry has the same card name, so a name search is useless here. The field matches set name, set code and collector number — the three things a player actually says out loud: "the Kaldheim one", "blb", "282". Same substring rules and same no-highlight decision as the set filter panel.

Foil is shown, not chosen
Granularity is per printing, and finish is not a printing — so one tile, and the quantity carries the split: ×3 · 1 foil. All-foil reads ×2 foil, never ×2 · 2 foil. The art gets a faint diagonal sheen so a foil-only entry doesn't look like a data error; the sheen is decoration and carries no meaning that the text doesn't.
No collector number
Promos, Secret Lair drops and some older exports have none. The caption says no number in the same dim mono — never #—, #null, or a silently missing field. Two entries from the same numberless set stay two entries, distinguished by their art and their position in the set group; the accessible name falls back to no collector number.
Which entry is which
A printing's identity is set code + collector number. When the number is missing that key is incomplete, so the pin has to fall back to the Scryfall print id — otherwise a numberless Secret Lair Forest and its neighbour are indistinguishable and the pin lands on the wrong art after the next replace. Flagged as gap 4; it is the one place this design depends on data it can't see.
Replace is destructive by design. If a pinned printing is no longer in the new export, the pin is dropped silently and the resolver default returns — no warning banner on the review screen. You didn't lose a preference; you sold a card.
#101 · the three filter-panel calls, ratified — same surface, same round
Read this before treating the below as a ratification. #101's text isn't in this project, so I can't see which three decisions engineering actually made. What follows ratifies the three open questions the filter-panel handoff itself flagged (its gaps 3, 4 and 5) — the only three that needed a call. If #101 is about different decisions, this section is void and I'll redo it against the real list.
Ratified
The sheet's search field goes to 16px
Not maximum-scale=1. Killing pinch-zoom app-wide to save two pixels in one control fails WCAG 1.4.4 and punishes exactly the players who need it. The field is 16px on mobile, 14px on desktop; the sheet absorbs the 4px of extra height by dropping its max-height to 76vh — half a row, and the half row was already the scroll cue. Same 16px floor applies to this picker's search field, drawn in state 4.
Ratified
Set counts ignore the text search
Confirming what was drawn. The count answers "how much of this set is in play right now", and a count that changes on every keystroke is unreadable while you type — you'd watch every number tick down as you spelled a card name. Filters are stable, discrete constraints; free text isn't. Counts respect the filter chips only. The result count above the list already tells you what the text search did.
Ratified
Undated sets sort last, A→Z
Confirming the assumption, and now it matters twice: this picker's set groups use the same order. Promos and Secret Lair drops with no usable release date collect at the bottom, alphabetically — deterministic, and it keeps the top of both lists full of the sets a player actually recognises. Unstable at the foot of state 4's grid is that rule in action.
