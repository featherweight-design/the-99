Open with Hugh · how we know a player installed

Recommendation: A, a server flag. The installed app stamps installedAt on its first signed-in open, and the header button and its tour stop stay away in every browser session of that account. B (no flag) costs nothing, but an installed player keeps seeing the button in every Safari tab a friend's link opens, and invites and spare requests arrive that way from Messages.

Calls

  1. The header button is the ask; the tour points at it. R1's checklist row is gone, so there's one control for one action. The stop explains the button the way the other stops explain the nav. I'd ruled out a tour step before because installing sends the player out to Share mid-tour. As the last stop, the tour is already over when they go.
  2. Last, after What's new, on phones only. The stop is added when the run starts if the header button draws then. That's decided once, like the Credits stop. The kicker and diamonds count it (8 with Credits, 7 without), and step 1's foot reads one stop more (G3).
  3. Lit as a slot. The cutout covers the whole shipped slot, Install and its ✕ (5px room, 14 corner), so the ✕ the foot mentions is visible. The card docks above the tab bar as every phone stop does.
  4. The lit button can be selected on this stop. A press there ends the tour (stamped as finished, like Finish) and does the button's own press: the sheet on iPhone, prompt() on Android. Finish just closes the tour, and the button stays. The tour's ✕ skips as shipped.
  5. R1c · a fallback row for players who skip the tour. It shows only when the tour ended before the Install stop (skipped with ✕, or the stop never came because the button didn't draw at the start but does now). It's R1's checklist row (Fallback board). It's retired for good once the player selects it or the header button, or taps its ✕. The header button steps aside while it's on screen. A player who saw the stop never gets it, so nobody is asked twice.
  6. No new dismissal. The button keeps its shipped rules: its ✕ means quiet for 30 days, and a second ✕ retires it. The stop never shows again, because the tour runs once (and on a replay only if the button draws).
  7. Copy by browser. Only Safari's body mentions alerts. The sheet is shipped and unchanged.
  8. How we know they installed: option A, a server flag (recommended, yours to call). The installed app stamps installedAt on its first signed-in open, and the header button (so the stop too) stays away in every browser session of that account. Under B, an installed player still sees the button in every Safari tab a friend's link opens. The first launch draws nothing.
  9. No About entry (the brief's default). If About's tour entry counts stops, it says one more where the stop can show (Hugh's call at the next About batch).

Gaps for engineering

  • G1 · installedAt (option A only). A nullable timestamp on user_prefs, written once by the installed app's first signed-in open (isStandalone()), idempotent. The header slot reads it from the shell and draws nothing when it's set.
  • G2 · The stop. INSTALL in tour-steps.ts (target tour:install, registered by InstallSlot; kind slot), appended by withInstallStop when the slot's target exists at the run's start at 390. On this stop only, the cutout passes presses to the slot (lift the slot above the scrim, or give the scrim a hole). A press ends the tour with onEnd(false) and then runs the slot's onPress.
  • G3 · Counts. Step 1's foot gains footSeven/footEight variants for the stop. The diamonds and kicker come from the step list as shipped.
  • G4 · iOS keeps the installed app's sign-in separate from Safari, so the player signs in once more on the first launch. Hugh's call: should the sheet say so? It's left out.
  • G6 · The fallback's trigger. Reaching the Install stop writes a local the99-install-row = seen. The row draws when the tour is stamped done, the slot would draw, and the key is neither seen nor retired. Selecting the row or the header button, or the row's ✕, writes retired. The row's ✕ also calls dismissOnce().
  • G5 · The header's quick-return. The stop scrolls the page to the top before lighting, so the header is fully in view.
