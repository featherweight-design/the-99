The 99 · Foil treatment · R2 · large views · 2026-10-15

The same film, larger and calmer. The card tilts a little toward you.

R2 carries R1’s film into card details, the zoom, the hover preview and the phone peek. On a large face the film is a little softer and wider. Every card in details and the zoom now tilts up to 4° toward your pointer (hover on desktop, press and hold then move on a phone), with a soft light following; on a foil card the film slides with it. The face itself is drawn exactly as today and never waits. Theme drawn: Kaldheim; the others are on each surface board.

The brief’s nine questions, in its order (§Open)
  1. 1Intensity at sizeR1’s film, at 80% strength and spread one and a half times wider. Same stops and colours, so a tile and its details read as one material. The wider spread keeps a 264 to 372px face from reading as stripes, and the lower strength keeps pale art from washing out.
  2. 2Motion at sizeThe film follows the tilt: it slides toward the pointer or finger, up to a quarter of the card’s width each way, and a soft light follows with it. Keyboard focus plays R1’s one 640ms sweep instead. Nothing loops.
  3. 3Tilt (Hugh, 2026-10-15: yes, subtle)Every card in details and the zoom tilts up to 4° toward where you point, the edge under the pointer dipping away, with a soft light following. On desktop it is hover; on a foil card the film moves with it. During a flip the tilt eases flat and waits, then resumes on the next move, so the two never fight.
  4. 4The phonePress and hold the card, then move your finger: it tilts the same way. A drag on the card already pages or moves the sheet, so the tilt waits for a 300ms hold inside the 10px swipe slop, then the swipe stands down. In the zoom, which has no swipe, a press and move tilts at once, and a tap still closes. Plus R1’s one band when a card lands. Device tilt stays out (permission prompt).
  5. 5Arrival on a background faceThe face never waits; only the film does. One preloaded Image marks the FILM span (the arming ArtLayer already uses). Cached art, which covers most opens, is marked done and the film is there at once. A cold open fades the film in over 300ms when the bytes land.
  6. 6Precons in detailsDetails keeps the card’s own resolution. Showing the box’s printing changes what details names, which is more than a cosmetic round should move. If you own the Collector’s Edition, your MSC copies resolve and carry the film anyway.
  7. 7The peek and the hover previewBoth get R1’s tile film, still, with no motion. The peek is mid-size and partly off screen; the preview already moves with the pointer, so a moving film on it is noise.
  8. 8The flipThe film rides both faces through the turn. Each face carries its own film and hides its own back, so the film turns with the card stock and the back is foil the moment it shows.
  9. 9A mixed holding in detailsNo film, the same rule as tiles: every owned copy of the shown printing is foil, or nothing. The picker’s finish filter is a way of finding a printing, not a statement about the face.

The locks, and how each is met
Only real copies, only over that printing’s own artFilm only when every owned copy of the SHOWN printing is foil (or etched) and the face is that printing’s own image. Representative or oracle-level art, unowned cards and suggestions: never.
No new image downloadsGradients only. The film’s arrival mark reuses the face’s own URL, which the browser already fetches for the face.
The face never waits for the filmThe face stays a CSS background drawn at once. Only the film span carries an arrival mark.
Reduced motion is staticThe tilt, the light, the follow, the sweeps and the fade all sit under no-preference. The film still draws, centred.
Reduced transparency and forced coloursR1’s rules cover every [data-foil]: a 2px --fg-muted ring, and no film. The light is dropped under both; the tilt stays.
No change to what details saysNo strings. The finish line, the picker captions and the zoom caption are untouched.
No per-frame JavaScriptTwo custom properties per pointermove on one element; a CSS transition does the rest. A 300ms hold timer on the phone. Nothing runs while idle.

The CSS, proposed (README §R2 · The CSS)
/* Foil, large views (R2). A large film is any [data-foil] with data-foil-size="large": the
   details face(s) and the zoom card. The peek, the neighbour plate and the hover preview keep R1's
   tile film. R1's reduced-transparency and forced-colors rules already cover every [data-foil]. */
[data-foil-size="large"]::before { inset: 0 -25%; opacity: .8; }

/* A background face has no <img> to wait on, so the FILM carries its own arrival mark (armArtArrival
   on a preloaded Image of the face's URL). The face itself is never held. */
[data-foil][data-arrival="pending"], [data-foil][data-arrival="failed"] { opacity: 0; }
@media (prefers-reduced-motion: no-preference) {
  [data-foil][data-arrival="in"] { animation: art-in var(--motion-fade) var(--motion-ease); }
}

/* The tilt, on every card in details and the zoom. The host is a box OUTSIDE the one that turns for a
   flip (desktop art box, phone card, a wrapper round card-zoom-card). JS writes --tilt-x / --tilt-y
   (0..1) and data-tilting while a fine pointer hovers, or after a phone hold; data-turning while a
   flip runs. */
@media (prefers-reduced-motion: no-preference) {
  [data-tilt] {
    transform: perspective(1400px)
      rotateX(calc((.5 - var(--tilt-y, .5)) * 8deg))
      rotateY(calc((var(--tilt-x, .5) - .5) * 8deg));
    transition: transform var(--motion-duration) var(--motion-ease), box-shadow var(--motion-quick) var(--motion-ease);
  }
  [data-tilt][data-tilting] { transition-duration: var(--motion-quick); }
  [data-tilt][data-turning] { --tilt-x: .5; --tilt-y: .5; }

  /* The light: every card, only while tilting. */
  [data-tilt] [data-glare] {
    position: absolute; inset: 0; border-radius: inherit; pointer-events: none; opacity: 0;
    transition: opacity var(--motion-quick) var(--motion-ease);
    background: radial-gradient(circle at calc(var(--tilt-x, .5) * 100%) calc(var(--tilt-y, .5) * 100%),
      rgb(255 255 255 / .16), rgb(255 255 255 / 0) 55%);
  }
  [data-tilt][data-tilting] [data-glare] { opacity: 1; }

  /* A foil film rides the same vars. */
  [data-foil-size="large"]::before {
    transform: translateX(calc((var(--tilt-x, .5) - .5) * 33.333%));
    transition: transform var(--motion-duration) var(--motion-ease);
  }
  [data-tilting] [data-foil-size="large"]::before { transition-duration: var(--motion-quick); }
}
@media (prefers-reduced-transparency: reduce), (forced-colors: active) { [data-glare] { display: none; } }

/* Desktop: R1's band plays on keyboard focus only here; hover has the tilt. */
@media (hover: hover) and (pointer: fine) and (prefers-reduced-motion: no-preference) {
  :is(a, button):hover:not(:focus-visible) [data-foil-size="large"]::after { animation: none; }
}

/* Phone: one band when a card lands (the element mounts), after the card's own entry. */
@media (hover: none) and (prefers-reduced-motion: no-preference) {
  [data-foil][data-foil-size="large"]::after {
    content: ""; position: absolute; inset: 0; border-radius: inherit;
    background: linear-gradient(105deg, rgb(255 255 255 / 0) 30%, rgb(255 255 255 / .42) 50%, rgb(255 255 255 / 0) 70%);
    animation: foil-sweep calc(var(--motion-duration) * 2) var(--motion-ease) var(--motion-duration) both;
  }
  [data-tilt][data-tilting] { box-shadow: 0 34px 70px rgb(0 0 0 / .7); }
}

/* The peek's art is an ArtLayer div, not an <img>: R1's hold reads the mark on any sibling. */
[data-arrival="pending"] ~ [data-foil], [data-arrival="failed"] ~ [data-foil] { opacity: 0; }
