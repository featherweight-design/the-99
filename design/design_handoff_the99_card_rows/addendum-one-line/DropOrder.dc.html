D1 · The drop order, per view

What folds first, as the row narrows

The row reads its own column’s width, not the window’s, so the two-column grid, a narrow window and a future side panel all get the same answer. Three tiers: wide (a column of 480px or more: 1300 is 582px), middle (360 to 479px: 900 is 382px, 1024 is 444px) and tight (under 360px: a window of about 770 to 860px). Every row below is the same markup at the width its label names; only the width changes. The name is the one thing that shrinks between steps, down to an ellipsis.

D2 · Reading what folded

The fold is never a dead end

+N is a mark, not a control. It is bare mono in the mark ink, like ×N, and adds no hit box. With a fine pointer it opens the shipped fact tooltip (400ms in, out at once) listing what it holds. A press anywhere on the row opens card details as today, where every fact is written out. Each folded mark keeps its name for a screen reader. A cut name is recovered by the shipped hover preview: resting on the row for 240ms shows the card itself at 252×352, whole name included, so the row adds no second popup over the same hover.
