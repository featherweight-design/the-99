A visible Use on every phone result

When an import line can't be matched, its row opens a search (state 16). On a phone the first result, the one most likely to be right, showed only a bare ↵, which doesn't read as a button. Same flaw as the Add panel's quick-add rows, same fix. Every frame is the shipped expander rendered with the shipped CSS (Amonkhet theme) under the shipped deck page capture; the right-hand frame has this addendum's change applied.

Design calls

Every phone result draws the ghost Use, the first one included. The shipped ghost the other rows already have: 96 × 40, transparent, 1px --border-strong, radius 7, --accent-text 13/600, “Use this”. The bare ↵ is gone.
The ghost is a picture of the option's press, not its own target. Unlike the Add panel's row, this whole row is one listbox option, and it already acts when selected: a tap anywhere on it uses that card (the shipped onClick on the li). The row is 63 tall at 390, so the tap target is the full row, well over 44. Nothing inside the row opens card details, so there is no second target to keep apart.
No button inside the option. A real button in a role="option" is a nested interactive control, which a listbox doesn't allow, and a screen reader would stop on it as a second item. The ghost stays aria-hidden, as the shipped ghost on the other rows already is. What a screen reader hears doesn't change.
The active row is marked by its own edge, as shipped. Row 1 keeps its --accent border; its Use looks like every other row's, so the most likely card is as plainly usable as the rest.
Pressed. A finger down anywhere on the row (:active on the option, group-active on the ghost) gives the ghost the --elevated fill and the --accent border, the same press look as the Add panel's ghost. No new token.
Pending has no look of its own. Selecting Use drops the line from the list in the same step (the shipped optimistic resolve), so the expander closes at once, the card joins the deck and the group's note says That’s Aang, Swift Savior. 97 built now. The shipped 0.5 dim on pending never paints. Drawn in States, S4.
Desktop is unchanged. The active row keeps ↵ use this where a keyboard is likely: md and up with a fine pointer. The desktop render is byte-identical to main (Desktop board).
A touch tablet gets Use too. At md with a coarse pointer the active row draws the ghost “Use this card” like the other rows, and the visible keyboard hint goes back to screen-reader only. The ghost keeps its shipped md size; the target is the 60-tall row, over the tablet's 36.

Screen readers, ↵ and copy

Screen readers: unchanged. The field stays the combobox, aria-activedescendant points at the active option, each option keeps its aria-label (name, type, colors, owned) and aria-selected. Selecting an option (VoiceOver double-tap) fires the same onClick and uses that card.
The keyboard hint is still the field's description. It was already screen-reader only on phones. On a touch tablet it now stays screen-reader only instead of showing; it still describes the field there.
Does ↵ still appear on phones? No. The active row's bare ↵ was the only one this list drew on a phone. The phone keyboard's return still uses the top match, as shipped; the Use on that row now says it.
Copy: no new strings. useShort “Use this” on every phone row, use “Use this card” at md, activeRowHint “↵ use this” on desktop's active row only. All in deckImportCopy.resolve.
