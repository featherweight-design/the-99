R1Item 6b · card details from quick-add · #412 §2

Quick-add’s rows open card details from the name, like every other card row

Every named card row in the app opens the shared card detail from its name; quick-add’s can’t, because each row is an option in a listbox and a button can’t live inside one. Recommended (A): make the popup a grid, which a combobox may own instead of a listbox. Each row becomes two cells: the thumbnail and name (opens card details) and Add. Nothing new is drawn on the row: Add is the shipped Add, the name gets the shipped name trigger’s underline on hover. ↵ still adds the top match, so typing a name and pressing Enter works as today. B: quick-add offers no details, ruled on purpose: it is a name-entry tool, and the card is one press away once it lands in the list. Your call.

Once added, the card’s decklist row opens details as every row does.

Why A

  • Every other named card row opens details from its name (#405, #407). The row already shows ownership, availability and the card note, but not the text or the price.
  • A grid is the combobox pattern built for rows with more than one action, so the accessibility tree describes it honestly.
  • Nothing changes for the common path: type, ↵.

A, for engineering

  • role="grid" on the popup, a row per result with two gridcells; focus stays in the field via aria-activedescendant on the active cell.
  • ↑↓ move rows (the cell column is kept); →/← switch cells; ↵ acts on the active cell; typing resets to the Add cell of row 1.
  • The name cell is CardDetailTrigger’s open path without a nested button; aria: View details for Swan Song (shipped triggerAria).
  • Hint copy for /copy-review: → details, ← back to Add, ↵ opens details.

Either way

  • No modifier key, long-press or open-on-focus: none can be found by looking.
  • In-deck rows (✓ In deck) keep the name cell in A, so you can still read a card you already have.
