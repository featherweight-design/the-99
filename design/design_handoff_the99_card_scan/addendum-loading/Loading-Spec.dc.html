Addendum · card scanning · the scanner’s first open · the calls

Rules, timing and copy

L1 · Getting the scanner readyOpen to the last model byte. The bar counts bytes. About 8s on a phone.
L2 · Almost readyRuntime and warm-up. 0.2–2s.
L3 · Show a card to the cameraThe shipped looking panel, and reading starts.

1 · A real bar, not a spinner

The two model files (3.2 MB detector, 14.8 MB embedder) are counted together against their total, so the bar moves once, from start to full. The runtime can’t be measured, so it isn’t counted. If it is still loading when the last byte lands, L2 covers it along with the warm-up.

If the server sends no file size, the bar runs as L4’s indeterminate bar, with L1’s words and no figures.

2 · In the panel, over a live camera

The loading state is the shipped result panel (phone: above the tray; desktop: under the feed), with new words. There’s no scrim, overlay or extra screen. The camera starts as shipped, so the player can frame a card while it loads. ✕/Stop, Auto/Normal and the light all work, and a mode chosen now is the one the scanner reads with.

No outline is drawn while loading, because nothing is reading yet.

3 · The hand-off

When the first frame can be read, the panel turns into the shipped looking panel in place: a 150ms cross-fade of its contents (none with reduced motion), with no “ready” message, toast or sound. From then on the scanner works exactly as shipped.

4 · A cached reopen shows it, quietly

About 3s is too long to show “Show a card” when nothing can read. If the scanner isn’t ready 400ms after it opens, it shows Starting the scanner with an indeterminate bar above the shipped mode line. That way the hand-off changes only the heading. There are no figures and no first-time line, because nothing downloads.

StateShown whenEnds when
L1 Getting the scanner readyThe scanner opens and a model file isn’t in Cache Storage (or fails its hash check). If one model is cached, the bar and figures count only the one still downloading.The last model byte lands → L2. ✕ or Stop abandons it.
L2 Almost readyEvery model byte has landed, and the runtime or warm-up isn’t done.The first frame can be read → L3.
L4 Starting the scannerBoth models are cached at open, and the scanner still can’t read 400ms later.The first frame can be read → L3.
L3 Show a cardShipped, unchanged (D7), once the scanner can read.As shipped.

Closing abandons it. ✕ or Stop closes at once, with no confirm, as today. Nothing half-downloaded is kept, so the next open starts L1 from 0, and the copy doesn’t promise to resume. Unchanged: going offline mid-download shows the shipped offline notice, and a load that fails is the shipped “couldn’t start” notice. A turn across the 768px line keeps the state and its figures.

Accessibility

The bar is a progressbar with aria-valuenow on L1, and without it on L2 and L4. The panel’s existing polite live region announces only its heading changes (Getting the scanner ready, Almost ready, Show a card to the camera), never each MB. Focus stays on ✕ (Stop on desktop) as shipped.
