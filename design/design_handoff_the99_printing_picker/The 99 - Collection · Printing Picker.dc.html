Placement redrawn inline

You own four Forests. One of them is the one you like.

An addendum to the shipped card detail modal. When you own more than one printing of a card, an inline region inside the card view shows them all and lets you pin the one that represents it. The card never leaves the screen. 2,368 of your 2,470 cards have exactly one printing — for those, the only change is a caption naming the printing you're already looking at. Every state leads with the phone (392px), desktop (1060px) beside it.

What changed since R1
Placement redrawn. R1 replaced the card view with a second view. Locked decision 4 rejected modal modes — so the picker is now an inline region: docked under the art panel on desktop, an in-place expansion of the Set row on mobile. No back link, no view state, no Done button.
Mobile art settled. card-modal.tsx:180 is hidden md:flex — mobile has no art panel, and the Collection handoff's drawing of one is stale. R1's mobile art header is gone; the printing row's thumbnail is the only art on the phone.
A pin is kept, not dropped. R1 said a replace that loses the printing drops the pin. It doesn't — the pin goes dormant and reactivates if the card comes back. Drawn as state 6.
Scope corrected. The pin applies to collection surfaces only — grid, rows, this modal. Not decks; per-deck art is #42. Copy and state 3 both fixed.
Pin identity fixed the other way. (oracle_id, set_code, collector_number) is the key — zero duplicate groups in 100,601 rows. scryfall_id is nullable for bare Name,Qty imports, so R1's print-id plan would have denied the feature to those users. R1 gap 4 withdrawn.
Per-finish was rejected in decision 3, not 5 — corrected in the README and READINESS. The no number treatment stays: that case is the empty string, not null.
Where it lives
An inline region in the card view. Desktop: docked under the art panel, spanning the modal. Mobile: the Set row expands in place.
Entry point
The printing caption, a MetaField like every other property — and a control only at two or more.
Chosen vs default
Solid brass ring + corner check + Your pick. Default gets a dashed grey ring + hollow ◇ + Default. Never colour alone.
Overflow
Past {{ overflowThreshold }} entries the region gains a pinned SearchField, finish chips and sticky set headers. 54 Forests, newest set first.
Finish
Foil is shown, not chosen (decision 3). One entry per printing; quantity reads ×3 · 1 foil.
Commit
Picking commits immediately. No confirm, no Done — the only escape hatch is Use the default again.

Chosen and focused are deliberately different rings — the pick hugs the art at +3px, focus floats clear of it behind a 2px dark gap. A tile can be both at once and still read as both.
Hover is 1px solid #4A4033 at +3px and never brass; the pointer's position must not look like a commitment.
Badges sit on a rgba(10,8,6,.72) plate so the glyph clears AA over any art. The brass badge is #14110E on #C9A24B ≈ 9.4:1.
Why the region spans the modal
Locked decision 4 keeps this inside the card view, so the region docks under the art panel and spans the full modal width rather than staying inside the 320px column. That column has 264px of content after its 28px padding: two tiles per row, 27 rows of Forests, and no room for a search field and three chips. Spanning gives 5-up and keeps the art, name, oracle text and mana cost visible above the grid the whole time — which is the point of the lock.
The region is attached to the caption, not floating: the caption's bottom radius flattens and its border runs continuous into the region's. Padding rhythm matches the panel above — 28px vertical, 32px horizontal.
Roles & keyboard
button[aria-expanded][aria-controls] div#printings[role=radiogroup] button[role=radio][aria-checked] span.sr-only "shown by default"
Radiogroup, not listbox — exactly one printing represents the card, and the resolver default means one radio is always effectively on. Arrow keys move and select; Tab leaves the group.
Esc collapses the region, focus returns to the caption. A second Esc closes the modal — the modal's own handler, untouched.
Picking writes to the modal's existing live region. No second region is introduced.
Tiles are 110×154 minimum on phone; the collapsed printing row is 62px.

54 Forests is the real ceiling
Basics are the only cards where this gets big, and it gets big honestly: a decade of drafting means a Forest from nearly every set. It stays a grid because the task is recognising art, not reading a table. Past {{ overflowThreshold }} entries it gains the SearchField primitive, a finish chip row in chip-row.tsx's idiom, and set group headers so scrolling has landmarks.
No virtualisation. 54 tiles is nothing and the real worst case across Magic's basics is under 200.
The region scrolls, the card doesn't
This is the one place the inline placement has to work harder than a separate view would. The modal caps at 700px; the card block above is fixed and the region scrolls internally, with its search and chips pinned to the region's own header. You never lose the card, and you never scroll the whole modal to reach the grid.
Search matches set name, set code and collector number — never card name, since every entry shares it. Same substring rules and no-highlight decision as the filter panel. Empty state: Not in that set.

Foil is shown, not chosen (decision 3)
Granularity is per printing, and finish is not a printing — so one tile, and the quantity carries the split: ×3 · 1 foil. All-foil reads ×2 foil, never ×2 · 2 foil. The art gets a faint diagonal sheen so a foil-only entry doesn't look like a data error; the sheen is decoration and carries no meaning the text doesn't.
No collector number = empty string
The audit is right that no catalogue row is null — the case is the empty string, which arrives from bare Name,Qty imports and some older exports. The caption says no number in the same dim mono — never #—, never a silently missing field. Two such entries from one set stay two entries, told apart by art and position; the accessible name falls back to no collector number.
The pin key, corrected
R1 called for the Scryfall print id and flagged the composite key as unsafe. Both were wrong, in opposite directions: (oracle_id, set_code, collector_number) has zero duplicate groups across 100,601 rows, and collection_items.scryfall_id is nullable — pinning on it would deny the feature to exactly the players who imported a bare Name,Qty CSV.
The composite key is the pin. R1's gap 4 is withdrawn. The no number display treatment survives it unchanged — the empty string still needs saying out loud.

Your pick · not owned now
Dormant, not deleted
Dashed brass ring, outlined ✓ on a dark plate, greyed art, ×0. It is not selectable — aria-disabled, still in the radiogroup so the count and the reading order stay honest.
Kept, and it comes back
R1 said a replace that loses the printing drops the pin, and argued it as a feature. That's wrong against the lock: the pin is kept, and it reactivates if the card reappears in a later import. Nobody has to remember to re-pin after selling and re-buying, or after a bad export.
Which is why the region is the only place this is said. A dormant pin is not an error and doesn't earn a banner on the review screen — you find out the next time you look at the card, in the sentence that explains it.
Forget that pick is the only way to clear it, and it replaces Use the default again while dormant — the default is already what you're seeing, so offering it again would be a no-op.
