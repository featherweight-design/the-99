Coming back to Upgrade starts fresh, with the last run in reach

Hugh: “When running Precon Upgrade on a deck and coming back, it's still at the end state of the last run. Should we show a new Precon Upgrade screen instead to start the flow over with history accessible?” Yes. R2 (Hugh, 2026-11-18, with #2985): the result reuses Suggested changes' results, so adds and cuts are picked separately. Every frame is the shipped flow rendered with the shipped CSS (Low Sun) with the proposal patched in, over the precon page. Fixture as R2d: Prismari Artistry, Muddle at bracket 3, three kept runs. Copy is DRAFT for /copy-review.

The answer in one line

The press always opens on the start screen, which leads with Your last upgrade as a History row that says where it went; History stays in the title row; a run in flight still resumes, and a result that landed while you were away shows once.

Design's calls

1. Every return opens on the start screen

The press opens the intro whatever runs are kept, on the precon page and on the deck page's band. This retires today's rule (the newest result until a deck is started from it) and the after-History fresh flag. A first-time reader sees the intro exactly as shipped.

2. The start screen says what happened last

One block above the intro's lead: the mono kicker Your last upgrade (History's month-heading style) over History's own row for the newest kept run, at its stronger edge. Opening it is free and shows the result with ‹ Back to the start screen. Nothing else on the intro moves.

3. Past runs stay one press away

The title row's History link (shipped glyph) stays on the start screen and on a fresh result; it lists every run, as shipped. The start screen shows only the newest run, so there's one way to the list and one way to the last run.

4. Each row says where its run went

On the start screen and in History alike, the row's second line adds in Prismari Artistry (faint) once a deck was started from the run or its swaps were applied, or no deck yet in --accent-text while it's still unused. One row component, so the two lists always agree.

5. Applied: open it, start again if you like

Opened, the result keeps its press live, as History does today (a second deck from the same swaps is allowed), under a dashed note: Already in Prismari Artistry. Opening it again uses no credit. That note replaces History's A past upgrade, read-only, which was wrong because the press under it works. An unused run draws no note.

6. Not applied: still yours to apply

Yes, it stays reachable. The row says no deck yet; opened, Start the deck with these 14 swaps (precon page) or Apply these 14 swaps (deck page) is live, with Try another strategy after the lists. A run over an old list keeps the shipped listChanged line and its press off.

7. In progress: it resumes

Unchanged from A3. The press reads Upgrading toward Tokens · 0:05 and opens on the wait. No start screen while a run is in flight, because a second run can't start (inFlight).

8. Landed while away: shown once

The first open after a run lands shows its result, as A3 drew it (tracker, History link, pulse on the press). From then on it's Your last upgrade on the start screen. Seen means shown in the flow once, including a run that lands while the flow is open (G25).

9. The result is Suggested changes' results, reused (R2)

Hugh: a run is a list of adds and a list of cuts, not pairs to keep or drop. Under the run's head (title, the four facts as found, the commander pair) the swaps are drawn by the shipped SuggestedChangesRun: Additions and Cuts side by side on desktop and behind the Additions | Cuts switch on a phone, grouped by type or role, each row the shipped pick line (art, name, allocation marker and buy tag, reason, ✓ Picked / Pick), with the counts chip 13 of 14 chosen on each side. So a player can keep Sai, Master Thopterist and still cut Wizard's Staff for Counterspell.

10. Every card starts picked; the counts must match

A run is the plan the player paid for, so all 14 of each start ✓ Picked (the Suggested changes rule otherwise: up to N of each). The pinned bar is Suggested changes' own: +13 in −13 out · stays at 99 · bracket 2 → 3 · Upgraded, as asked. Uneven counts turn the press off with the shipped line 14 in, 13 out. Pick 1 more cut to apply, so the deck stays at 99. Dropping the pick that moved the bracket gives the shipped warning, and the press stays on. Picks are free and kept with the run (G28).

11. One press, in the bar

The bar's Apply place carries the flow's own press: Start the deck with these 13 swaps on the precon page (no confirm, as today) and Apply these 13 swaps on the deck page. The flow's foot is retired on the result; Try another strategy | 2 credits moves to the end of the lists. The You asked box is left out: the facts strip already says what the run was for.

12. The deck page gets the same start screen

Inside the band's flow, with A2c's intro line and Apply. A run already applied to another deck from this precon reads in Muddle Tokens and can still apply here.

Must-nots

  • Never reopen an old result on its own: the only result the press opens by itself is one the reader hasn't seen.
  • Never hide History on the start screen, and never add a second way to the list.
  • Never lock a past run: opening one is free, and its Start or Apply stays live while the list still fits.
  • Never block a new run because an unused one exists.
  • No status chip or stamp on the row: the words go on its existing mono line.
  • Never fork Suggested changes' results into an Upgrade copy: one component, one pick line, one bar.
  • Never start or apply uneven counts: the deck stays at 99.
