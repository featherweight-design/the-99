R3
Undo a removal · one link that always works

A restore cannot be refused, so nothing here refuses.

R2 modelled the restore on the pull flow, and that was the wrong parent. A pull is contended — it mutates another deck. A restore mutates only your own draft. Put back is an add, and in this app adds never refuse on claims — they price them. DeckAddRejection is three values, all about legality and identity, and addCardToDeck does not read availability at all.

Every gate is closed by construction. A row under Going out was in this deck's committed list, so it already passed legality and colour identity; and a commander is not a deck_cards row, so is-commander cannot fire either. The claim gates were never open in the first place.

So R3 deletes both refusal states and everything that existed to serve them: the claimed tag word, the commander row's empty-control variant, the 32px shared slot, and the Pull it → Pull demotion. Each of those had exactly one reason to exist, and the reason was a refused row. Two review rounds of alignment work on the price column goes with them — there is no second price to align to.

And R3 drops one more thing the audit did not ask for. R2 kept the row through the round trip because the refusal was drawn on it. With no refusal to draw, that argument retires too — so the restore is optimistic, and the in-flight state disappears rather than shrinking. See 3.

What is left: one always-succeeding link, one edited string, and the focus ruling. Diff against R2 · README · matrix · copy · READINESS.

The row leaves because the list is derived and the card is no longer in draftDiff.removes. Announced once: Necrotic Ooze is back in the deck. 101 cards, 16 going out. No animation on any figure. Focus goes to the group heading the row left — never the next row's control, which would put a live restore under a finger that just used one. The focus ruling is unchanged from R2.
Why there is no third state
R2's in-flight state existed for one reason: the refusal was drawn on the row, so the row had to outlive the round trip. That was #185's argument and R2 accepted it correctly. With no refusal to draw, the argument retires with the states it protected — and a disabled control held for a round trip on an action that cannot fail is exactly the ceremony R1 was criticised for.
So the restore is optimistic: the row leaves on tap. This is also the only reading consistent with #185, whose undo is not optimistic because its receipt is the thing that must survive to state a refusal. Same principle, opposite conclusion, because the two surfaces draw their outcome in opposite places — here the row leaving is the success, so there is nothing an optimistic apply can destroy.
Rule 4 is satisfied rather than departed from. R1 asked to break nothing unmounts mid-write and was refused. R3 does not need to: the write cannot be refused, so the unmount is not mid-write in any meaningful sense — there is no branch in which the row should come back. R1's requested ruling is withdrawn, not granted.
A transport failure is the one thing left, and it keeps its shipped treatment. If the request never reaches the server the row returns and MutationError says so — the app's existing behaviour for every optimistic write, not a state this feature designs. It is not a refusal: nothing was decided, and trying again is the whole remedy.

5 · The contract

one link, one edited string, one focus ruling
The whole inventory
Put backthe only new thing in R3
Borderless brass link, 12px 600 --accent, 34px tall, 44px square target at 390px, right-aligned in the Going out row's reserved action slot. Stops propagation. One variant. No guard, no tag, no disabled state. Calls addCardToDeck optimistically.
Not in R3 — nothing else at all
No new token, no new hex, no new tag word, no new vocabulary, no new motion class, no client state, no new storage, no new mutation, no modal, no toast, no confirm, no tooltip, no spinner, no disabled state, no guard branch — and no change to any shipped control, including Pull it, decklist-row.tsx and deck-card-undo-tile.tsx.
Notes for engineering
The restore is addCardToDeck, unwrapped — the same call #185's undo makes. No new mutation. R2's thin-wrapper escape hatch (“justified only if the guard vocabulary cannot name the holding deck”) is withdrawn: there is no holding deck to name.
No refusal enum, and no refusal handling. DeckAddRejection's three values are all closed by construction for a row under Going out. If one of them ever fires, it is a bug in the diff and not a state to draw.
Optimistic. The row leaves on tap. A transport failure returns it and MutationError states it — shipped behaviour, not a designed state.
Revalidation needs nothing new: revalidateClaims is already what addCardToDeck calls, per the audit.
Seniority is free. versions.ts:175 inherits since at commit by oracle id, so any restore inside a draft preserves it.
No new storage and no client state. Going out is draftDiff.removes.
One shipped string is edited: review.outNote, whose first clause is now false. R2's second edit is withdrawn — review.pull (the correct key; R2 twice called it pullCta) keeps Pull it unchanged.
Flagged, not edited: review.lede — “nothing here is a decision except the pulls” is now wrong by one, though less wrong than in R2: a restore is a decision but never a contended one. A ratification question.
One live-region message per settle: Necrotic Ooze is back in the deck. 101 cards, 16 going out. No motion anywhere.
Focus after a restore: the group heading the row left — never the next row's control. The one ruling carried intact through all three rounds, and the only one left.
Card-row parity
Name + one availability slot: held trivially. R3 adds no tag, no price and no second marker to any row.
Every addition names what it displaced: the Going out action slot was reserved and empty since R1.2. Nothing is displaced, and nothing is added to a decklist row.
No row's grid template changes, no row grows, none is two-line — at any width. With one label and no refusal variant, this now holds by construction rather than by measurement.
Words, never colour alone: the only new element is a text label. No hue is load-bearing anywhere in R3.
