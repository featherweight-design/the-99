Link-out · #330 · the second door

The strip is already the row the link-out asks for.

R3’s rule — the link-out lives in its container’s pinned bottom row, below the hairline that row already has — lands this pass without inventing anything. The price strip is the Shopping filter’s bottom element, it already sits inside its own bordered box under the pills, and it already renders exactly when there is something to buy. The link joins it as one new line at its bottom edge: no hairline, no box, no button, and nothing shipped inside the strip moves a pixel.

Same element as R3, same 14px, same five states, same string as the export dialog’s — because after decisions 2 and 3 the two doors point at the same list. This addendum adds one placement and zero primitives, tokens or strings.

Read LINKOUT-R4-README.md and LINKOUT-R4-READINESS.md. R3 is untouched and still the spec for the primitive, the export footer and the card modal. Colours resolve against amonkhet; no hex here is normative.

What this pass was told, rather than read

src/components/decks/price-strip.tsx and src/components/ui/external-link.tsx are not in this project — src/ holds one file, components/shell/nav.tsx. The strip below is drawn from the R3 price addendum canvas and its README, which are the design of record for it; the link is drawn from R3’s primitive spec. Two things need checking against the files once: the strip’s real padding and border radius, and whether external-link.tsx’s shipped underline colour is the 45% mix R3 specified.

If external-link.tsx already ships the R3 anatomy, this pass is a placement and a selector, not a component — which is the whole intent.

1a · R3’s rule is satisfied, not amended
“In its container’s pinned bottom row, below the hairline that row already has — and where no pinned row exists, it becomes one.” The strip is the bottom element of the filter container and it is already bounded on all four sides. There is no hairline to add and no row to invent: the link goes inside the box that is already the bottom of the container.
Which makes this the third placement under one rule, and the second where the answer was join the row that is already there. The rule has now been applied to a footer, a pinned nav row and a bordered strip without producing a divider. That is the test it was written to pass.
1b · Last, not first — the total is still the subject
Reading order in the strip stays figure → where it came from → what you can do about it. The link is the only underlined mark in the container and the only 14px one, so it is found; it is also the last thing said and the smallest weight after the figure, so it does not lead. A player who came to read a number reads a number.
The strip is still --fg-locked provenance and small mono type. Nothing gains a fill, a border, a radius or a hover background — the one new mark on the surface is an underline.

Two things the focus ring must clear here, that it did not in the footer
• The strip’s own border, 1px at --border, 15px from the link’s leading edge. The 2px offset ring sits well inside it and never touches, so the ring never reads as a second border on the box.
• The provenance line above it, 9px away. An outline takes no layout space, so it overlaps that gap by 2px rather than pushing the line — visible, and nothing moves on focus. This is the reason the gap is 9px and not 6px.
4a · A link, and the same one — you asked, so here is the argument
It navigates to another company in a new tab. That is a link’s job and a button’s lie: a button promises the app will do something, and the honest reading of this control is you are leaving. Everything downstream depends on it being an <a href> — middle-click, copy link, open in background, the ↗, rel="noopener", and the sr-only new-tab promise.
And a button would need a box. A box in this strip is a filled control under the filter pills, inside the GroupToggle container — the exact footprint the brief rules out, and the thing that turns a quiet aggregate into a CTA bar. The link keeps no box of its own, which is why it fits at all.
So: external-link.tsx as shipped, no variant, no size prop, no new token. If it takes href and children today, this pass adds no code to it.
4b · Two placements, one string, and no third convention
The strip’s link and the export dialog’s are the same string at the same href — linkOut.deck, now with two call sites. A player who finds both does not learn two things; they learn the app has one door and put it in two doorways.
these resolves correctly on both surfaces because both now render the same list — item 5. Had the two lists stayed divergent, one string across both would have been the bug rather than the fix.
4c · Tab order — the link is last in the strip
The strip holds no other focusable, so there is no order to negotiate and no shipped keyboard path to break. Coming from the pills, focus reaches the link after the filter it belongs to and before the first card row. DOM order matches reading order matches visual order — the one place in this ticket where all three agree for free.

5a · The divergence had a design cause, not just a code one
The export dialog composed its own list because it was a different surface with a different noun — a file to take away, not a filter to read. Once the buy action lives on the filter, the filter’s rows are the only defensible definition of these, and both doors take it.
One selector, three consumers: the rows, the strip’s total and denominator, and both hrefs. If a fourth appears, it takes the same one — and if the definition ever changes, it changes in one place and the total cannot drift from the basket again.
5b · Export keeps its link, retargeted
Unchanged in every visual respect — second footer row, left-aligned, quieter than Copy shopping list and .txt, R3’s drawings still the spec. Only the payload moves. Export is the take-this-elsewhere surface; it was never wrong there, it was only alone.
Two doors is not redundancy here: one is buy what I am looking at, the other is take this with me. They differ in intent and share a destination, which is the same relationship Copy shopping list and .txt already have.
