Amendment 6 · Keep all auto

Agreeing with the fill needs a button too.

The auto tag is provenance, and provenance expires: it is worth reading right after a fill, while the player is deciding whether the app's guesses are theirs, and it is wallpaper once they have decided. It never actually clears, because the affordance is missing. keep ✓ clears one row. The only bulk control is Clear all auto, which deletes the cards. A player who agrees with all forty picks is offered one button to throw them all away and none to accept them all.

Called: one more ghost button in the group toolbar, and nothing else. Keep all {n} beside Clear all auto · {n} — same geometry, same zero-state rule, no receipt strip, no confirm, no new visual language, and no change to what the tag means.

Locked, not reopened
No automatic expiry of the flag. schema.ts:183-185 holds the hard rule — “cleared by the keep control alone — re-sorting, regrouping, or opening the card detail must leave it set” — so that looking at a card cannot silently accept it. That rule stands, and this amendment does not widen it: it adds a second keep control, not a second way for the flag to clear on its own.

Why the phone wraps instead of shortening further
At 390px the shipped row already carries two filter pills, the sweep and two grouping pills. A second control in that row either truncates a label or pushes By role off the edge, and both cost more than a line of height. So the toolbar container gains flex-wrap and the auto cluster drops to its own row, full width, with two 44px targets side by side. The mobile keep label is Keep 40 — the shortest form that still names the act, and it leaves the shipped Clear auto · 40 unreworded.
The zero-state rule, reused whole
Absent at count === 0, never rendered disabled, and disabled only while its own write is in flight — ClearAutoButton's rule, verbatim, because the two controls read the same count and a toolbar where one is present and the other is not would say the count means two things. The keptNote keeps living outside both guards, which is state 7 of the shipped design table and the reason the wrapper span exists at all.
Rejected: a two-part split control
One segmented pill reading Keep all / Clear all puts an accept and a delete in one box, one 8px gap apart, on a phone. The mis-tap there is forty cards gone. Two separate buttons, drawn like every other toolbar control, is the answer the toolbar already gives.
2 Does Keep all get a receipt? no strip · one announcement ↑ contents

No. SweepReceipt exists because its rows are gone and the strip is the only route back. A keep takes nothing: every card is still in the deck, at the same quantity, in the same group. There is nothing for a receipt to hold open.

And an Undo would have to write auto = true across forty rows — the app re-marking as its own the cards the player has just declared theirs. That is the write schema.ts's comment is standing in front of. A reversal that re-claims is worse than no reversal, and the honest alternative is stated in the gaps rather than drawn.

Receipt 1 · forty tags leave at once
The list is the receipt. Forty auto plates disappear in one optimistic pass, the group clauses drop their · N auto tails, and the fill's provenance paragraph — gated on autoCount > 0 — leaves with them.
Receipt 2 · the button is not there any more
Both controls go absent at count === 0. A bulk action whose own control vanishes on completion has confirmed itself in the place the player was looking.
Receipt 3 · one line, spoken
Both of those are visual. The shell's existing live region — the one carrying sweptAnnounce and sweptRestoredAnnounce — takes one more message: “40 cards kept. 68 cards are yours now.” One announcement per settle, never one per row.

3 The toolbar after keptNote at n = every card ↑ contents

The note stays, unedited, and it is the only thing left. keptNote counts non-auto cards, so after a Keep all it reads 68 cards are yours now — a claim about the whole deck, which is exactly what just became true. It is not arithmetic the player has to check against anything; it is the sentence the action earned.

Everything else in the cluster leaves in the same pass: both buttons go absent, the fill's provenance paragraph unmounts, and every group clause drops its auto tail. That is the toolbar going quiet — one mono line at 11px in --fg-locked, desktop only, exactly as it ships. And because the note has always been the last survivor of the auto lifecycle, this amendment does not have to argue for it: it just stops being reached only by clicking forty times.

Engineering — five strings, one action, one edit each side
keep-all-auto · copy strings.ts — five keys into recommendationsCopy.auto, beside the sweep's. Nothing re-worded, nothing deleted.
actions.ts — keepAllAutoCards(deckId): one update deck_cards set auto = false where deck_id = ? and auto, returning the row count for the announcement. The identical write already ships one file over, at update-actions.ts:307, where applying a re-import clears auto on every card the list names — so this is the deck-wide case of a statement the codebase has already made, with the same for update lock and the same claimSurfaces revalidation as the sweep.
optimistic-deck.tsx — a keepAll edit: map(c => c.auto ? { ...c, auto: false } : c). Its own edit, not a loop of keep, for the reason the sweep's comment already gives about forty dispatches.
clear-auto.tsx — the new button inside the existing wrapper span, above the sweep. The file already owns this cluster and its zero-state rule.
group-toggle.tsx — two props (onKeepAllAuto, keepAllPending) threaded like onClearAuto, and flex-wrap on the container for 390px.
Tests — the write clears only auto rows and touches no quantity; absence at 0; both controls disabled during either flight; the announcement fires once.
Gaps
1. A mis-tapped Keep all cannot be undone. It costs no cards — it costs the sweep, and the player is back to removing rows one ✕ at a time.
2. The same words, Keep all {n}, now live in two copy modules: here, and in amendment 2's removal diff. Deliberate — the subjects differ — and a future reader will read it as a duplicate once.
3. The keptNote is desktop-only, so the phone's only receipt is spoken.
4. Nothing distinguishes “kept deliberately” from “kept in bulk” afterwards, by design: no column records it, and inventing one would be the provenance this amendment is retiring.
5. A fill that runs after a Keep all re-populates the tag, and the player meets the pair again. Correct, and unannounced.
Settled elsewhere, applied in this R1 — the hand-added marker is gone
