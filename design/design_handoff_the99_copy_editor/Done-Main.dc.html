Unsent edits on Done · copy editor addendum · R1

In a live test Hugh filled the tray, pressed Done, and nothing said the edits were still waiting; he expected Done to send them. This adds the one state the R1 boards don’t draw: Done with unsent edits. Drawn over the R1 Help me choose page with the mode off and three edits in the tray. W1 the notice right after Done, W2 later (notice closed or another page), W3 Open pull request pressed from the notice. Phone and Desktop boards sit to the right.

The three options, and the pick

A · Done asks: send, keep or discard

Not picked. Done is also how you use the page mid-batch (Q3: links don’t work while the mode is on), so a question would stop every hop between pages, the batch Q2 exists for. Discard beside Send is one wrong tap from losing the work.

B · Done sends

Not picked. Same hop problem, and worse: leaving a page to edit the next one would open a pull request with half the batch, and the submit route allows one a minute. Opening a PR is a send, it shouldn’t ride on a button that means “give me the page”.

C · Done leaves; the door shows a count

Half of it. The count keeps the edits visible later, but it is passive: at the moment Hugh pressed Done he was looking at the page, not the corner.

Pick · C, plus a notice at the moment of Done

Done leaves as today, never asks and never sends. When edits are waiting, a small notice says so right where the bar was, with Open pull request one press away; it doesn’t block the page. After it closes, the door keeps the count.
Calls

D1 · Done with edits waiting

  • The mode ends exactly as today: outlines off, the page given back, the page shows today’s text again (Q4 previews are mode-only), focus back on the door.
  • A notice opens where the tray sits (desktop: 360px, 84px above the bottom, right 24) or under the phone header (12px gutters, 8px below it). role=status, so it is announced once; it never takes focus.
  • Title 3 edits waiting, not sent with an accent dot, one line on where they are, then Review and Open pull request (primary), and ✕.
  • It doesn’t block or dim anything. It closes on ✕, Esc, either button, or the next page. Clicking the page behind it leaves it up.

D2 · The door carries the count

  • Desktop pill: pencil, Edit copy, staging dot, then a chip 3 edits waiting (accent text on 16% accent, 24px, radius 999).
  • Phone pencil: an accent count badge (18px, the number in --bg, 2px --bg ring) takes the top corner; the staging dot moves to the bottom corner, so staging still reads.
  • Label: Edit copy, 3 edits waiting. Shown whenever the tray holds unsent edits, on every page, from this browser’s storage, before the mode is ever turned on.
  • Pressing the door turns the mode on as today; the bar already reads 3 edits ›.

D3 · Sending from the notice

  • Open pull request opens the tray straight in C5 Submitting, mode still off: no outlines, the page stays usable behind the desktop panel. Submitted, Failed and Try again are C5 unchanged.
  • Review opens the tray (C4) the same way, mode off. Edit in a row opens the editor without a target, as reopening from the tray does today.
  • Closing the tray leaves the mode off. Once the PR opens the tray is empty, so the count goes away.

D4 · What stays as it is

  • Done with an empty tray: unchanged, no notice, no count.
  • Esc that ends the mode is Done: same notice.
  • Done while Submitting: unchanged (no notice; the edits are already going). A Failed tray still holds its edits, so they count as waiting.
  • The bar, the tray, C4 and C5 are as the README draws them.

For engineering

E · How it could work

  • The count can’t wait for the overlay chunk: the provider reads localStorage["the99.copyEdits"] itself (length only, no import of edits.ts, which pulls in the validator) on mount, on Done, and on the storage event for other tabs.
  • stop() gets the count at the moment of Done; edits > 0 and no submission in flight shows the notice. The overlay renders nothing while off, so the notice and an off-mode tray live outside its on gate (the overlay stays mounted after first load).
  • Notice: polite status, no focus move (focus still goes to the door, as today). Esc closes it before anything else.
  • Copy for src/lib/copy/copy-editor.ts: doorWaiting(n), doorLabel(n), waiting.title(n), waiting.body(n), waiting.review, waiting.send, waiting.close. Text in ADDENDUM-done-unsent.md and copy strings.ts.
