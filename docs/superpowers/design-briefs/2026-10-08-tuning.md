# Tuning: a deck-level hub

Design brief, 2026-10-08. A new hub that replaces an existing panel (Suggested changes) and
absorbs two tools that do not exist yet (Mana Balance, Proposed cuts) plus a new History surface.
It also relocates an existing component (the roles strip) and fixes a broken link on it. Source:
Hugh's discussion notes, `boards/tuning-discussion-2026-10-08.md` (kept outside the repo).

## The finding

Suggested changes ships today as one panel on the Analysis tab (`TuningPanel`,
`src/components/decks/tuning-panel.tsx`): a manifest of what a run reads, an action row, and a
results list of up to five swaps. It is the only tool on that tab. Two more are wanted — Mana
Balance and Proposed cuts — and a single panel does not scale to three tools plus their history.
Hugh's ruling (below) makes Tuning the hub all three live inside, and moves the roles strip
("Recommended Mix," `RoleCounterStrip`) back out of the Analysis tab to "Your deck," where it
lived before Round 0 moved it in (handoff `design_handoff_the99_deck_tuning`, Hugh's note on
`builder-shell.tsx:1467`: "Round 0 moves it here on purpose").

## The ruling (Hugh, 2026-10-08, decided)

- **Name: Tuning.** Tools: Suggested changes (exists), Mana Balance (new), Proposed cuts (new,
  offered only when the deck is over 100 cards), History (every past run of every tool).
- **One home plus contextual shortcuts** that open the same tool from where the problem shows:
  the decklist's own "over by N" state links to Proposed cuts; the roles strip's lands cell links
  to "Balance mana." Both land on the same tool, with the same History, as pressing the tool's own
  tile from the Tuning home.
- **Selecting a tool opens it. Navigating away resets the view to the landing.** Past results are
  not pinned open across a visit; they are reachable only through History.
- **The roles strip moves back to "Your deck,"** one place only — not both, as it drew briefly in
  an earlier round. Its "consider →" jump, broken today, needs fixing in the same move (Hugh
  pressed it and nothing happened, in the discussion that produced this brief).
- **Mana Balance and Proposed cuts are two tiers each**: a free, deterministic first pass with no
  model call, and an optional "Look deeper" pass (a model call, spends a credit) that treats the
  free pass's own checked facts as its grounding. Proposed cuts ships tier 1 only to start; tier 2
  is added only if the eval on real decks shows gaps tier 1 cannot close.
- **Mana Balance counts every source**, not basics alone: duals, utility lands, rocks (Talisman,
  Signets, Arcane Signet), dorks, land search. Suggestions can rebalance basics against each
  other, or trade basics for ramp ("drop 2 basics for Talisman of Unity"), and can name a missing
  staple the deck has no answer for (no Arcane Signet, say), sourced from `format_staples` and
  the commander's own most-played ramp, owned cards offered first.
- **Open, not yet decided: free-first vs. deep-by-default.** The free pass costs nothing and
  returns instantly; the deep pass costs a credit and is more confident, and some players will
  want it on every run. The orchestrator's lean, not yet a ruling: show the free result instantly
  with "Look deeper" offered at the top of it (one press, not a second trip), and consider a
  per-player "always look deeper" preference later. **Design: draw the default (free-first,
  Look deeper offered) and leave room for a preference toggle to be added without a second round;
  do not block this brief on resolving the open question.**

## What exists today (the record)

- **Suggested changes** (`TuningPanel`): a manifest (read-only disclosure of what a run reads:
  decklist, games, notes, description, collection, your limits — see the "manifest reads as
  checkboxes" ruling, `docs/superpowers/design-briefs/2026-09-28-tuning-manifest-affordance.md`,
  which still governs how a manifest row looks and ticks), an action row (Suggest / Stop), and up
  to five results with per-suggestion citations. Inputs include a free-form request box, a price
  cap, a set filter and "Only from my collection" (all per-deck, from H35,
  `docs/superpowers/design-briefs/2026-10-03-deck-description-and-tailored-suggestions.md`). A run
  is `deck_suggestion_runs` (`src/db/schema.ts`), one row per attempt, kept forever — this is
  already a run ledger, not a mutable "current result"; History is the first UI to read its past
  rows rather than only its newest.
- **The roles strip** (`RoleCounterStrip`, `src/components/decks/role-counter-strip.tsx`): five
  cells (ROLE_ORDER), each a role's count against the commander's recommended mix, with a
  "consider →" link on a short cell that has a Consider shelf for it. Today it is conditionally
  mounted: on "Your deck" when the Analysis tab is off (`builder-shell.tsx:1471`, `!analysisEnabled`),
  and inset inside the Analysis tab's panel when the tab is on (`builder-shell.tsx:1611`, passed
  `inset`). The ruling collapses this to one place, "Your deck," regardless of the Analysis tab.
- **Proposed cuts and Mana Balance do not exist.** No component, no route, no schema. "Over by N"
  as a decklist state and "Balance mana" as a roles-strip link are both new copy and new wiring.
- **`src/lib/tuning/`** (`limits.ts`, `prompt.ts`, `validate.ts`, `presentation.ts`,
  `src/lib/decks/tuning-read.ts`) is Suggested changes' own module: its prompt builder, its
  validator (nine `suggestionRules`, grounding and citation checks), its fixed numbers
  (`MAX_SUGGESTIONS = 5`, `TUNING_MODEL`, token ceilings), and its manifest-row derivation. None
  of it is tool-generic yet; Mana Balance and Proposed cuts need their own prompt/validate pairs
  (tier 2) and their own limits, sharing only what is genuinely shared (the model client, the
  allowance, the citation/quotable machinery for player text).
- **`accuracy-and-humility` is a standing product principle** (Hugh, 2026-10-07, prompted by
  Deckcheck's wrong claims about his HD Gishath deck): prefer verifiable facts over model
  assertion, validate card-rules claims against oracle text, hedge what cannot be checked, and
  never let a free tier 1 pass invent what it has not actually counted. This governs every tool
  in this hub, not only the ones with a model tier.

## Mana Balance (new)

**Tier 1 (free, deterministic, no model call).** Counts every mana source in the deck against
pip demand, curve-weighted (a 1-drop's pip counts more than a 6-drop's, since it needs to be
online sooner):
- Basics, duals and utility lands that produce colored mana.
- Rocks that produce colored mana: Talismans, Signets, the colored-identity Signets, Arcane
  Signet, and similar. Not every artifact that taps for mana is a "rock" the deck should keep —
  tier 1 only counts what it can verify produces the colors in question, from the card's own text
  or the catalog's recorded mana abilities, never from a guess at the card's name.
- Dorks (creatures that tap for mana) and land search (tutors/ramp that fetch a land) count as
  sources, weighted by how reliably they resolve (a dork that dies to removal is a source with a
  caveat tier 1 should not silently erase, even if it has no room to say so today).
- The output: which colors are under-served relative to their pip demand, and by how much.
- Suggestions: rebalance basics against each other (swap N Plains for N Islands); trade basics for
  ramp ("drop 2 basics for Talisman of Unity," when the deck's curve and color count justify a
  rock over raw lands); and name a missing staple the commander's bracket of decks usually runs
  and this one doesn't (sourced from `format_staples` and the commander's own most-played ramp,
  per `commander_support_cards`), owned copies offered first, a buy link after.
- Every suggestion carries the counted fact behind it (current count, target count, the pip math),
  shown rather than asserted — the accuracy-and-humility rule applied to a tool with no model in
  its free tier: there is nothing to hedge because nothing here is a claim the deck can't check.

**Tier 2 ("Look deeper," spends a credit).** Takes tier 1's counted facts as grounding and reasons
about synergy tier 1 cannot ("this deck wants untapped lands because X creature cares about
timing," "this rock is dead weight because the deck has no other artifact matters, consider the
land instead"). Any rules claim ("Y produces two colors") is checked against oracle text before
it reaches the result, same discipline Suggested changes' validator already runs.

## Proposed cuts (new, offered when the deck is over 100 cards)

**Tier 1 only, to start.** A deterministic shortlist of what to cut, ranked by:
- Commander inclusion rate (how rarely this card appears in decks under this commander, per
  `commander_support_cards` — a card far below the commander's typical inclusion rate is a
  stronger cut candidate than one near it).
- Roles over target (a role the roles strip already shows as over its recommended count is where
  a cut is least costly to the deck's balance).
- Curve (a card that crowds an already-heavy curve slot).
- Bracket flags (a card that pushes the deck's bracket where the player has not asked for that,
  via the same `card_bracket_flags` data the bracket system already reads).

Never cuts the commander or a locked card (`card_assignments`/locked-card convention, same rule
Suggested changes already enforces as a hard filter, not a model instruction). Each proposed cut
carries a checkable reason — the counted inclusion-rate figure, the role's over-target count, the
curve slot, or the named bracket flag — never a bare "cut this," and never an invented one.

**Tier 2 is not built in this brief's scope.** It is added only if the golden-deck eval (below)
shows tier 1's shortlist missing cuts a strategy-aware read would catch. If it ships, it reviews
tier 1's shortlist for fit with the deck's description/notes, the same grounding discipline as
Mana Balance's tier 2.

## Recommendation quality (applies to every tool, not new UI)

Two real failures motivate this, both from Hugh's HD Gishath read (project
`project_accuracy_and_humility_principle.md`): the Overview called Rhonas's Monument a
mono-green-only discount (it discounts any green creature spell) and called Marauding Raptor +
Polyraptor "value" when it is a mandatory loop that draws the game. Every tool in this hub ships
with:
- **Oracle-text verification** of any rules claim before it is shown, not after a complaint.
- **A mandatory-loop flag**, sourced from Commander Spellbook's own data
  (`spellbook_variants`/`isInfiniteOrGameEnding`, `docs: db:seed:combos`), so a suggestion never
  recommends keeping or adding a loop that ends the game as if it were ordinary value.
- **A golden-deck eval set**, starting with Hugh's own "HD - Gishath"
  (`904fdc61-e190-4ba5-8e34-2b18fa0584f2` on staging), scored on every prompt change the way
  `docs/superpowers/eval/metrics-tuning.md` already scores Suggested changes' prompt variants.
- **Hedged wording when a claim cannot be verified** — "may," named uncertainty — rather than a
  confident guess, and the tool asks the player only for what it cannot derive itself (it never
  asks "what colors does your deck need," which it can count).

None of this is new UI. It is a quality bar every tool's copy and validator answer to, and it
belongs beside the result, not as a separate screen: see "Citations and hedged claims" under
States, below.

## What this brief asks Design to draw

### 1. The Tuning hub (landing)

- **Entry point.** Where Tuning lives on the deck page — the brief assumes it replaces the
  Analysis tab's current Suggested-changes-only body, but Design decides whether "Tuning" is the
  tab's new name, a sub-area inside the existing Analysis tab, or its own tab. Whatever the
  answer, it is one landing, reachable from one place in the deck's own navigation, at both
  widths.
- **The four tiles**: Suggested changes, Mana Balance, Proposed cuts, History. Proposed cuts'
  tile is present but inert (or absent — Design's call) on a deck at or under 100 cards; draw
  both the "offered" and "not offered" states and whatever explains the second, briefly, if it is
  shown at all.
- **Selecting a tile opens that tool** in the same hub area (not a new route) — draw the
  transition and whether the other three tiles remain reachable (a tab-like switch within the
  hub) or the hub narrows to "this tool, with a way back."
- **Navigate-away resets to the landing.** Draw what counts as "navigate away" at the UI level —
  leaving the deck page certainly does; switching to another deck tab (Your deck, Your games) and
  back is the one that needs a stated answer, since the hub's own tool state must not survive it
  while the in-flight run itself (if one is running) still does (see "A run outlives the view,"
  below).

### 2. Suggested changes inside the hub

- Draws exactly as it does today (manifest, action row, five results, the four persisted
  controls from H35) but inside the hub's tool area rather than as the Analysis tab's whole body.
  Confirm nothing about its own states (ready/generating/results, the manifest's read-only
  checkbox-look) changes — this round moves its frame, not its insides.

### 3. Mana Balance (new, both tiers)

- **Free result.** The source breakdown (which colors are short, by how much, counting every
  source kind named above) and the suggestion list (rebalance / trade-for-ramp / missing-staple),
  each suggestion showing its counted fact. Draw how a "missing staple" suggestion differs visually
  from a "rebalance basics" one, since one names a specific card to add and the other names a
  swap between cards already in the deck.
- **"Look deeper."** One press, at the top of the free result (per the orchestrator's lean —
  Design may draw this differently if a strong reason emerges, but a second navigation to reach it
  is out). Draw the credit cost's visibility (does the player see "uses a credit" before pressing,
  the way Help me choose's own Look deeper already shows it?), the loading state, and the deeper
  result's relationship to the free one underneath it (replaces it, sits above it, or merges in —
  Design's call, consistent with how Help me choose already answers this for its own deeper read,
  `src/lib/intake/deeper-read.ts`).
- **Contextual entry**: the roles strip's lands cell gets a "Balance mana" link beside (or in
  place of) its existing "consider →," when the strip is short on a color the mana count can
  explain. Draw whether both links can appear on one cell or only one at a time.

### 4. Proposed cuts (new, tier 1 only)

- **The shortlist.** Each proposed cut with its one checkable reason (inclusion rate / role /
  curve / bracket flag) and a way to accept or dismiss each (does accepting commit the change
  immediately, stage it the way Suggested changes' own swaps are staged, or something else?).
  Draw the never-cut guarantee's visual language, if any (nothing to draw if the commander/locked
  cards simply never appear on the list).
- **Contextual entry**: the decklist's own "over by N" state (new copy: a deck at 101+ cards
  shows how far over, with a link into Proposed cuts). Draw where that state sits relative to the
  existing unresolved-count and coverage-strip language already on the decklist.

### 5. History (new)

- **Every past run of every tool**, one list. Draw how a History row distinguishes which tool it
  belongs to, whether it is a tier-1 or tier-2 (credit-spending) run, and its outcome (ok / refused
  / failed — the same outcome vocabulary `deck_suggestion_runs.status` already has for Suggested
  changes). Opening a History row shows that run's result read-only; it is the only way to see a
  past result once the view has reset to the landing.
- **Scale.** A deck can accumulate many runs across three tools over months. Draw whether History
  is a flat reverse-chronological list, grouped by tool, or filterable — and what it shows when
  empty (a deck with no runs of anything yet).

### 6. The roles strip, moved and fixed

- **One home: "Your deck."** Draw it exactly as it ships today on that tab (it does not change
  visually) — the work here is removal from the Analysis/Tuning area, not a restyle. Confirm
  nothing about the strip's own states needs a second look now that it has only one caller.
- **The "consider →" fix.** Hugh pressed this link and nothing happened. The brief does not ask
  Design to diagnose the cause (that's an engineering read at implementation), but if the fix
  changes what the link looks like, is labeled, or does when a shelf doesn't exist for a role,
  draw that. Otherwise this is a non-visual fix Design does not need to re-draw.

### 7. States that apply across every tool

- **Ready / running / results / refused / failed**, matching the existing five-ish states
  `TuningPanel` already draws for Suggested changes (manifest, action row, Stop) — Mana Balance
  tier 1 has no "running" state worth drawing (it is instant and free), but its tier 2 does, and
  Proposed cuts tier 1 likely has a brief "running" state too (it still reads the deck and the
  catalog, just without a model call) — Design's call whether that is worth its own loading frame
  or renders as an instant free result like Mana Balance tier 1.
- **A run outlives the view.** A run already in flight when the player navigates to the landing
  (or away and back) is not lost — Suggested changes' own runs already survive a navigate-away
  today (the ledger row exists independent of the panel). Draw whether a running tool's state is
  visible from the landing (a tile showing "running…") or silent until the player reopens that
  tool or checks History.
- **Citations and hedged claims.** Every tier-2 (model) result inherits Suggested changes'
  existing citation pattern (`YOU SAID` / grounded quotes) — draw the same pattern for Mana
  Balance's and Proposed cuts' tier-2 results, and draw what a hedged claim looks like (e.g., "may
  still be live if the opponent plays around it") versus a counted fact, so the two read as
  different kinds of statement at a glance.

### 8. About entry

- **Not drawn in this round.** Per the standing rule (`AGENTS.md`, "A multi-round feature line
  batches its About entries at the end of the launch"): Tuning ships across several PRs (cost
  labeling and the roles-strip move first, then two tier-1 engines, then the hub UI, then the
  tier-2 passes — see the roadmap). The About entry and its `ABOUT_VERSION` bump are owed at the
  end of that whole line, describing Tuning as it finally works, not at any one PR along the way.
  Design still draws the entry eventually, on the per-entry artboard
  (`design/design_handoff_the99_about/`); this brief's roadmap names it as the launch's last task.
