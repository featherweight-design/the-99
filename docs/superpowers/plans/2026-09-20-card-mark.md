# Implementation plan — The card mark (Round 1)

**Handoff:** `design/design_handoff_the99_card_mark/` (R1) · **Verdict:** 🟡 Yellow,
`READINESS-r1-audit.md` · **Brief:** `docs/superpowers/design-briefs/2026-09-19-the-card-mark.md`

Three standing facts about a card — **Game Changer**, **mass land denial**, **extra turns** —
drawn wherever a card already appears. The handoff's engineering ledger is nine items; this plan
groups them into five PRs and folds in the audit's nine errata.

---

## The rules this build is held to

Carried from the verdict, and each one is a way this feature fails rather than a preference.

1. **The key ships in the same release as the marks.** A wordless mark is only legal here because
   it is glossed, and `MarkKey` is currently mounted on the deck surface alone — three call sites
   in `decklist.tsx`, nothing under `collection/`. **A PR that draws a mark on `/collection`
   without mounting the key there is the deck-status failure repeated.**
2. **Nothing may imply completeness.** Detection on two of the three facts is partial. No tick, no
   `clean`, no `no MLD`, no count of unmarked cards, and no sentence that reads as a clearance.
3. **No row or caption grows.** Every mount is additive into space that already exists.
4. **12px floor, and nothing is substituted below it.** No dot, no dash, no initial.
5. **No provenance anywhere.** Round 2 owns the detection sentences and their slot.
6. **Rarity is desktop-only on the collection tile and stays that way.** Guardrail 7 must not be
   read as licence to add it to the phone.
7. **The glow is a `filter: drop-shadow`** — never a `box-shadow`, plate, pulse or motion.
8. **Solid glyphs, with the turn-again arc's 2px stroke the one stated exception** (erratum 9). The
   rule is *no hairlines, no outline-only glyph*.

## PR 1 — the token, the component, and the browse payload

**Ledger 1, 2, 7b · errata 3, 4, 8 · this plan**

- `--fact: #8FA6BE` declared in **all six** theme blocks in `globals.css`, plus the `@theme`
  mapping beside its siblings if it is consumed as a utility. `pnpm check:tokens` fails by design
  on a token a component reads and no theme declares — that check is the gate here, and a silent
  unset custom property is exactly the hazard it exists for.
- **`CardFactMark`** — three inline SVGs on a shared viewBox, ink from `--fact`, size from the
  caller, glow via `filter`. Pure and client-safe. It renders nothing when the card carries no
  fact; **absence is the design and reserves no space.**
- **Tooltip** — a positioned element, `pointer: fine` only, 400ms in. No native `title`, no tap
  target, no focus ring. It states only what a *marked* card is.
- **Browse list payload widened** with the two joined flags (ledger 8). `game_changer` already
  rides every card row; the other two cost one join through `loadCardBracketFlags`. **The
  payload-ceiling arithmetic is done in this PR and recorded in its body** — the byte guard is
  the check that matters, and the delta is measured against a real collection rather than
  estimated.
- Corrections to the handoff's own artifacts, since they are what the next reader builds from:
  `CONTRAST-the-card-mark.md`'s floor becomes **6.31:1** (kaldheim `--elevated-hover`), and the
  mana pip joins the neighbour table with the colour-exclusivity claim replaced by *the only
  uncontained mark*.
- Tests: the three glyphs render, absence renders nothing, the floor substitutes nothing, and the
  tooltip is absent under `pointer: coarse`.

**Boundary:** no mount. Nothing on a row, a tile or a modal yet.

## PR 2 — the deck surfaces

**Ledger 3, 6, 7 · erratum 2**

- **`decklist-row.tsx`** — the mark inline after the count, both widths, `flex-none` in a name
  block that is already `flex-auto min-w-0` with ellipsis. **No change to `hasMetaLine`.**
- **`card-modal.tsx`** — one block, *In the bracket rules*, between the oracle text and
  `AvailabilityDetail`; `null` when the card carries no fact. Glyph plus name per line, **no
  provenance**.
- **`MarkKey` gains the three fact entries**, and the composition rule is settled here: **the
  three fact entries are unconditional on any surface that can draw a fact mark; `buy` and `proxy`
  stay conditional exactly as they ship.** The handoff asked for all five unconditionally; the
  component refuses an empty legend, and an unconditional buy entry prints `not owned` over rows
  the player owns — the falsehood that key's own ruling forbids. Unconditional fact entries
  deliver Design's stated reason verbatim: *a player scanning for Game Changers needs the entry to
  be there before they find one.*
- Tests: a marked row draws one mark and the key carries three entries with no marked card present;
  an owned-everything deck draws no `buy` entry.

## PR 3 — the collection surfaces

**Ledger 4, 5 · errata 1, 5, 6**

- **`rows-view.tsx`** — the mark after the name, before the `AvailabilityMarker`, both already
  inline in a `min-w-0` / `shrink-0` cell. One clause added to the row's `aria-label`.
- **`grid-view.tsx`** — the mark in the meta line after the chip; **`metaTrail` is unchanged, and
  rarity stays desktop-only.**
- **`CardTileCaption` gains a name-line slot** so `×N` can move off the meta line (erratum 6). The
  count is `aria-hidden` today, so **the accessible-name ordering is re-asserted after the move**
  rather than assumed.
- **`MarkKey` mounted on `/collection`, both views** (erratum 1). This is the PR rule 1 names, and
  it cannot slip to a follow-up.
- Tests: the tile's accessible name after the count moves, and the key present on both views.

## PR 4 — the probe

A browser probe is the only proof a visual ruling shipped; jsdom lays nothing out, so every ruling
below is invisible to the unit suite.

`pnpm probe:card-mark`, at 1300×900 and 390×844:

- **The mark is drawn at its stated size on each surface**, read off the laid-out box rather than
  a class list, and **never below 12px**.
- **No collision in the row's densest state at 390** — the mark's rect against the ownership dot,
  the availability marker, the buy tag, the mana pips and the printing caption. Overlap is the
  failure, measured as intersecting rects rather than inferred from markup.
- **No row or caption grew** — the row's height against an unmarked row of the same surface.
- **The key is on screen wherever a mark is.** Per surface: if any mark is drawn, the key's three
  fact entries are present. **This is the check that enforces rule 1**, and it fails the run
  rather than reporting a note.
- **The glow is a `filter`, not a `box-shadow`**, read from resolved style.
- A run that finds no marked card **fails rather than passing quietly** — it has measured nothing.
  The fixture account's collection is the source, and the probe says which card it found.

## PR 5 — the About entry and close-out

- **The About entry and the `ABOUT_VERSION` bump.** This is the round that ships a surface a reader
  can discover — *which of my cards are Game Changers?* is answerable for the first time — so the
  entry lands here. A new entry is always a bump.
- `feature-acceptance`: the route × viewport contact sheet across all four surfaces, and
  `pnpm check:shared` if the inventory carries a `shares` block.
- The close-out walk against the brief's §2 and §5.
