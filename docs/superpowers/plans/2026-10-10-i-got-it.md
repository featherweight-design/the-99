# I got it (collection home epic, sub-project 4)

2026-10-10 · lane: planning · status: **awaiting Hugh's approval**

A player who bought a card off a deck's Shopping list presses that row's buy tag, says which
printing came, its finish and how many, and the copies go into the Collection through the ledger.
The deck reads the new copy like any other, so the row usually leaves the list on its own.

## How the preset is chosen (Hugh's ruling, made concrete)

The confirm's printing is required: Add stays `Choose a printing` until one is selected, and no
tile shows a price (no price, no `listed $X`, no badge). The preselection is:

1. **The printing behind the row's figure, when that figure is live.** On a spoken-for row with a
   deck pick in stock, that is the pick. With the pick out of stock, it is the cheapest in-stock
   printing (ruling c). On every other row it is today's cheapest in-stock printing.
2. **Otherwise nothing is preselected.** A `sold out` row has a chosen printing behind it, but a
   stale one (audit gap 1 note); Hugh's ruling says in stock, so a stale printing is not preset.
   This is the handoff's Open 1 state (B7), unchanged, except for a card with exactly one
   printing, which is selected (PR 2).

The finish preset follows the price state: `priced` gives nonfoil; `foilOnly` gives foil, else
etched (audit closed rulings). With nothing preselected there is no finish until a printing is
chosen, then finding 1's rule applies.

**Measured on staging** (Hugh's account, read-only, 2026-10-10): all 219 of the unowned slots
across his 21 decks have an in-stock printing, so step 1 covers every row today and step 2 is a
test case. The median unowned card has 5 printings and the widest 57, so the choose role's
overflow search (over 12) is a real path, not an edge.

## Switch

`SHOPPING_MARK_BOUGHT_ENABLED`, through `shoppingMarkBoughtEnabled()` in
`src/lib/decks/mark-bought-flag.ts`, the same shape as the other release switches, and listed in
`.env.example`. The feature is on only when it **and** `COLLECTION_EDIT_ENABLED` are on. With
either off, the tag is a plain span, there is no key item and no details link, the phone stack is
main's (finding 5, errata 4), and the action refuses. History entries already written still show
their `From Shopping` tag (E2).

`DECK_PRINTINGS_ENABLED` is independent: off, no row has a deck pick, and the preset is the
cheapest in-stock printing. Only a deck pick moves a figure (Deck printings call 1), so a
Collection art preference never changes the preset.

### PR 1 · The write and the undo option (no UI)

- `shoppingMarkBoughtEnabled()`, the two-switch predicate, `.env.example`, tests.
- `markBought(deckId, oracleId, { scryfallId, finish, quantity, expected, id })` in
  `src/app/decks/mark-bought-actions.ts`: both switches on; `requireDeck`; the card is on that deck
  (body or commander); quantity 1 to 20. The server resolves set and collector number from
  `scryfallId` and checks the finish through the same `resolvePrintings` path `editCollection`
  uses (gap 2). One `edit` row whose quantity is `expected + quantity` (absolute, never a delta),
  with `scryfallId` for a row that does not exist yet, `source: shopping:<deckId>`, and the
  per-press id. `expected` is the count of that exact (printing, finish) holding as the confirm
  read it (gap 6). The action calls `invalidateCollectionReaders` BEFORE it returns, as the
  revert action does (`history-actions.ts:131`), because `editCollection`'s `after()` settle runs
  after the response and does not re-render the route by itself; only the commander-score warm
  stays in `after()`. The deck page's list is therefore current when the action resolves.
- The receipt's facts (gap 5) are read INSIDE the write's transaction, under its per-user lock,
  so a second write landing between the commit and a later read cannot be counted as this
  purchase. `applyCollectionChange` gains an option naming one oracle id whose availability it
  returns as it stood before and after the raise. From those two snapshots:
  - **which decks took the copy:** the UNEXCLUDED `allocateClaims` before against after, so
    seniority is applied with the source deck in it; the source deck is then dropped only from the
    names the receipt prints. A source deck senior to the others is allocated the copy and the
    receipt names nobody else;
  - **this deck's remaining need:** the after snapshot through
    `availabilityState(…, { selfExcluded: true })`, the vantage Shopping draws, which covers a
    draft deck as well as a committed one.
- Revert gains an `ignoreDeckId` option. Only the toast's undo passes it, and the server accepts it
  only when it equals the deck named by the entry's own `shopping:<id>` source (gap 3, call B).
- Undo outcomes: `alreadyReverted` reads as undone; `notFound` reads as failed (finding 2).
- The confirm's printings come from `loadPrintingChoices`, with no new read.
- Tests for every refusal, stale, a forged finish, a new holding versus a raised one, the claimed
  and partial receipts on a committed and a draft deck, a source deck senior to another claimant,
  a write landing between two receipts, and the undo exclusion accepted from the
  toast and refused for a mismatched deck.
