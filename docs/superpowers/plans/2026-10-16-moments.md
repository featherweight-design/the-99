A moment is a one-time bubble beside a control a reader has not used, pointing at the tool it opens. Fifteen of them
(M1–M15), at most one per visit, spent once shown, and each following its tool's switch. This plan builds layer 1 of
the brief only: no showcase, reference, tour or new entry point.

## Architecture

- **The switch.** `MOMENTS_ENABLED`, a `feature` switch with no parent. Each moment also follows its own tool's switch
  (STATES-moments, Per moment), resolved from the same `requestSwitchEnv` env the screen already holds. Off: no
  anchor registers, nothing is read, nothing is written.
- **The spent set (E1).** `user_prefs.moments_spent text[]`, append-only, like `upcoming_seen_codes`. The write
  (`spendMoment`, `src/lib/moments/spent.ts`) unions the id into the array and runs ONLY when it adds one
  (`setWhere ... not <@`), because `user_prefs` carries the `user_data_touch` trigger and any UPDATE moves the reader's
  stamp. `user_prefs` is already purged with the account, so the purge needs nothing new.
- **The read.** The shell, which already resolves the reader's env, reads the spent set when `MOMENTS_ENABLED` is on
  for that reader and hands it to a client `MomentsProvider`. The shell is not cached, so the set never rides in a
  cached page payload.
- **The spend action.** `spendMomentAction(id)`, a server action that re-checks `MOMENTS_ENABLED` for the signed-in
  reader and accepts only an id the registry names. It revalidates nothing: no page figure moves.
- **A visit (E2, G4).** Client side, in `localStorage` (not `sessionStorage`, so two tabs make one visit): the visit's
  start, its last activity and whether its moment is taken. Thirty minutes with no activity ends it. A storage read
  that throws reads as a fresh visit with no moment taken, and a write that throws is ignored.
- **The registry (E3).** `src/lib/moments/registry.ts`: the 15 ids in the fixed order (README, Q2), each with its tool
  switch. `pickMoment` is pure: given the anchors on screen, the spent set and the visit, it returns the one to show or
  none. Unit tested on every rule above.
- **Anchors.** `useMomentAnchor(id, eligible)` returns a ref for the control and its describedby id. The provider
  watches each eligible anchor with one `IntersectionObserver`, opens the tie window on the first one on screen, and at
  its close asks `pickMoment`. A loser is not spent; it waits for a later visit.
- **Over the page (E6).** A moment waits while anything is open over the page. That is read from `dialog.ts`'s
  scroll-lock counter, exported as a subscribable `scrollLockCount`, plus a `useMomentHold(active)` for a surface that
  does not lock scroll (a menu, a toast). An anchor inside the topmost open `aria-modal` surface is the exception
  (M8, M9).
- **Spent (G5).** A bubble is spent once it has been visible for one second, however it closed. One torn down sooner
  (an instant navigation) is not spent and does not take the visit.
- **`MomentBubble`.** The handoff's Q1 form: `--elevated`, 1px `--border-strong`, radius 10, the 6px `--accent` diamond,
  the tool name semibold in `--fg` and the line in `--fg-body`, a bare ✕ named `Dismiss`, a 10px nib on the control's
  centre, 8px below (flips above when below would leave the viewport or cross the tab bar), clamped 16px from the
  edges, and the halo on the control as a box shadow. A fade and 4px rise over 200ms in, 140ms out, fade only under
  reduced motion. It closes on ✕, a press of the control, Esc, a press elsewhere, the control leaving view and the page
  leaving.
- **Screen readers.** A labelled, non-modal note (`role="note"`, `${tool}, a tip`), the control's `aria-describedby`
  pointing at it while it shows, spoken once through ONE shared polite live region in the shell (`MomentsAnnouncer`).
  Focus never moves.
