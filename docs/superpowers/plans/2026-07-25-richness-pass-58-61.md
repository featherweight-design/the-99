# Visual Richness Pass (#58–#61) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Apply the landed visual richness pass — crab/kaiju character layer, density dials, motion posture, candle-glow vignettes, and a contrast lift — across the four shipped v1 surfaces, and create the two designed-but-unreachable states (global loading, 404).

**Architecture:** Four sequential PRs, one per ticket. **#58 is foundational and must land first**: it creates the character components (`<Crab>`, `<Kaiju>`), the CSS motion layer with the app's first `prefers-reduced-motion` handling, the two new route files, and the contrast-token migration. #59 and #60 are then parallelizable re-skins that consume those primitives; #61 lands last because the kaiju celebration is the highest-risk piece and benefits from every earlier decision being settled. Motion is pure CSS (utility classes in `globals.css`), not a React hook — that keeps reduced-motion declarative and avoids introducing jsdom to a node-only test setup. The only genuinely new logic is the celebration trigger, which is a pure function in `src/lib/decks/celebration.ts` and is unit-tested.

**Tech Stack:** Next.js 16 App Router (`loading.tsx` / `not-found.tsx` special files), React 19 client components, Tailwind 4 arbitrary-value utilities, brand tokens as CSS custom properties in `src/app/globals.css`, Vitest (node environment) for pure logic.

### Task 1: Motion layer + new tokens

**Files:**
- Modify: `src/app/globals.css`

**Interfaces:**
- Produces: CSS classes `.anim-bob`, `.anim-dots`, `.anim-breathe`, `.anim-rise` and tokens `--kaiju-body`, `--celebrate-top`, `--celebrate-bottom`. Every later task consumes these.

**[Yellow 4] Reduced-motion decision:** CSS media query, not a React hook. The mocks use a blanket `* { animation: none !important }`; we scope it to the four `.anim-*` classes instead. A blanket rule would silently suppress any future animation nobody has designed a static fallback for, and `!important` on `*` is unreviewable. Scoping means adding a new animation forces an explicit reduced-motion decision. A hook was rejected: it needs jsdom to test and would make every character component a client component for no gain.

**Static fallbacks are correct by construction:** with `animation: none`, no keyframe applies and base styles win — `.anim-rise` renders at `opacity: 1, transform: none` (not its `0%` frame, despite `both` fill mode), and `.anim-dots` renders three fully-lit brass dots. Task 8 verifies this in a browser rather than trusting the reasoning.

### Task 2: The Crab component

**Files:**
- Create: `src/components/character/crab.tsx`

**Interfaces:**
- Consumes: `.anim-bob` from Task 1.
- Produces: `export function Crab(props: { size?: number; bobSeconds?: number; className?: string })`. Renders an `aria-hidden` SVG. Default `size = 96`, `bobSeconds = 5`. Passing `bobSeconds={0}` disables the bob entirely.

**[Yellow 6] Component API decision:** numeric `size`, not a variant union. This deliberately differs from `src/components/marks.tsx`, which uses variants because `Crowned99` *composes* px-sized diamonds and text — a uniform scale there would produce fractional pixel values and fail design review. The crab is a fixed path set in one `viewBox`, so scaling is a single uniform transform with no composition. The mocks use five sizes (84, 88, 96, 104, 120); a five-member variant union carrying one number each would be ceremony. Record this reasoning in the file header so the next reader doesn't "fix" the inconsistency.

- [ ] **Step 1: Create the component**
