## PR boundaries (no stacking; each under 20 files and 800 lines)

**PR A: reads and writes (no UI).** All in `src/lib/social/` except the deck-commander read (E2).
- Migration: nullable `social_profiles.commander_oracle_id` (references `cards.oracle_id`, `on delete set null`), and
  `setCommander(viewer, oracleId | null)`, which refuses an id that is not a commander the catalog lists (E1).
- The commander (oracle id, name, art crop) on `ensureProfile`, `listFriends`, `listPods` (you and friends ONLY: a
  member who is not your friend stays name-only, D2) and `readInvite` (open, your own and already-friends states only,
  D1).
- `readInvite`: `friendsSince`; the state checked before `alreadyFriends`; the inviter's name stripped server-side in
  every ended state (E6).
- `listOpenInvites(viewer)`: token, created, expires, open only (E3).
- `listPods`: members ordered owner, You, then by name; `isFriend` per member; `nextOwner { publicId, displayName }`
  per pod you own, computed server-side, because the tie-break reads Clerk ids (E4).
- `listSharedPods(viewer)` over `sharedPodsQuery` (E5).
- `addMembers(viewer, podId, publicIds[])`: one transaction, all or none, under the lock order `addMember` uses (E11).
- The picker's two reads: your decks' commanders (newest deck first, up to 8, a partner pair as two tiles), and a
  commander name search with art over the set `/commanders` lists (E2).
- `check:social-reads` stays green; the purge coverage test learns the new column (it is the account's own row, so it
  goes with the profile). `pnpm probe:social` grows a case per new read and write, on a scratch branch.

**PR B: actions, routes, plumbing (no screens).**
- Switch-checked server actions over every write: `setDisplayName`, `setCommander`, `createInvite`, `revokeInvite`,
  `redeemInvite`, `declineInvite`, `unfriend`, `createPod`, `renamePod`, `deletePod`, `addMembers`, `removeMember`,
  `leavePod`, `shareSparesWith` (E18). Each maps its library result to a typed outcome the screen draws, never "false
  means done" (E12).
- `/friends` and `/friend/[token]` routes: `notFound()` with the switch off (E18); `/friend/[token]` public in
  `src/proxy.ts`, its signed-out card drawn whatever the reader's switches (E8, E19).
- An already-friends link is spent once, from an action after mount, never in a render that can repeat (E6, G4).
- The link origin from the request (E7). The QR encoder: one pinned dependency, client-only, rendered to SVG (E13).
- Name and pod-name caps counted in code points, not `maxLength` (E14).
- The account menu row, About, Friends, Admin, with its refs sized from the links (E9).

**PR C: `/friends` head and friends.** The face component (64 / 40 / 26px, initials while unset), the head with the
name edit and the commander picker (dialog at desktop, tall sheet at phone; one press picks and saves; `Use initials
instead`), the friends list with remove, its empty state, the open links list with the hold at 10, and the Add a friend
dialog/sheet with QR, link, copy and share. The receipt after Accept carries the friend's public id (E10). Loading via
`LoadingScreen`, failures through the error boundary and the shared toast (E15, E16).

**PR D: the friend request card (`/friend/[token]`).** Every state: signed out, open, expired, used, revoked, not found,
your own, already friends, declined, failure. The flip (face down, 200ms, 520ms turn at perspective 1400px; Decline
turns it back; reduced motion is a 120ms cross-fade); the card is one labelled image to assistive tech.

**PR E: pods (option B, the table).** Seats as art tiles over a 30% blur, you outlined in the accent, the owner's 28px ✕
disc, `+ Add friends` as an empty seat (five a row desktop, three phone); create, rename, the owner's menu, leave (naming
`nextOwner`), last leave, delete, add (batch), remove (a not-a-friend member removed for good: drawn as is, noted, D3),
the spares checkbox per pod. Build B's missing menu, rename, leave and delete states on B's header with R1's panes
(E17).
