# Collection quick filters: plan

Handoff: `design/design_handoff_the99_collection_quick_filters/` (README, STATES, READINESS Yellow, `copy strings.ts`). Approved by Hugh 2026-11-24 (R2, option C). Brief: Hugh 2026-11-25 "pick up the quick chip work". No new feature switch (rides the Collection line's existing switches or none), no migration, no spend, no model call, no About entry. The Filters panel and the mark key are unchanged.

## What ships

A strip of one-press chips on Collection > Cards: In no deck, Two-card combos, Game changers, Tutors, Extra turns, Mass land denial, Foil. Desktop and tablet: the chassis chip row (`data-chassis-row="chips"`) prints `Quick:` and the chips in place of `No filters on`. Phone: one new row under Filters / Sort. Pressing Two-card combos swaps the list for a pairs view (You own both / You own one). The combo feed item links to `/collection?combos=both` with its pair tagged NEW.

## Eng settlements (the READINESS Yellow items)

1. **Counts.** One pass over the rows the other filters leave, computed with the same predicates `filterCards` applies (a pure `quickCounts(list, filters)` in `src/lib/collection/quick-filters.ts`). No new query. Counts and predicates read ONLY kept columns (finding below), so they are right before the fields route has filled anything. A chip with count 0 is not drawn; all zero prints today's `No filters on`. Counts follow the list after every filter EXCEPT the quick chip itself, so the pressed chip keeps its own count.
2. **State and URL.** One quick chip at a time, held as `BrowseFilters.quick?: QuickKey` (optional, like `availability`, so the fourteen `BrowseFilters` builders stay valid). In no deck is NOT a second state: it is `availability = ["free"]` (the call-out's `avail=free`), so pressing the chip and choosing Free in the Availability menu are the same state and both show the chip pressed. The other six write one param, `quick=<key>` (`gc`, `tutor`, `turns`, `mld`, `foil`, `combos`), added to `OWNED_PARAMS` in `browser.tsx` and parsed in `parseBrowseParams` (`window.ts`); an unknown value falls back to none. The combos toggle is `combos=both|one` and implies `quick=combos`; `?combos=both` alone opens the view. The address bar is written through `mirrorUrl` (existing path), never `replaceState`.
3. **What each chip filters (review fix: `facts` is a draw key, `foil` is sole-finish).** `facts` is in `COLLECTION_DRAW_KEYS` (`list-wire.ts`), withheld outside the first 200 rows, and `foil` is set only when every copy of the drawn printing shares one finish with its own art, so neither can drive a filter or a count. Add ONE kept column, `q`, a small int bitmask per card (bit per gameChanger, tutor, extraTurns, massLandDenial, anyFoil), set in `toListCards` from `facts` and from `printings[].finishes` (any foil or etched copy in any printing) BEFORE the printings are dropped, deleted when 0. `facts` stays a draw key. Server (`firstWindowIds`, `parseBrowseParams`) and client share the predicate, so a shared `?quick=tutor` link cuts the first window correctly. Re-measure the wire with `probe:payload` (holds at 1.05MB; one short key plus an int on the cards that have it). Adding any filter in the Filters panel while combos is pressed returns to the card list (README C5); a pressed non-combo chip ANDs with the other filters.
4. **Pressed chip never also an active chip, and Clear stays live (review fix).** `collectionChips` skips `availability=["free"]` while the strip shows it pressed. The chassis (shared by decks, games, precons, the commanders rack and sets) gains two optional props, `quick` (the strip node) and `quickActive`; `none` text and Clear's `disabled` read `chips.length + (quickActive ? 1 : 0)`. Default absent, so other pages render byte-identical; a chassis test pins both. Clear all clears `quick`, `combos` and `new`. `quick=` with `avail=free` is one chip on: `parseBrowseParams` keeps `avail` and drops `quick` (README C3: one at a time), and the strip derives In no deck from `avail`. Phone strip is its own optional slot row (`flex-nowrap overflow-x-auto`), the desktop strip sits before the hairline in the wrapping chips row. `CHIP_CLEAR_INTENT`, the live-region announcement and `serializeParams` get quick intents; `OWNED_PARAMS` gains `quick`, `combos` and `new` (a stale `new` must not survive a filter change).
5. **Combos payload (PR 2).** Pairs, not per-card partners: the view's unit is a pair, and `bestPartnerPerCard` keeps ONE partner per card so it undercounts. New `src/lib/combos/collection-combos.ts`: `loadCollectionCombos({ userId, store, side })`, built on `ownBothQuery(userId, null)` (own both: already unassembled, no deck holds both, the same set as the combo mark and the feed item) and a sibling own-one query mirroring `pairsWithOnePiece`'s rules (one piece owned, one not, template-free, `isInfiniteOrGameEnding`). Rows dedupe by `variant_id`, then by unordered card pair (A+B equals B+A; the most popular variant names the pair). Loaded ONLY when the view opens: a GET route `src/app/api/collection-combos/route.ts` (session-gated, own rows only, `side=both|one`), cached in the component by `side` through `useDiscoveryCache` (never `staleTimes`), keyed on the list stamp the page already holds so an upload or deck edit retires it. Own-one is collection-wide, so it needs its own prune (like `ownBothQuery`'s `owned` CTE), `.toSQL()` pins, a staging timing measure, `missing_must_be_commander` handled, and the Wanted-by subquery aliased and qualified (code-rules). Price reads through `Store` (`check:store-reads`); verify the draft status vocabulary in `decks` first. Run `check:collection-routes`, `check:db-pool` and `check:flag-reads` and state the results. Payload per pair: both oracle ids and names, image uris, the result word, `variantId`, and per side: own both: `holding` (first committed deck from `holdingDecks`, or null: "In no deck together"); own one: `missing` card, `priceCents` from the reader's store (`Store` preference, silence when the store prices none), `wantedBy` (the draft that already asks for it, from `deck_cards` on a draft, else null). The result word is the combo copy's existing `produces` mapping (`comboAwarenessCopy`), not a new vocabulary.
6. **The chip's count (data PR; review fix).** `loadOwnBothPartners` folds rows through `bestPartnerPerCard`, which drops `variant_id`, so the count is NOT free. Add a pure `distinctPairs(rows)` in `near-miss.ts` (applies `isInfiniteOrGameEnding`, dedupes unordered on card ids, keeps the most popular variant) used by BOTH the count and the view, so the chip and the view cannot disagree. The loader returns the rows beside its Map (the injected `read` type in `attachComboPartners` and its tests change with it). `comboPairCount` is not per-card, so it rides the page payload and the cached list entry (`{ cards, pricesFailed, comboPairCount }`); the fields route cannot carry it. It rides the existing deck-write invalidation (both read decks); confirm in `invalidate.ts`. Own-one is counted when its side loads.
7. **NEW (PR 4).** `combo-writer.ts` already stores `variantId` on each combo feed item. The Home feed item (`item.combo.variantId`, nullable: null falls back to `?combos=both`) gains a link to `/collection?combos=both&new=<variantId>`. The row's stretched press already opens the combo sheet (`comboSheetOpenOpts`), so the link is a sibling control placed per the handoff, never an anchor nested in the press. The view tags the pair whose `variantId` matches `new`; with no `new`, no tag. No feed write changes, no migration.
8. **Telemetry.** `find_a_deck_opened` with `from: "quick_chip"` when In no deck is pressed ON (the brief names this event; `FIND_A_DECK_FROM` in `tool-events.ts` gains the value, one tuple covers the schema; check no test snapshots the list). Other chips: none.
9. **Undrawn states** follow the list: every count 0 is `No filters on`; an empty combos side is one `--fg-muted` line (`emptyBoth`, `emptyOne`); combos loading is the list's existing skeleton; a failed combos load is the list's existing quiet-failure line.
10. **Accessibility.** Chips are `<button aria-pressed>` with a 44px hit area (the `after:` pseudo pattern the chassis Clear uses) and `chipAria` copy. On phone, `onFocus` scrolls the chip into view (`scrollIntoView({ inline: "nearest" })`); the strip scrolls sideways, no wrap.
11. **Copy.** `quickFilterCopy` from the handoff goes in `src/lib/copy/quick-filters.ts` after copy-review; tests import the leaves (`check:test-copy-literals`).
