# Rule 0 table check (build plan)

Brief: `docs/superpowers/design-briefs/2026-10-16-rule-zero-table-check.md` (#1934). Handoff:
`design/design_handoff_the99_rule_zero/` (#1939, R2 approved by Hugh). Readiness:
`docs/superpowers/readiness/rule-zero-r1.md` (🟡 Yellow, fourteen gaps, every one resolved by engineering; its resolutions
bind this plan and are not restated in full here). Behind `RULE_ZERO_ENABLED`, which needs `SOCIAL_FRIENDS_ENABLED`.

**What it builds.** A pod member seats tonight's players from one pod, gives each seat a deck, and every seated player opens
the same page: the read (each seat's shipped bracket chip and its five finding counts, the table's middle, any deck a
bracket or more away from it flagged with what puts it there), a suggestion of closer decks for a flagged seat's own player
with one tap to swap, and `Log this game`, which opens the player's seated deck with the other seats filled in. A table
lasts 24 hours. No model call anywhere.

## Rulings this plan builds on

Hugh's (brief, Locked 1 to 13, and the orchestrator's relay of 2026-10-16): the read is brackets plus their drivers; seats
are pod members only, with no guest seat; one player sets the table and every seat sees it; the table fills the game log;
it expires after 24 hours; it suggests the player's own closer decks; seated players see each other's chosen deck, and
nothing else of theirs, for the table's 24 hours.

**G7, ruled by Hugh (2026-10-16): one open table per pod for now, with room for several later.** Pods sometimes split six
players into two games of three, rarely. So nothing in the schema is keyed by pod: `rule_zero_tables` is keyed by its own
id, seats are keyed by the table id, and "one open per pod" is a single check in the setup write (`setTable`, under the pod
row's `FOR UPDATE`, PR 2). It cannot be a partial unique index, because "open" is `expires_at > now()` and an index
predicate cannot read the clock. Several tables later is a UI change (the pod row and Home's card listing tables) plus
dropping that one check; no migration.

**Decided here, beyond the readiness doc:**

1. **Home's table card is read per request, outside Home's cached payload, as a `PER_REQUEST_READS` entry**
   (revised 2026-10-17, orchestrator; this replaces the `tableGeneration` key and the `user_data_touch` trigger this
   decision first called for). Readiness gap 1 said "an uncached read beside the cached payload", and `check:list-cache`
   now allows exactly that: a module listed in `PER_REQUEST_READS` (`scripts/lib/list-cache-tables.mjs`, #1966) with its
   reason is not followed from the page's edge, and the guard holds the page to the shape that keeps it out of the cache.
   Each use sits directly in the page's `export default function`, in a statement after its plain awaited
   `cachePageForUser`. Friends on Home (#1974) reads its section this way.
   - The card's read lives in its own module, `src/lib/social/rule-zero-home.ts` (`loadHomeTables(viewer, now)`, the
     tables the viewer sits at with `expires_at > now()`, read at request time), listed with its reason. Home calls it
     after the cached load, and a failed read draws no card (`not a fallback:`, since nothing is stored).
   - No stamp trigger on `rule_zero_seats` and no key element: a re-seat by a non-friend, a rename and an expiry are seen
     on the next request because nothing caches them. The card is still in the first render, so nothing shifts.
   - `seen_at` lives in its own table (`rule_zero_seen`), which Home never reads.
   The card sits where readiness gap 1 puts it: after `Pick up where you left off` on the phone, in the right column on
   desktop. It is in the first render, so nothing shifts. A Home tab left open does not re-render the card; its link opens
   the table, which draws the expired state if the night has ended.
2. **A seat's deck is `on delete set null`.** A deck deleted while seated leaves the seat waiting (`picks their own deck`),
   the state T10 draws, rather than removing a player from the table.
3. **The grant also joins pod membership.** The seat read requires the viewer's seat at an unexpired table AND the viewer's
   current membership of that table's pod; seats whose player has left the pod are omitted. A player removed from the pod
   loses the table on their next poll (it reads as not found), and nobody keeps sight of a former member's deck.
4. **Expired rows are not swept by a job.** Every read filters `expires_at > now()`. A pod's expired tables are deleted by the
   next setup on that pod, inside its transaction, and every table goes with the account purge. A job would be scaffolding
   for a table that holds a handful of rows per pod.
5. **No deck id of another player reaches a client.** A seat is addressed by its own seat id. The only deck ids in the
   payload are the viewer's own (Change deck, the suggestion). The game log's prefill is built on the server (PR 8).
6. **The pod row reads fresh.** `/friends` is not a cached page (it resolves `requestSwitchEnv` and renders per request,
   with no `cachePageForUser`), so the pod row's `openTablesFor` read needs no key; `check:list-cache` does not cover it.
7. **A table left with fewer than two seats.** The account purge deletes, in the same transaction, any table it leaves
   with fewer than two seats. A player who leaves the pod is omitted by the grant (decision 3); a table left with one
   member-seat draws what is left as `Nothing to compare yet.` (T10), and the setter can reseat it.

## Switch

`RULE_ZERO_ENABLED`: `kind: "feature"`, `needs: "SOCIAL_FRIENDS_ENABLED"` in `src/lib/switches/registry.ts`. The flag
function `ruleZeroEnabled(env)` (in `src/lib/social/flag.ts`, beside `socialGamesEnabled`) checks that parent alone.
Readiness gap 7 asked it to require `analysisTabEnabled(env)` too; PR 1 does not (accepted 2026-10-16): the registry
admits one `needs` parent and `flags.test.ts` holds each flag function to exactly its declared parents, so a second
parent is a multi-parent registry change of its own. Logging from the table also
needs `socialGamesEnabled(env)`; the invite row follows `socialInvitesEnabled(env)`. Off: no pod row, no Home card, no
route answers (404), `/friends/table/[id]` is not found. Every reader decides it from the env the request resolved:
Home's card from the page's own resolved env (it is read after the cached load, decision 1), `/friends` and
the table page from `requestSwitchEnv`, each route from its own re-check. Staging `'true'` from PR 6, the first PR in which
a reader can set a table (the pod row is the only way in); production unset until Hugh turns it on.

## Migration

One migration (next free number at the time PR 2 is cut; 0141 as of this plan; regenerate and re-stamp the ledger on a
collision):

- `rule_zero_tables`: `id uuid pk`, `pod_id → pods.id on delete cascade`, `set_by text not null` (the setter's user id),
  `created_at`, `expires_at not null` (created + 24 hours), index on `(pod_id, expires_at)`. No owner column, so no trigger.
- `rule_zero_seats`: `table_id → rule_zero_tables.id on delete cascade`, `user_id text not null`, `seat smallint` (seating
  order, 1 to 8, check), `deck_id → decks.id on delete set null`, `changed_at not null`, primary key `(table_id, user_id)`,
  unique `(table_id, seat)`, index on `user_id`. No `user_data_touch` trigger: Home reads it per request (decision 1).
- `rule_zero_seen`: `(table_id, user_id)` primary key, `table_id → rule_zero_tables.id on delete cascade`, `seen_at`. The
  seated player's own last draw of the table. No trigger: Home never reads it.

Purge (`purge.test.ts` coverage fails until all three are handled): the account's seats and seen rows are deleted, every
table it set is deleted (its seats cascade), and any table left with fewer than two seats is deleted (decision 7). These run in `purgeSocialIn`, before the pod hand-on, since a table belongs to the pod's night,
not to the pod's next owner.

### PR 1. The rules (pure, no database, no caller)

`src/lib/rule-zero/rules.ts` and its test, plus the switch (registry entry, `ruleZeroEnabled`, `flags.test.ts` holds
`needs` and the analysis requirement).

- `seatState(seat)` from one snapshot (readiness gap 9): `{ kind: "illegal", cards }` when `deckLegality` says not legal now,
  even with a stored reading (whole-deck count `built + (100 - size)`, so `87 of 100`, `101 cards, over 100`); `fresh`;
  `stale` (chip kept, `from before its last change`); `unread` (legal, NO `deck_profiles` row: read on the spot);
  `needsAnalysis` (legal, a row exists but `readStoredReading` returns null: an older-version row over a dirty or changed
  list, or a row a newer deployment wrote). `needsAnalysis` never spins and is never computed by another player: the seat
  says it needs its player to analyze it and is left out of the read (a new string, through `/copy-review` with the rest);
  `waiting` (no deck).
- `seatValue(permits, declared)`: a single bracket is itself; a range answered by a declaration inside it is the
  declaration (`declarationAsk` = `answered`); an undeclared or drifted range stays a RANGE `[lo, hi]`. A drifted declaration
  is never compared.
- `tableRead(seats)`, with no circularity between the middle and the ranges: the middle is the median of the read seats'
  values, where a range contributes its midpoint (`[1,2]` is 1.5), and an even count takes the mean of the middle two. A
  seat's distance is `|value - middle|`; a range's is 0 when the middle lies inside it, else the gap to its nearer end. A
  seat is flagged `high` or `low` at a distance of 1 or more. The rail draws a range's face at its end nearer the middle,
  the lower end on a tie, and its line names that end (`measured from Core`). Exactly two read seats a bracket or more
  apart (a range measured by its gap to the other seat, 0 where it covers it) are both `split` and the rail draws no band;
  two seats closer than that are balanced; fewer than two read seats is `notEnough`. Fixtures pinned in the test, each
  a brief or handoff state or a review case: `2,3,3,4` flags both ends, `2,2,4` flags the 4, `3,3,3` balanced, `[1,2]`
  beside `1,1` and beside `2,2` (unflagged both times, face at 1 and at 2), `[1,2],[1,2],1,3` (middle 1.5: only the 3 is
  flagged), `[4,5]` declared 4, a drifted `[4,5]` declared 1 (a range, never compared as 1), a two-seat `2,4` split, a two-seat `[1,2]` and `2` balanced, one
  read seat beside an illegal one (`notEnough`).
- `driversFor(seat, flag)` (readiness gap 10): `ruledOut` reasons speak `whyLimit` against the bracket below; `assembled`
  speaks `whyCombo` from `lean.decidedBy` and its tutor receipts, with the bracket name taken from the sub-line (not the
  hard-coded `Upgraded`); a `[4,5]` range takes its reasons from `slotDeck`'s bracket-3 violations; a low seat speaks
  `whyLow`, which always says counts can miss cards.
- `suggestionsFor(seat, ownDecks, middle)` (G6): own decks, legal now, with a reading, strictly nearer the middle; nearest
  first, then most recently played; at most three; none is an empty list (the block is absent).
- `startingDeck(decks)` (G8): most recently played, else most recently edited.

### PR 2. The data: tables, the seat grant, writes (dark, no caller but the probe)

The migration and schema; `src/lib/social/rule-zero.ts` (every cross-user read stays in `src/lib/social/`, so
`check:social-reads` holds); the purge; `pnpm probe:rule-zero` on a scratch branch.

- `loadTable(viewer, tableId)`: one statement joins the viewer's seat at the table, `expires_at > now()`, and the viewer's
  membership of its pod; null otherwise (the page's not found, or expired: `tableStatus` tells the two apart for the
  viewer's own seat only). Per seat it returns exactly readiness gap 2's fields (display name, `public_id` only when the two
  are friends, deck name, commander art, permits, declaration and `declarationAsk`, five finding counts, the sub-line,
  `lean` with the combo's names and tutor count, the bracket-3 reasons for a range, card count and legality, fresh or
  stale, `changed_at`) and nothing that links to a deck page or a profile. Readings are read under each seat's owner id
  after the grant is checked, in one repeatable-read snapshot.
- `readOnTheSpot(viewer, tableId, seatUserId)` (gap 8): for a seat at a table the viewer sits at, whose deck is legal now and
  has NO stored `deck_profiles` row at all, computes one with `computeAndStoreProfile` under the owner's id and
  `resolveSwitchEnv(owner)`, stored as theirs. It is model-free: `computeAndStoreProfile` is the deterministic profile
  build (`slotDeck`, `findings`; `src/lib/profile/stored.ts` imports no model module), the same work the Analysis tab's
  free press does. It cannot be driven to repeat: a stale row is never recomputed (it draws `from before its last change`),
  so the write happens at most once per deck until its owner analyzes it, and it runs under a transaction-scoped
  `pg_try_advisory_xact_lock` on the deck id, so a second seated viewer polling at the same moment skips rather than
  computes again. A deck with an unreadable row is `needsAnalysis`, never `unread`, so no seat waits on a computation that
  will not run. Called from the poll route (PR 4), never in the page's first render.
- `setTable(viewer, podId, seats)`: under the pod row's `FOR UPDATE`, deletes the pod's expired tables; when an open table
  exists (one per pod, G7: the only place the rule lives) it returns `{ kind: "open", tableId }` if the viewer is seated at
  it, else `{ kind: "occupied", setBy, closesAt }` with nothing written, which setup draws as one line and does not
  navigate (a new string, through `/copy-review`). Otherwise it writes the table and 2 to 8 seats. Refuses a seat who is not a pod member, a
  viewer not in the pod, and a deck the viewer picks for a seat that is not the viewer's own or (through `friendDecksIn`)
  their friend's. A non-friend's seat is written with no deck (G3).
- `reseatTable(setter, tableId, seats)`: the setter's `Seats`, same checks, keeps unchanged seats' decks and `changed_at`.
- `setSeatDeck(viewer, tableId, deckId | null)`: the viewer's own seat only, the viewer's own deck only; moves `changed_at`.
  `Undo` is this call with the previous deck.
- `markSeen(viewer, tableId, seenThrough)`: upserts the viewer's own `rule_zero_seen` row with
  `seen_at = greatest(seen_at, seenThrough)`, where `seenThrough` is the snapshot's `revision` (the latest `changed_at`
  among the seats it carried), never the time of the acknowledgement. A swap landing after the drawn snapshot keeps its
  dot on the next poll. `loadTable` returns `revision` with the seats.
- `openTablesFor(viewer)`: the viewer's seats at unexpired tables of pods they are still in (Home's card, the pod row).
- `loadHomeTables(viewer, now)` (`src/lib/social/rule-zero-home.ts`, listed in `PER_REQUEST_READS`): what Home's card
  draws for each table the viewer sits at with `expires_at > now()`, read per request. Its test renders the query with
  `.toSQL()` and asserts the qualified `"rule_zero_tables"."expires_at" > now()`, and the probe makes a table expiring in
  two seconds and reads it before and after with no write between: it must leave the list, so Home never draws an expired
  table as open (orchestrator, 2026-10-16). PR 6 is its first caller.
- `podSetupMembers(viewer, podId)`: members with `hasDecks` for the viewer's friends only (`friendDeckCountsQuery`, G2); a
  non-friend member reads as `picksOwn`.

The probe proves, with fixtures it owns: the grant (a seated non-friend sees the chosen deck and nothing else; an unseated
member, an expired table and a member who left the pod read null), one open table per pod under two concurrent setups with
different seat lists (the seated caller gets `open`, an unseated one `occupied`), `markSeen` keeping a swap that landed
after its snapshot unseen, the
writes' refusals, `on delete set null`, `readOnTheSpot` writing once and skipping on a second call, on a stale row and on an unreadable older-version row, and
the purge removing all three tables' rows and closing a table it leaves with one seat.

### PR 8. Logging from the table, and the close-out

`/decks/<seated deck>?tab=games&table=<id>`: the deck page, with games and Rule 0 on and the viewer seated with that deck at
that unexpired table, builds the prefill on the server through the seat grant and opens `GameLogForm` expanded on it
(`initialOpen` plus a new `prefill` prop: pod size = seated count, `From <pod>'s table. Seats filled; change anything.`,
and the seats). A prefilled seat is a new client-safe kind, `{ kind: "tableSeat", seat: <seat id>, won }`, carrying the
seat's display name, deck name and commander art for drawing and NO deck id or public id: the existing `friendDeck` seat
(`src/lib/decks/game-seats.ts`) sends the friend's deck id to the client and back, which decision 5 forbids. `logGame`
resolves `tableSeat` entries on the server, in the game's own transaction and under the seat grant (the viewer seated at
that unexpired table, the seat at the same table): a seat whose player is the viewer's friend becomes a `friendDeck` row
through `resolveFriendSeatsIn` as today; any other seat becomes an `other` row with the table's commander and partner and
`label` the display name as seated, cut to 30 (gap 4), drawn `from the table`. A grant that has lapsed by save is the
form's ordinary refusal, with the form kept. A prefilled seat the player edits becomes an ordinary picker seat and leaves
the table path. Tests assert the serialized prefill and the form's submitted seats hold no other player's deck id or
public id, before and after an edit. Result is left empty. Any mismatch (not seated, expired, another deck) opens the
Games tab with no prefill. L1 to L3, H1, H2. Then `feature-acceptance` at feature close: the route by viewport walk of every row in the
inventory on staging, with three accounts seated (a friend, a non-friend, the setter).

## Review focus

The inputs no single task's tests reach most naturally, each pinned in the PR that owns it:

1. **A table expiring while open** (PR 4): the next poll answers the expired body and the page draws L4 in place; a press
   on any control after expiry is refused with the shared toast, never a thrown error.
2. **Two members setting a table on one pod at once** (PR 2): the second gets the first's table only if seated at it, else
   `occupied` with nothing written; the probe races them with different seat lists.
3. **A seated deck deleted, or made illegal, mid-night** (PR 2, PR 4): the seat waits, or reads its card count, and the read
   recomputes without it.
4. **A non-friend's deck reaching a client by another path** (PR 2, PR 8): the payload and the prefill carry no deck id or
   public id of a non-friend; asserted on the serialized payload in the tests.
5. **A viewer removed from the pod while seated** (PR 2): the grant drops at the next poll; the probe removes one mid-test.

## Not in this build

A guest seat; the invite flow itself; any change to how a bracket is computed; a model call; a push channel; a table past
24 hours or a history of tables; several open tables per pod (ruled out for now; see G7).
