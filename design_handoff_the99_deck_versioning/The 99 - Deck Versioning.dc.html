Deck versioning · #389 · five surfaces

The draft arrives forty rows at a time.

A committed deck never edits its committed list directly — edits pile up as a draft until the next commit. The normal way that draft gets populated is a paste from Deckcheck, per Addendum R2, so pending state and Review changes are drawn at 36 changed rows first and checked downwards at two.

The deck is HD Tune — Mutant Menace, The Wise Mothman, Sultai: v2 committed in March, a draft of +19 / −17 on top of it, 101 cards on screen and no complaint about it. Nineteen adds split eleven free, five sleeved in other decks, three not owned — and one of the five is held by a deck with its own pending changes, which is the guard, drawn.

Read README.md for the decisions log, STATES-pending.md for the state matrix, OVERLAPS.md for the two calls the spec left open, COST-TRACK.md for the un-shingled pip proposal, copy strings for production copy.

R1.2 — redrawn against the shipped deck page

Corrected from the screenshot: text tabs with a brass underline (not pills) and the labels Your deck / Consider / Games · a cream primary button (#E8E4D6 fill, dark label) with brass reserved for links, counts, toggles and the tab underline · the commander art plate with its Card details overlay · the RECOMMENDED MIX strip with rec n and consider → · the All / Shopping · By type / By role toolbar and the two view-mode buttons · two-column rows grouped by type under Cinzel group headings · and the cost track on every row. Every surface in this handoff now inherits that chrome rather than inventing a parallel one.
R2 — the blocker, answered
The rows mount CostPips. The canvas was wrong, and it is corrected. R1.2 drew the mana value in the numeral disc — 3 for Beast Within's {2}{G}, 2 for Thought Erasure's {U}{B}. That is a different figure from the generic-cost token the component renders, and it was an error rather than a specified mode: I reasoned about what a reviewer wants to compare and drew that number in a slot that already means something else. Every track on this canvas is now CostPips' output — Beast Within reads 2 · G, and Thought Erasure has no disc at all, two pips. So no fifth atom, the inventory holds, and versioning is not connected to the amendment: COST-TRACK.md is card-rows' business start to finish.
The consequence worth naming: the numeral is conditional, so it is not a fixed leading element — which changes the track's geometry and every row's accessible name. And mana value now appears in exactly one place, the what-changed strip, where it is a deck-level statistic. A reader reconciling a row against the strip will not find the row's number, because the row does not carry one.
Rows are grouped by type, never labelled per row
The 120px type column is gone. Adds, removes and every version diff group under the same Cinzel headings the deck page uses, so one row anatomy serves the whole app: dot, name, cost track.
The pips stop shingling
A commander deck's identity is at most five colours — but a cost repeats symbols, and Progenitus is ten. R1.2 confused the two and dropped the cap on it. Corrected: a wider track and a cap. See COST-TRACK.md.
Review changes gains a what-changed strip
Mana value 3.10 → 2.92, the mix cells' movement, and the type distribution before and after. Removal crosses its recommendation in this draft, and the strip is where you see that.
Commit stops repeating the lists
The sheet keeps the note, one money block with the Mana Pool link-out, and one released line. The eight priced rows and seventeen names live on the review page, one screen up, and are not drawn twice.
Versions is a fourth tab
R1 hid history behind a mono line under the deck name. It is now Versions · 3 in the tab row beside Games — the page's own IA, and the same shape of thing as the game log.
The guard says pending, not a sentence
The deck name is already on the row, so the reason rides it as a four-letter tag and the action is Open → in Pull it's slot. Same width as a pullable row, no two-line link.
Locked upstream — drawn as written, not re-litigated
Always-draft, no mode to enter · a committed version beats seniority and the pull is offered, never automatic · commit emits the to-do list and does not assert the work is done · no versions until the first commit · games are stamped with the version live when they were played · seniority is per card (R1), carried on the claim · a paste lands in the draft and never commits (R2) · and the vocabulary is version, draft, commit a version — never “committed cards”.

R1.2 said five pips was the ceiling. That was wrong, and the no-cap ruling rested on it. Colour identity caps at five; a mana cost repeats colour symbols freely. Progenitus is a legal commander at ten, and cost-pips.test.tsx:101 already asserts against that exact string. The cap stays.
So the proposal is a wider track and a cap, not a track instead of one. Desktop 110px, cap 5; phone 76px, cap 3. Overflow is a mono +n in --fg-faint, never a pip — it is a count, not a colour. The cap is read from the shipped prop, not re-declared.
What survives untouched is the actual bug. Two same-coloured pips are indistinguishable when shingled — Mana Drain's {U}{U} reads as one blue pip, and one blue pip is {U}. That is two different costs drawn identically, and no cap rule affects it.
The numeral leaves the pip stack — a quantity, not an identity, and the first pip crops it today. It is also conditional: {U}{B} has no generic component and so renders no disc at all.
Scope, corrected. CostPips mounts in five places, not two: decklist-row, card-search-row, top-off-list, suggestion-tile, deck-card-tile. Two of those are tiles, not rows, and a tile's width budget is not the deck page's whitespace — card-rows should rule with that in front of them.
